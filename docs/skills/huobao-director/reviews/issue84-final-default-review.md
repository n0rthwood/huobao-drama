## 二、新小目标干跑：已授权的明代运河地图

**这是纸面规划，不执行请求，不生成实际 ID。**

设本次明确授权的小目标为：

> 在获准项目中，新建“明代京杭运河通州段概览图”；用户已选择 `program`、`archival`、非示意模式，并授权正常完整地图流程及人工指定的几何调整。仅画有证据支持的点线面，不追求测绘级历史复原。

以上路线和风格是干跑的**授权前提**，不是助手自行替用户选择。若真实授权仅说“明代运河地图”，应先澄清空间范围、用途及尚未决定的路线/风格，不能偷偷缩为通州段。

### 1. 接入、范围与台账

- 在操作授权内检查服务、活跃任务及目标项目，确认没有同目标任务正在运行。
- 项目没有集级地图需求，因此不为套用通用开工清单而新建剧集或索取集级剧本确认。
- 发现可用文本、图片配置时，仅保留安全白名单字段，密钥不进入日志。
- 显式钉选获准的 `text_config_id`：正常流程预留 **3 次文本调用、1 次底纹图片**；视频和 TTS 为零。钉选文本端点不自动回退。
- 不钉选时，按文档最多 **9 次文本尝试**保守规划，实际消费按调用行记账；重试另计。不得将已授权目标解释为无限重试。

### 2. 新建与保存需求

```json

  "drama_id": "<本次获准项目ID>",
  "name": "明代京杭运河通州段概览图",

```

这里尖括号是规划占位符，实际请求必须使用真实返回的数值 ID。

GET 新资产工作流后，以当前修订保存：

### 3. 逐步执行与审核

| 阶段 | 操作与检查 |
|---|---|
| **brief** | `run {mode:"manual", expected_revision, text_config_id:…}`。检查 `issues[].blocking`；有关键缺失则补 brief，不绕过充分性检查。 |
| **research** | 重新读修订，以 `advance` 执行当前阶段。核对逐源查询、实际摘录、坐标依据和冲突。正常研究为两次文本调用，不把工作流容器当一次调用。 |
| **候选处理** | 有依据的点线面可保留 `proposed:true` 继续制图。仅在人明确采纳具体要素后，读取完整 `map_spec`，去掉获准项的 `proposed` 并完整保存；不批量替人采纳。 |
| **base** | 生成程序底图，打开核对覆盖范围、配准与图层依赖。Natural Earth 底图不是明代河道正确性的证明。 |
| **style** | 只生成无地理内容的独立底纹，不把底图或史料送扩散。不得因底纹失败自动改成跳过；跳过须属于人的决定。 |
| **drawing** | 确定性绘制有依据的点、线、区域与文字。没有区域依据就如实报告缺口，不为了“覆盖区域能力”虚构范围。 |
| **complete** | manual 模式在推进 complete **之前**打开 final，记录实际路径与 SHA-256；再技术采用。无 `opened` 参数，也不代表史实或许可批准。 |

若用户已授权全自动，可显式使用 `run {mode:"auto", …}` 从当前阶段连续执行；完成后立即打开真实产物。不能仅因保存的 `mode` 为 auto，就省略 run 入参并期待自动连续执行。

### 4. 手工调整及恢复

- 用户指定拖点或改线后，以实际底图配准反算 WGS84。
- GET 完整 spec，只改获准项，带当前 `expected_revision` PUT；**map_spec 是完整替换**。
- 投影、bbox、背景层未变时，从返回的 `drawing` 阶段重绘并 complete，复用底图和底纹，不重跑研究。
- 409 保留草稿，重新读取并由人决定合并；不盲投。
- 如要求回退或取消，记录人的决定。取消用 `{}`，不附不存在的 `expected_revision`，也不声称已经发出的底纹任务停止或退费。
- 收尾只报告本新地图的产物、来源风险、实际调用和待审决定，不沿用历史资产、任务或验收 ID。

## 三、反例与参数准确性

| 核对点 | 评审结果 |
|---|---|
| 地图分类与上传目标类别 | **准确。**prop 的 `asset_type:"map"` 与 register-upload 的 `asset_type:"prop"` 含义不同，§3.84 已显式警示。 |
| 保存语义 | **准确。**brief 内合并；传入 map_spec 则完整替换；CAS 不能替代完整读取与授权项比较。 |
| run / advance / mode | **准确。**run 省略 mode 默认 manual，即使保存为 auto；advance 始终 manual，且仅 advance 支持 skip-style。 |
| complete 与审批 | **准确。**地图 complete 是技术采用，没有 `opened`；普通资产流水线 approve 的 `opened` 要求不能移植为地图参数。地图专节的具体规则已消除泛化误用。 |
| 配准标准 | **准确且有边界。**Earth 必须实测网格、独立最大残差 ≤3px、漂移 ≤0.25px，并满足 Clean；外部图至少三个非共线控制点，阈值为源图对角线 5%。两者都不能证明历史位置正确。 |
| Earth 失败处理 | **安全。**不能以程序图替代 Earth 后宣称通过，不能复用被拒绝的非 Clean 原件冒充新验收。 |
| 原件与底纹 | **准确。**真实底图不进扩散；派生 final 可叠独立底纹，不能叫未改动原件。要求原貌时须按人的选择跳过 style。 |
| 成本与观测 | **准确。**正常 3 文本＋1 底纹；钉选无回退；失败重试计新请求；采集失败先读回业务状态，避免重复提交。 |
| UI 恢复 | **准确。**mfocus 指向已保存要素，mview 指向产物；恢复界面不能触发保存、生成或采纳。 |
| 历史评审与证据 | **应作为历史读取。**旧评审中新增 opened/CAS、限制未实测 auto 等意见，不是现行契约。旧响应末尾的“预算待确认、新 API 全为 [S]”也不能覆盖本次明确授权与最新逐方法状态。 |
| #86/#87 与 #88 | **边界保留。**公开消息分页、实际计量不等于全部 harness 已覆盖；#88 不能因地图或设计卡路径可用而被视为关闭。 |
| 评审角色身份 | **不推断。**default/slow 是角色标识，不是已核实的供应商或具体模型名称。 |

没有发现需要靠新 API、假 preview、虚构参数或未记载供应商能力才能安全完成上述干跑的断点。
