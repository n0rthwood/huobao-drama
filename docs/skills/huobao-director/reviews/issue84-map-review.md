## 第一轮：default 角色

## 一、五项结论

1. **更好思路：保留现有工作流，补齐执行契约，不重做 Issue 方案。**  
   显式地图分类、统一入口、分阶段运行、配准真源、程序绘制几何、独立底纹、产物读回等方向正确。主要需要补清三件事：**哪些缺失阻断、点面如何自动生成并确认、编辑后如何重新出图**。无需增设无关系统或缩减三路线。

2. **过度设计：未发现足以要求删减的设计。**  
   `revision`、配准、来源记录、历史及预算控制都有必要。60 图层／240 顶点属于具体实现限制，不应仅因数字固定便认定为过度设计；但若它们使用户目标无法完成，应明确报告限制并等待决定，不能自行删减内容。当前“不丢点、不缩减”的规定值得保留。

3. **遗漏需求：存在，尚不能直接通过。**  
   - “允许非关键资料缺失”没有明确落到执行规则，反而被“资料空缺……不能当通过”（API 目录第290行）笼统覆盖。
   - 有点线面存储与程序叠加，但**从检索证据自动生成点位、区域的步骤和结果归属**没有说清，不能仅以 `regions` 字段证明自动面绘制流程完整。
   - 手工编辑后，缺少明确的重新绘制路径；“保存不等于渲染”提醒正确，却未告诉执行者下一步如何做。
   - 失败重试计入额度未明确重申；取消消耗额度和重启不自动计费不能完全替代这条规则。

4. **未授权决定：已有较好防护，但确认边界不完整。**  
   类型降级、回退、取消、冲突合并均明确交人决定；没有明显要求助手擅自执行这些操作。缺口是：文档使用“人工确认的几何”“已确认几何”，却未说明**如何记录确认、确认针对哪个修订、自动模式是否只生成候选几何**。不得把 `advance`、`completed` 或无人反对视为人工批准。

5. **调查不足：只能确认文档缺口，不能判定实现缺失。**  
   本次仅检查所给新增章节，未读取源码、其他目录或运行服务。新增端点保持 `[S]` 正确；三路线实际可用性、自动面生成、配准及几何确认持久化均不能据此宣称已验证。以下是文档执行干跑，不是生产实测。

## 二、一张地图小目标的执行干跑

**小目标：**制作“殷墟车马坑位置示意图”，包含有依据的点位；如来源支持可表达的区域，再自动绘制区域。此轮假设用户明确选择 `program` 路线、`manual` 模式和概览用途，不启用底纹。**这只是本轮选择，不取消 `image`、`earth` 或自动面绘制能力。**

| 步骤 | 按新增文档可执行的动作 | 干跑判断 |
|---|---|---|
| 1. 创建地图 | 用 `POST /props` 创建 `asset_type:"map"`，读取工作流及 `revision` | 类型和入口清晰；业务数据通过 API 写入 |
| 2. 保存需求 | 用工作流 PUT 保存对象、用途、粒度和所选路线；殷墟车马坑的隐含时代、位置由 AI 解释，区分推断与考证 | 不应机械地要求用户补时代；也不能擅自把概览变为精确坑位测绘 |
| 3. 充分性检查 | 启动 manual，读取 `stage/steps/status/issues`，逐步推进 | 阻断字段须补充；但目前缺少“非关键缺失只告警”的明确分界 |
| 4. 真实检索 | 按资产描述在 Wikipedia、Europeana、Smithsonian 检索，读取逐源命中、失败、摘录及点线面证据 | 某一来源无命中不应自动判整图失败；也不能把命中链接当坐标证据 |
| 5. 生成几何 | 将有依据的点位、区域变成可编辑的 WGS84 几何，保留出处、冲突及不确定性 | **文档断点：**何阶段将 `research.features` 转为 `map_spec`，以及候选／确认状态如何处理，尚不明确；不能靠审稿人补造 |
| 6. 底图与绘制 | 生成程序底图并打开检查；到 `style` 用已列明的 `skip:true` 跳过底纹，再进入确定性绘制 | 路径基本清晰；不能因跳过底纹而跳过检索或充分性检查 |
| 7. 手工编辑 | 用户拖动点位，按实际配准反算；GET 修订后带 `expected_revision` PUT | 保存规则清晰；**保存后如何只更新成图、避免重跑检索或再次计费，未写清**。不能自行回退以触发重绘 |
| 8. 验收 | 打开实际 `base_image/final_image`，检查图层、来源、配准、文字和区域；交人审核 | 技术完成与内容批准已明确区分；不得将本次干跑标为 `[R]` |

## 三、边界与反例检查

- **“京杭运河通州段”未给时代：**应提示补齐，不默认当代或任一朝代；“殷墟车马坑”则不能同样机械拦截。
- **三源中一源无命中，其他来源足以支持核心点位：**应记录检索结果、提示非关键缺失并继续；不能因“资料空缺”一概阻断。若关键位置或时代依据不足，则阻断相关输出。
- **只有点位证据，没有区域边界依据：**不能虚构区域补齐成果；应呈报缺失。反过来，有充分区域证据时，也不能将范围缩为“只支持点位”或“区域只能人工画”。
- **外部图只有两个控制点，或三个点共线：**不满足当前配准要求；不能声称配准成功，也不能擅自换程序底图。
- **Earth 配准失败：**不得用 bbox 仿射或程序图冒充 Earth。Earth 路线仍须保留，失败应如实呈报。
- **真实地图加纹理：**真实图不进入扩散；扩散仅接收独立底纹请求，随后程序合成几何。不能借“美化”重绘史料图。
- **底纹失败后重试：**重试仍占额度，提交前检查剩余预算和授权；原先一次预算不能自动解释为无限重试。
- **409、回退或完成：**409 后不盲投；回退须人明确要求；`completed`、阶段推进均不构成人工内容批准。

## 四、最小整改清单

**结论：暂不通过；未发现仅凭所给文本即可判定的 P0，需补齐以下 P1。**

1. **P1｜明确缺失分级。**  
   修改 API 目录第290行的笼统表述：关键需求／关键证据不足阻断；非关键缺失记录风险后允许继续。区分“检索步骤真实执行成功”与“所有来源都有结果”。

2. **P1｜补齐自动点面与确认契约。**  
   写明检索结果在哪个阶段转为可编辑点位、线路、区域，候选与人工确认如何记录，以及重跑如何保护确认几何。沿用实际支持的字段，不臆造接口。

3. **P1｜补齐手工编辑后的重绘路径。**  
   写明 PUT 保存后通过哪个现有动作更新产物、如何处理阶段及旧输出，避免无意重跑检索、覆盖几何或再次调用底纹；不得以擅自回退替代。

4. **P1｜明确失败重试预算。**  
   加一句硬规则：失败重试同样计额度，每次 GPU 提交前须有足额预算及对应授权。

这些修改只需落在本次新增地图章节及其 API 目录中，不要求重写无关系统，也不要求重新评审 Issue84 方案。

## 一、五项逐条判定

### 1. 是否需要改进 —— **是（中等程度，集中在契约边界与一致性）**
- §0 铁律 2 与 §1.3「硬禁止」清单未同步收录地图工作流新增的人决定写入点（去 `proposed` 的采纳保存、`rollback`、`cancel`、`confirm_asset_type_change`、schematic 采用）。§S2-84 正文把这些归给人，但 §0 自称"仅汇聚后文"，实际没有汇聚到，弱模型只读中央清单会漏判。
- `PUT map-workflow` 对 `map_spec` 是整体替换还是逐项合并未写明；与"人工确认的几何不能被重跑检索覆盖"的保证存在数据丢失风险缺口（agent 全量 PUT 时可能误删已确认项或他人新增项）。
- `run {mode:"manual"}` 与 `advance` 语义重叠（都执行当前一步），仅 `advance` 有 `skip`，何时用哪个未说明。
- `mode` 三处出现（GET 返回、PUT 可存、run 入参），优先级未定义。
- 最终采纳（complete）没有 `opened:[{path,sha256}]` 类防伪字段，弱于 asset-pipeline approve 的严格度；只靠流程口径"打开成图"。
- "普通道具接口返回 not_a_map"一句主语歧义（应为"对普通道具调用 map-workflow 返回 not_a_map"）。

### 2. 是否过度设计 —— **基本否**
- 六阶段、三底图路线、auto/manual、revision CAS、proposed 机制均能逐条对应到需求摘要（三路线都实现、自动点线面、自动/人工与回退、扩散只做纹理），不是无依据的复杂化。
- 轻微冗余两处：`run manual` 与 `advance` 功能重叠；`mode` 既可持久化又可每次传入。建议收敛为一处，属简化项不属砍功能。

### 3. 是否遗漏需求 —— **少量遗漏，核心需求已覆盖**
覆盖项：显式地图类型（`asset_type:"map"`）✓；充分性判断（blocking issues + 充分性检查不可 skip）✓；三路线（program/earth/image，KMZ+自动载入有表述）✓；AI 自动点线面（`proposed:true` + regions）✓；自动/人工与回退 ✓；扩散仅底纹不改几何 ✓；保留 ID 与引用（仍 `kind:"prop"`、同资产 ID）✓；缺时代必须补齐（京杭运河例）✓。
遗漏/未钉死项：
- **Wikipedia/Europeana/Smithsonian 三来源只出现在背景叙述**，契约字段（`research.queries[]`）未枚举固定来源集，也未写外部检索凭据的存放与脱敏口径（全局只约束了 ai-configs 的 `api_key`）。
- image 路线无数值验收阈值（earth 有 3px 检验点残差，image 只有"至少三非共线点"），验收不对称。
- `faithful:true` 与 `asset_type:"map"` 的交互未写：忠实原件地图能否挂底纹阶段、image 模式下 final_image 中底纹与原件的合成关系（是否遮改原件外观）未说明。

### 4. 是否擅定用户意图 —— **契约主体未擅定，但留有代订缺口**
- 正面：缺时代"不能擅自默认"、AI 推断与出处考证区分、auto 候选"不是人工批准"、近似区域须显式 `schematic:true`——这些都明确把裁量权还给人。
- 缺口：`base_mode`（三路线选哪条）、`style`（archival/clean/ink）、`skip` 底纹这三个影响成本与成品性质的选择，**决策归属未写明**，正例中"生产选定底图"主语含糊，agent 可能自选。应补进人决定清单或至少写"人未给定时停下来问"。

### 5. 是否调查不足 —— **按材料口径：状态如实，生产证据按声明缺位**
- 文档自我标注一致：新增端点全 `[S]`，并明文"新端点的开发副本检查不能标为生产 [R]"，与需求摘要"新增API保持[S]"吻合，没有伪 `[R]`。
- 本评审为封闭上下文，无法也不应验证源码行为；earth 3px 阻断、409 流、三来源真实命中等均无运行证据——这是已声明事实而非隐瞒，但意味着**转 [R] 前不得在生产用 auto 模式批量操作**。
- 文档内部可查处（如 `texture_image.task_id` 计预算、确定性产物不计 GPU）与 §1.2 口径互洽，未见敷衍。

## 四、规划 dry-run（纸面推演，未执行；生产计费预算尚未获准，以下不构成执行记录）

**场景**：新任务，两张地图。Map A「长安城坊市格局图」（site 级）、Map B「大运河全线走向概览图」（overview 级）。**用户均未给时代**。预算：图像 2 次、文本 8 次；videos/tts = 0。

**台账初始化**：`{images:2, text:8}`；每次提交前读台账，余额 ≤0 停下问人。

**Step 0｜缺时代阻断（0 消耗）**
按契约"缺时代不能擅自默认"，预期 brief 充分性产出 `issues:[{field:"era",blocking:true}]`。A 的"长安城"汉长安城与隋唐长安格局完全不同；B 的运河隋唐走向与元代截弯取直后的京杭走向差异巨大。**正确动作：一次性向用户问两图时代 + base_mode 选择（P1 缺口：契约未写归属，按全局精神问人）**，不让 AI 默认，不消耗模型调用。AI 可列候选时代作为"推断"呈报，但采用权在人。

**Step 1｜人答复后（假设：A=唐、image 路线用户提供带许可的扫描图；B=元明清、program 路线）**
- A：`POST /upload/image` 上传扫描件（0 GPU）→ PUT brief 含 `reference_image{path,source_url,license,control_points×3 非共线}`。注意：该扫描件为真实史料图，**绝不进 t2i/image_edit/i2v**，仅作配准底图。
- B：PUT brief（era、purpose、detail_level=overview、base_mode=program）。

**Step 2｜manual 逐步推进（预算紧，不用 auto 跨阶段）**

| 动作 | 文本 | 图像 | 备注 |
|---|---|---|---|
| A brief 充分性 | 1 | – | 契约未量化，按 1 预留（P1-5 的直接代价） |
| A research | 1 | – | 读回 `queries[]` 逐源命中/失败；三来源全无有效结果=未完成检索，阻断上报 |
| B brief 充分性 | 1 | – | |
| B research | 1 | – | |
| A/B 底纹提示（若 style 需文本） | ≤2 | – | 契约未写是否模板化，保守预留 |
| A style 底纹 | – | 1 | 无地理内容独立底纹 |
