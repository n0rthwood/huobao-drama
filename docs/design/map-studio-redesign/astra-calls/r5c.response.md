### B. 缺口补写（可直接粘贴）

#### B1. 建议值为零时，区分算法结果与无非零可行解

**插入位置**：03 §7.2，替换零建议值后的说明；同步替换 §11.1 的 `smoothing_zero_has_single_action` 断言。

**原文片段**
> 这条曲线在 0.05 的力度下也会超出容差，只能关闭平滑来保持原走势。

**新增文本**

> `suggestedStrength=0` 时只显示「关闭平滑 / Turn smoothing off」，直接采用既有算法结果，不自行提高建议值。  
> 通用说明为「当前算法未给出可采用的非零建议强度；建议关闭平滑。 / The algorithm returned no usable non-zero strength; turn smoothing off.」
>
> 不得仅凭返回值为 0 断言“0.05 也超限”：该值经过有限步二分及向下取档。只有同口径复算确实证明 0.05 超限时，才显示相应事实；只有能证明不存在非零可行解时，才显示「没有可用的非零强度，只能关闭平滑。 / No non-zero strength is feasible; smoothing must be turned off.」
>
> 验收：返回 0 时只有关闭动作；未取得额外复算证据时不显示“0.05 超限”的断言；关闭后重新计算完整曲线，不直接清空警告。

#### B2. 明确精确值 tooltip

**插入位置**：03 §7.1，精确详情说明之后。

**原文片段**
> 详情不只依赖鼠标 hover。

**新增文本**

> 偏离/上限数值组提供 hover 与键盘 focus 均可触发的精确值 tooltip；触摸点击打开等价详情。内容来自未按一位小数格式化的计算值，不把示例 `18.03 / 17.98` 当作固定展示精度。  
> 文案：「精确偏离：{deviation}px；精确上限：{limit}px / Exact deviation: {deviation}px; exact limit: {limit}px」。  
> 验收分别覆盖鼠标、键盘和触摸入口；一位小数相同时，主界面的「（超限）」标记仍保留。

#### B3. 缓存不得引入新的 bbox 精度变更

**插入位置**：04 §3.1，替换 bbox 行及其后量化精度说明；§3.2 删除请求 bbox 与生产 bbox 因量化不同的说明。

**原文片段**
> 每值量化至 1e-7 度  
> 命中请求自己的原始 bbox 可能与生产者有微小量化差异

**新增文本**

> 缓存使用既有模块确定、实际传给 renderer 与 registration 的 bbox，不增加坐标量化或容差合并。按 west、south、east、north 固定顺序，对实际数值进行无损、确定性序列化；仅消除不改变数值语义的表示差异。不同的有效 bbox 数值必须产生不同键。跨日期线继续沿用既有表示与校验，不排序或改写经度。
>
> 缓存层不得为提高命中率修改 bbox、投影或 registration。若现有模块在进入缓存前已有规范化，以该既有处理的输出为权威，不新增精度口径。
>
> manifest 记录实际渲染 bbox，命中时核对其与请求实际输入一致。移除本设计新增的 `1e-7` 量化及“小于 0.1px 即可合并”标准。
>
> `cache-normalization` 验收：同一数值的等价序列化及河集合顺序/重复项不改变键；两个不同的有效 bbox，即使差值小于 `1e-7` 度，也不得复用旧键。图像与 registration 必须对应实际请求输入。

#### B4. 编辑器正文补足持久化组与失效边界

**插入位置**：03 §10.2 之后，新增 §10.2.1。

**原文片段**
> 页面保存带当前接受快照的 `expectedRevision`

**新增文本**

> **10.2.1 保存组与失效**
>
> “页面保存”表示持久化责任归页面，不表示把所有脏数据合并为一次 PUT。几何使用「保存修改 / Save changes」，图层选项使用「保存图层选项 / Save layer options」，brief 使用「保存需求 / Save brief」；每组明确列出本次保存范围，不暗带其他组旧值。多组均脏时分别显式处理，前一组成功后更新 revision，再提交下一组。
>
> `layer_options` 的既有专门保存路径要求已有 `layer_doc` 且 brief/spec 未变；不满足时不得声称平滑已持久化。**实施前提**：核实无 `layer_doc` 时既有 API 是否可保存这些选项；若不能，须在允许的模块 API 范围内补齐真实持久化契约，并以保存后刷新恢复验收，不能只保留本地草稿冒充完成。
>
> 纯几何修改使成图过期，不因此重取底图；extent/bbox 修改使底图需要重做；普通 brief 修改按既有需求重启路径处理。上述服务端失效在保存结果中确认；本地草稿阶段仅提示预览与已保存图片不一致，不伪造服务端字段已清空。layer_options 成功保存后的输出变化依 02 §5 和返回 detail 展示，不自动重渲。

### C. 跨文档矛盾

#### C1. 03 与 01：TAB 切换

**矛盾**：01 §3.3 允许绘制草稿暂停、隐藏后切类；03 §2.2 要先完成、放弃或留下。

**裁定**：采用 03 的单活动形状仲裁。保留页面草稿及各类选择记忆，不保留跨类别悬挂的活动绘制事务。

**替换 01 §3.3 对应两条文本**

> 切 TAB 保留各类别选择记忆、zoom/pan 和页面已接收的未保存草稿。存在局部工作副本时，先选择「完成编辑并切换 / Finish editing and switch」「放弃局部改动并切换 / Discard local changes and switch」「留在当前类别 / Stay」。点数不足时禁用完成分支并说明要求。完成仅合入页面草稿，不 PUT；不得暂停隐藏局部绘制后直接切类。

#### C2. 03 与 01：普通布局、编辑专注模式

**矛盾**：01 §2 为默认 270px、画布与列表左右 62∶38；03 §1.1 为普通面板 720px、上下 65∶35。两者不能同时作为默认布局。

**裁定**：01 决定主界面注意力分配；03 的大尺寸上下布局用于显式专注模式。

**替换 03 §1.1 对应尺寸及布局说明**

> 普通主界面沿用 01 §2：1440×900 基准下编辑区约 270px，画布与当前类列表左右分栏，宽度比 62∶38；列表内部滚动，不把当前成图挤出首屏。
>
> 「放大编辑 / Enlarge editor」进入同面板专注模式，当前成图保留图片身份摘要；编辑区使用剩余空间，内部改为画布在上、列表在下，默认高度比 65∶35。720px 为专注模式可用高度示例，不是普通面板默认高度。画布 320px、列表 160px 等最小高度仅适用于该模式；视口不足时允许滚动。
>
> 关闭专注模式恢复原布局、滚动位置及同一份草稿、选择和视图状态。03 的上下布局线框标为「专注模式」。

#### C3. 03 与 01/02：条目按钮是否常驻

**矛盾**：01 §3.3、02 §4.1 要求未编辑时保留禁用的完成按钮；03 §6.1 此时只显示继续编辑。

**裁定**：线/面每个条目始终保留「完成编辑」位置；不把未编辑条目的完成按钮变为保存页面草稿的第二入口。

**替换 03 §6.1 非活动条目规则**

> 未在编辑：显示「继续编辑 / Continue editing」与禁用的「完成编辑 / Finish editing」，说明「没有进行中的局部编辑 / No local edit is in progress」。页面已有未保存改动时另显示「未保存 / Unsaved」，仍须由页面保存。
>
> 正在编辑且无实际改动：完成按钮禁用，说明「没有待提交的修改 / No changes to submit」；可取消退出，零 update、零 PUT。
>
> 正在编辑且有效、有修改：完成仅提交该条目局部副本；点数不足时禁用并给出原因。

#### C4. 03 与 02：完成编辑是否立即 PUT

**矛盾**：03 §5.2/§6.2 明确完成只入页面草稿；02 §4.2 给完成动作配置“编辑已保存”成功提示，§4.3 第 4 步直接写“点击完成编辑，PUT 成功”。

**裁定**：统一采用 03 的三层状态及页面显式持久化。

**替换 02 §4.1 完成编辑行的持久化说明**

> 本动作不 PUT。仅将该条目局部副本合入页面 specDraft；之后由用户点击页面「保存修改」通过 CAS 持久化。服务端 manual/confirmed、来源清理与输出失效，只在持久化成功后按权威响应呈现。

**替换 02 §4.2 完成编辑相关文案**

> 完成反馈：「已更新编辑预览，尚未保存。 / Editing preview updated; changes are not saved yet.」  
> 「正在保存编辑」「编辑已保存」「编辑未保存」分别属于页面持久化动作的进行中、成功及失败状态，不属于局部完成按钮。  
> 旁注：「结束本次局部编辑，不代表保存到服务端、确认几何或生成成图。 / Finish this local edit without saving to the server, confirming geometry, or rendering a map.」

**替换 02 §4.3 第 4 步**

> 4. 点击条目「完成编辑」或地点「保存到草稿」：预览更新，页面标脏，不发 PUT。再点击页面「保存修改」；CAS 成功后，三个坐标变更地点按服务端返回呈现 manual/confirmed，清理来源字段。之后才显示“编辑已保存”，恢复独立的几何确认动作。

**失效裁定**：03 与 02 对“确认不启动 drawing、服务端没有未确认几何强制闸门”没有矛盾；03 缺少保存组及失效细则，采用 B4 补齐，不另造失效矩阵。

#### C5. 04 §5 与 01 §7：关联字段口径

**差异**：01 只定义 `semantic_id` 的 kind＋ID 匹配；04 加入全局唯一 ID 和 `feature_id` 备选。后者虽标为假设，仍可能形成另一套关联规则。

**裁定**：以 facts 明确的 `semantic_id` 为正式契约；其他标识只能作为经 #125 最终契约证实的适配细节。

**替换 04 §5.1 的字段假设及判定顺序 1–3**

> 正式锚定入口为 `semantic_id`。在所选图片同源语义快照内，按 #125 最终定义的类别与标识解析；不得跨类别猜测。仅当实际契约明确证明标识全局唯一时，才可省略类别限定。
>
> `feature_id` 不是 facts 已确认的第二锚定契约，不直接启用备用查询。若 #125 最终提供等价映射，须先统一更新 01 §7.2 与本节，再由唯一读取适配层处理。
>
> 无锚点显示图层自身摘要；锚点存在但目标缺失，显示「该快照中找不到关联要素 / The linked feature is missing from this snapshot」，保留层自身摘要；多匹配或关联冲突显示「要素关联不明确 / Feature link is ambiguous」。均不得查询当前 spec 或按名称、距离补配。

#### C6. 04 §5 与 01 §7：缺 keywords 不应隐藏已有描述

**矛盾**：01 §7.2 的“description/keywords 缺失均正常降级”可能使缺 keywords 的有效描述降级；04 §5.2 明确缺 keywords 不降低 description 优先级。

**裁定及替换 01 §7.2 对应表行**

| 情况 | 规则 | 显示内容与文案 |
|---|---|---|
| #125 字段缺失 | description 与 keywords 独立处理；缺 keywords 不影响非空 description | 有 description 就显示；仅缺 description 时显示可用名称及几何摘要，并标“暂无要素描述”；独立存在的 keywords 可显示，但不代替描述 |

#### C7. 04 §5 与 01 §7：定位与编辑入口

**差异**：01 §7.3 禁用旧几何到当前编辑器的定位；04 §5.4 只明确禁用旧快照的图层编辑入口。两个入口不同，不能互相替代。

**裁定及补入 04 §5.4**

> 「定位到当前几何编辑器」与「图层编辑器」是两个不同入口。图与当前几何不一致、关联失效或无法证明对应关系时，禁用定位，提示「当前几何已变更，无法保证对应位置一致 / Geometry has changed; matching positions cannot be guaranteed」。旧快照进入图层编辑器的入口另按本节禁用。只读描述仍可查看，禁用入口不得导致图片或历史描述消失。

### D. 事实错误（与 facts.md 冲突）

以下区分“超出事实的断言”与“设计违反约束”，不把拟议接口、假设字段或尚未执行的验收当成现状错误。

| 文档说法 | facts 事实 | 证据 | 修正文本 |
|---|---|---|---|
| 03 §7.2：`suggested=0` 即“0.05 也超限” | 已核实的是 14 步二分后向下取档，低于 0.05 归零；返回零不单独证明精确测试过 0.05 | facts §1 V22；§3 平滑，`render/smooth.ts:227–237` | 使用 B1 的“算法未给出可采用的非零建议强度”；有复算证据才追加具体超限断言。 |
| 04 §3.1：缓存新增 bbox 量化，且 renderer/registration 使用量化结果 | V25 要求实际 bbox 参与完整键；任务明确不改几何校验/精确度口径，没有授权新增 bbox 容差合并 | facts §0 明确不做；§1 V25；§3 底图与缓存 | 使用 B3：无损序列化实际渲染 bbox，缓存不修改坐标精度，不合并不同有效 bbox。 |

其余重点核对结果：

- 03 明确当前服务端不阻塞未确认几何进入 drawing，没有虚构闸门。
- 04 将底图成品缓存写为拟议能力，没有把现有 DEM 瓦片缓存误说成成品缓存。
- 04 的 theme token、ID/manual 字段和历史快照能力均标明实施前提，没有把未知值当事实。
