# 第 2 轮：工作流停靠状态与行为契约

## 1. 术语、状态层次与三个模式

### 1.1 状态不得混用

| 层次 | 字段/术语 | 含义 |
|---|---|---|
| 服务端当前阶段 | `state.stage` | `brief / research / base / style / drawing / complete`，表示当前指针，不等于最后完成的阶段 |
| 工作流状态 | `state.status` | `idle / running / awaiting_review / blocked / failed / completed` |
| 阶段步骤状态 | `steps[].status` | `pending / running / awaiting_review / completed / failed / skipped`；没有 `blocked` |
| 人工停靠点 | 本文定义的 UI 派生状态 | 几何确认、底图就绪、成图待交付；不新增服务端几何合法性闸门 |
| 草稿状态 | 各编辑区本地状态 | `clean / dirty / saving / conflict`；不是工作流状态 |
| 几何未确认 | `geometryUnverified(spec)` 非空 | 软提示；不是 `blocked`，不能据此把任务显示成受阻 |

**阶段完成与当前阶段错位是正常行为。** 例如 manual 下 research 完成后：

- `steps.research.status = completed`
- `state.stage = base`
- `state.status = awaiting_review`

界面应显示“资料检索已完成 · 待准备底图”，而不是“底图已完成”。

下文中的“阶段 × 状态”描述该阶段工作的状态及其 UI 投影；**不声称所有组合都是服务端可产生的状态**。

### 1.2 模式定义

| 模式 | 谁触发 | 一次执行范围 | 自动推进终点 | 默认与入口 | 风险/边界 |
|---|---|---|---|---|---|
| `manual` | 人点击当前阶段动作 | 一个阶段 | 当前阶段完成后停；指针可能已移至下一阶段 | **任务默认模式**；主动作按阶段命名，不提供裸露的“逐步跑”模式切换 | 不自动进入下一阶段；用户仍须明确区分保存、确认与启动 |
| `guided`，本 Issue 新增 | 人点击“检索并准备底图” | 从需求/资料检索推进，完成 research 后自动执行 base | **base 完成即停**；不执行 style、drawing、complete | 主界面的“一键检索”动作使用它；不是把任务默认模式改成 guided | 不替人确认几何；未确认几何也允许完成 base |
| `auto` | 人在“AI 活动”抽屉内显式启动 | 现有连续执行流程 | `proceed=false` 或流程结束 | 仅抽屉“高级运行”入口；不得成为默认主动作 | **可能越过未确认几何进入作图**；#111 后服务端不以此阻塞 |

“默认 manual”指任务的日常推进策略；“一键检索”是范围固定的 guided 命令，不读取抽屉里上次使用的 auto 来决定终点。

### 1.3 guided API 形状与兼容

**设计新增，非现有 API：**

`POST /map-studio/tasks/:id/run`

请求语义：

| 字段 | 约定 |
|---|---|
| `mode` | 新增允许值 `guided`；已有 `manual / auto` 语义不变 |
| `expectedRevision` | 使用当前已确认的服务端 revision，遵循现有 CAS |
| 执行起点 | 允许当前阶段为 `brief / research / base`；从当前合法阶段执行，不隐式回退 |
| 固定终点 | `base`；不新增可任意越过人工停靠点的 `through` 参数 |
| 停止条件 | 失败、受阻、取消、`proceed=false` 或 base 完成，任一先到即停 |
| 重复执行 | 已有活动 run 返回 `409 workflow_busy`；不得另起并发 run |

guided 的 base 完成状态契约：

- `steps.base.status = completed`。
- `state.stage = style`，沿用阶段顺序，不伪造新服务端阶段。
- `state.status = awaiting_review`。
- run 已结束；style 尚未执行。
- UI 根据这些事实与 `outputs.base_image` 派生“底图就绪”。
- 几何是否确认独立显示，不改变上述终点。

兼容策略：

1. 老客户端继续使用 manual/auto，不改变其行为。
2. 新客户端只在确认服务端支持 guided 后启用“一键检索”。能力协商方式见第 10 节。
3. 不支持时显示“当前服务版本仅支持分步执行”，提供 manual 的“检索资料”“准备底图”；**不得静默降级成 auto**。
4. auto 继续保留现有连续运行能力。V2 的“无论 auto/manual 都停 base”不解释为修改全局 auto；改为：**主界面的一键检索永远 guided，与高级模式无关。**

下列条件由主表引用，避免把相同前置重复三十次。

| 回退编号 | 目标与清理 |
|---|---|
| R早 | 回退到 `brief / research / base`：清 `base_image / kmz / pip`，总是清 `final_image / layer_doc`，受影响 step 置 `pending` |
| R晚 | 回退到 `style / drawing`：总是清 `final_image / layer_doc`，受影响 step 置 `pending`；不据此宣称清底图 |
| R限 | 全任务回退上限 2 次；仅对服务端允许的历史目标展示。运行中先取消并等待活动 run 结束；“回退”不等于编辑保存 |
| R终 | `complete` 不是“返回更早阶段”的目标，不显示“回退到完成”；从完成区回退到较早阶段仍以服务端允许目标为准 |

`applyRollback` 的已知清理不包含 `render_draft / layer_options / texture_image`；UI 不得自行宣称这些字段已被清除，也不得把残留预览当成本轮有效成图。

**渲染按钮跨越 style 的约定：**

- 若指针已为 drawing，点击后启动一次 manual drawing。
- 若指针为 style，同一次明确的“渲染成图”意图先执行既有 style 跳过/推进，再使用返回的新 revision 启动 manual drawing。
- 不把这一步改为 auto，不执行 complete 或自动交付。
- 两个请求之间若出现 CAS 冲突、受阻、活动 run 或刷新，停止后续请求。显示“质感底纹已跳过，尚未开始作图”；不在刷新恢复时补发。
- `/advance` 在 style 的准确响应与推进方式列为实施契约核对项，不能假装已经有“直接渲染”端点。

### 2.3 各阶段失败/受阻态

失败时按 `error_detail.kind` 选择唯一主动作；受阻时优先解除真实前置条件。相同阶段的正常按钮被替换，不并列两个主色按钮。

| 阶段 × 状态 | 进入条件与停止位置 | 人工处理/确认含义 | 唯一主动作与次动作 | 回退 |
|---|---|---|---|---|
| brief · failed | 需求执行失败，链路立即停止 | 不确认、不推进 | 分型 F；次动作查看失败记录 | R早、R限 |
| brief · blocked | 缺 `brief.subject` 等真实前置 | 写 brief 后重新判断，不自动运行 | 补充需求 / Complete brief；次动作查看原因 | R早、R限 |
| research · failed | research 失败；已有进度不自动清空 | 续跑不等于接受几何 | 分型 F；有 progress 才提供续跑/清空 | R早、R限 |
| research · blocked | 服务端报告真实 blocking 问题 | 未确认几何本身不得进入此行 | 修正输入 / Fix input；次动作查看原因 | R早、R限 |
| base · failed | base 执行失败，不能宣称底图就绪 | 保留可读失败现场 | 分型 F；次动作查看失败记录 | R早、R限 |
| base · blocked | 缺 mapSpec、vision 等真实前置 | 修复对应前置，不写假 confirmed | 缺 spec：返回资料检索 / Return to research；缺 vision：配置可看图模型 / Configure vision model | R早、R限 |
| style · failed | 历史/异常 style 失败，不作为正常纸纹需求 | 不引导用户生成纸纹 | 分型 F；次动作查看失败记录；不能凭失败直接伪造 skipped | R晚、R限 |
| style · blocked | 仅展示服务端真实原因 | 不把纸纹缺失认定为阻塞 | 处理阻塞 / Resolve blocker；次动作查看原因 | R晚、R限 |
| drawing · failed | 作图失败；预览不等于 final_image | 不交付 agent 预览 | 分型 F；次动作查看失败记录 | R晚、R限 |
| drawing · blocked | 缺 mapSpec、vision 或其他真实 blocking | UI 几何停靠另行显示，不改服务端状态 | 按原因：返回资料检索 / Return to research，或配置可看图模型 / Configure vision model | R晚、R限 |
| complete · failed | 完成/交付准备失败 | 不显示“已交付”，先查交付记录避免重复操作 | 分型 F；次动作查看交付记录 / View deliveries | R限、R终 |
| complete · blocked | 缺 mapSpec 或实际交付前置不满足 | 不以继续按钮绕过 | 处理阻塞 / Resolve blocker；次动作查看原因 | R限、R终 |

补充规则：

- `idle / pending` 是未运行态：使用该阶段的启动动作；不显示“待复核”冒充已产出结果。
- `skipped` 仅用于 style step；其他阶段不提供“跳过”。
- `workflow_busy` 是请求互斥拒绝：重新读取 detail，显示正在运行的任务；不把当前 run 改成失败。
- 同时缺多个前置时只突出第一个可执行修复动作，其余列为原因清单。先输入，再模型配置，再启动。

### 2.4 #124 失败分型 F

以下是 **UI 动作路由设计**。现有事实只确认 #124 提供切模型重试、续跑、清空等能力，没有给出五类与请求的完整一一映射；具体调用必须复用现有处理，不创造新的重试端点。

| kind | 唯一主动作 | 次动作 | 禁止行为 |
|---|---|---|---|
| `steps_exhausted` | research 有可续进度：继续检索 / Continue research；否则：重试本阶段 / Retry stage | 查看已完成步骤 / View completed steps；research 可清空进度 | 不自动清空，不把 steps 用尽说成网络错误 |
| `ended_without_delivery` | 有可续 research：继续检索 / Continue research；否则：重试本阶段 / Retry stage | 查看未交付原因 / View missing-delivery details | 不把已有预览标为成功交付 |
| `call_error` | 切换模型并重试 / Switch model & retry | 查看调用错误 / View call error | 不因点击打开选择器就启动；选定并提交后才请求 |
| `rejected` | 修正后重试 / Fix & retry | 查看拒绝原因 / View rejection reason | 先定位 `problems[]`；存在问题时不盲目重复请求 |
| `mixed` | 查看并处理问题 / Review & resolve issues | 查看运行记录 / View run history | 不猜主要原因、不自动连发多次重试 |

清空研究进度是破坏性次动作：确认后调用既有 `/research-progress/clear`。它不等价于回退，也不承诺清底图或重置 spec。

重试遵循原执行边界：guided 重试仍最多到 base；从不因失败改用 auto。

## 3. 三个人工停靠点

### 3.1 几何确认

| 项目 | 设计 |
|---|---|
| 人看什么 | 几何编辑区的点/线/面 TAB；要素位置、名称、描述、来源/人工标记、未确认数；范围与 bbox；平滑偏离提示；参考信息区的需求和参考图 |
| 核对范围 | 当前 TAB 只画当前类，其余类不画；全局确认前必须能查看三类汇总，不能因隐藏类误以为不存在 |
| 确认调用 | 使用既有 map_spec 保存通道：PUT spec + `expectedRevision`。具体路由后缀以现有 API 为准，事实未提供完整路径 |
| 写入含义 | 对用户确认范围内要素清除 `proposed`；坐标未变且 `proposed!==true` 时由服务端设 `verification=confirmed`。不批量伪造 `origin=manual`，不删除未改要素的来源 |
| 是否推进 | **不推进阶段，不启动 run，不渲染** |
| 未确认后果 | 默认 UI 停在复核环节；base 可先生成。auto 或其他现有 API 调用仍可能进入 drawing |
| 草稿处理 | 有脏草稿先“完成编辑/保存”，确认按钮不可把未保存的修改与全量确认合成一次不透明写入 |
| 可视表达 | 主按钮“确认几何 / Confirm geometry”；状态“底图已就绪 · 还有 {count} 个要素未确认” |
| checklist | 需要简短核对项：范围、地点、线路、区域；不存在的类别标“不适用”。清单是复核辅助，不作为新的服务端闸门 |

显式旁注：

> 确认用于记录你的复核，不代表此前几何不合法。未确认几何不会被服务端阻止运行；高级自动运行可能直接进入作图。  
> Confirmation records your review; it does not make previously invalid geometry valid. The server does not block unconfirmed geometry, and advanced Auto may proceed to drawing.

若保存修改后所有要素已被服务端标为 confirmed，不再要求一次空 PUT：显示“几何已确认”，主动作改为“渲染成图”。不制造服务端没有的“全局复核签字”字段。

### 3.2 底图就绪

| 项目 | 设计 |
|---|---|
| 人看什么 | 底图预览的范围、地形、水系、registration；几何覆盖层；底图来源与缓存证据；不把缓存耗时当作命中证明 |
| 确认含义 | 接受当前底图作为下一次作图输入；**没有已核实的“底图确认”持久字段** |
| 调用 | 几何已确认时，“渲染成图”执行第 2.2 节的 style 推进 + manual drawing；不是 PUT proposed |
| 未确认后果 | 停留于底图就绪；改范围会触发底图失效，改普通要素坐标通常仅使成图失效 |
| 草稿处理 | 只做本地恢复草稿，不后台 PUT；有未保存修改先保存或放弃，不能渲染旧 spec 却让用户以为使用新草稿 |
| 可视表达 | 未确认几何：“底图已就绪 · 几何未确认”；已确认：“底图已就绪 · 可渲染成图” |
| checklist | 不再增加第二套确认清单；复用几何检查结果，避免两次同义批准 |

底图与几何停靠可以同时存在，动作优先级是：**保存草稿 → 确认几何 → 渲染成图**。

### 3.3 成图待交付

| 项目 | 设计 |
|---|---|
| 人看什么 | 当前成图、run_id、revision；图层描述及警告；遗漏要素；pip 细节；与上一版的区别 |
| 图像身份 | agent `render_draft` 标“AI 预览”；`final_image` 标“本轮成图”；历史成功图标“上一版”。查看器绑定所选图像同一 revision 的 layer_doc/语义 |
| 确认调用 | 既有 `POST /deliver` 通道，携带 `expectedRevision`；交付版本身份以返回的 sys_task id/交付记录为准 |
| 写入含义 | 创建/记录该版本交付，不清 proposed、不修改几何、不自动重渲 |
| 未确认后果 | 保留当前成图，停留待交付；允许服务端支持的回退与显式修改；修改后不得交付已经失效的“当前版本” |
| 可视表达 | 主按钮“确认并交付 / Confirm & deliver”；状态“成图已生成 · 尚未交付” |
| checklist | 需要：图像版本正确、图层内容已检查、警告/遗漏已知；此为 UI 检查，不宣称服务端已有审核字段 |

缺少 #125 的描述字段时显示几何摘要，不阻塞交付；不得显示空白错误状态。

## 4. “完成编辑”与“确认几何”分离

### 4.1 精确定义

| 动作 | 修改对象 | 持久化结果 | 阶段影响 |
|---|---|---|---|
| 完成编辑 | 当前条目的局部坐标/名称等草稿，经 `cloneSpec → markManual → emit('update')` 合入 specDraft | 页面 PUT spec；服务端逐要素比较，坐标变更要素变 `origin=manual`，清 `proposed / dataset_ref`，设 confirmed，并同步研究 features | 不主动 advance/run；服务端按保存内容执行既有失效逻辑 |
| 确认几何 | 明确列出的未确认要素集合 | PUT spec 清其 proposed；未改坐标的确认不应被前端批量 markManual | 不 advance、不 run、不渲染 |

事实未给出 spec、brief 的物理数据库表名：本设计以 `mapSpec`、brief、research features 为写入实体，不虚构表名。`task_observed_*` 是观测表，不用于保存编辑。

条目内“完成编辑”：

- 正在编辑该形状：结束当前操作，校验顶点下限，提交该条目的局部草稿。
- 未在编辑且无改动：禁用，旁注“此条目没有未保存修改”，不发空 PUT。
- 同一 spec 中另有脏条目：不能偷偷一起保存。提示“还有其他未保存的几何修改”，由用户选择“保存全部几何”或返回处理。
- 坐标保存导致该要素 confirmed，是服务端既有副作用，不等于全任务都已被人确认。

### 4.2 两组字符串文案

| 场景 | 完成编辑：zh / en | 确认几何：zh / en |
|---|---|---|
| 按钮 | 完成编辑 / Finish editing | 确认几何 / Confirm geometry |
| 保存中 | 正在保存编辑… / Saving edits… | 正在记录确认… / Recording confirmation… |
| 成功 toast | 编辑已保存；预览已更新，成图尚未重渲。 / Edits saved. Preview updated; the map has not been re-rendered. | 几何复核已记录；尚未开始作图。 / Geometry review recorded. Drawing has not started. |
| 失败 toast | 编辑未保存，已恢复服务端版本。 / Edits were not saved. The server version has been restored. | 几何确认未保存，请检查冲突或错误后重试。 / Geometry confirmation was not saved. Resolve the conflict or error and try again. |
| 旁注 | 保存当前编辑，不代表确认全部几何，也不会生成成图。 / Saves these edits; it does not confirm all geometry or render a map. | 记录对所列要素的复核，不改变坐标，也不启动渲染。 / Records review of the listed features without changing coordinates or starting a render. |

若网络超时导致保存结果未知，不能使用“未保存”的确定性失败文案，改用第 6 节的“保存结果待确认”。

### 4.3 用户流程示例

1. **AI 填入 15 个地点。**  
   guided 仍在准备 base；几何区显示 15 个地点与未确认标记。动作条“取消运行”；不弹出阻塞式确认框。

2. **base 完成并停靠。**  
   显示“底图已就绪 · 15 个地点未确认”。主按钮“确认几何”；地点 TAB 可编辑。

3. **人修改 3 个地点。**  
   SVG 即时显示草稿位置；显示“3 处修改未保存”。局部主动作“完成编辑/保存地点”；全局渲染不可用。

4. **点击完成编辑，PUT 成功。**  
   3 个坐标变更地点由服务端标为 manual/confirmed，清 proposed/dataset_ref；其余 12 个仍未确认。显示“编辑已保存 · 12 个地点未确认”。按钮“确认几何”。

5. **核对余下地点并确认。**  
   PUT 清相应 proposed，成功后显示“几何已确认”。不发 advance/run。

6. **检查底图。**  
   只改地点坐标、未改 extent/bbox 时，不要求重取底图。主按钮“渲染成图”。若修改了范围，则改为“准备底图”，完成后再回此停靠点。

7. **点击渲染成图。**  
   必要时跳过 style，启动 manual drawing；状态“正在渲染成图”，按钮“取消运行”。旧图若存在，标“上一版 · 正在渲染新版”。

8. **成图落盘。**  
   轮询取得当前 final_image 与对应 revision 的 layer_doc，显示“成图已生成 · 尚未交付”；按钮“确认并交付”。

## 5. 编辑失效矩阵

**读法：**保存编辑与 `applyRollback` 是不同操作。不能把回退的清理列表无条件套到所有保存路径上。

| 编辑动作 | 服务端阶段/输出后果 | proposed / origin | UI 必须显示 | 允许的下一个动作 |
|---|---|---|---|---|
| 改 brief 文本或其他非主题 brief 字段 | `restart='brief'`；brief 变化使底图需要重做。不能误写为直接把 stage 设 base；应先经过需求流程 | 不宣称因此批量清 proposed 或改 manual | “需求已更新 · 底图需要重做”；原成图仅可作为上一版 | 保存后从需求重新推进；可用 guided 到 base |
| 只改主题 | 历史/API 情况：base 已完成时 `restart='base'`，否则 brief；任务 UI 不再提供主题选择 | 不据此确认几何 | “样式设置已变化 · 需要重新生成”；不得承诺底图随主题换色 | 显式重新生成；不自动改写历史成图或人工 layer_doc |
| 改 extent 或 bbox | 回到 base，底图重做，成图失效 | 只有实际坐标变更要素适用 manual/confirmed 规则；改范围不是确认所有要素 | “范围已变化 · 底图需要重做”；旧图标上一版 | 准备底图；无新底图前不渲染 |
| 改要素坐标 | 几何本身只使成图过期，不要求重取底图；事实未给出所有情况下精确 stage 赋值 | changed 要素 `origin=manual`，清 proposed/dataset_ref，`verification=confirmed`，研究 features 同步 | “已转为人工几何”；“图与当前几何不一致” | 保存后确认剩余几何，再显式渲染 |
| 只确认未改坐标要素 | PUT 清 proposed；未变且 proposed 非 true 的要素被 confirmed；不额外承诺一定不触发 spec 保存失效路径 | 不批量改 manual，不批量删除 dataset_ref | “几何复核已记录”；图有效性按返回 outputs 判断 | 底图有效则显式渲染 |
| 改 layer_options | **仅 layer_doc 存在且 brief/spec 未变**时进入 `saveMapLayerDoc`；变化会清 `final_image` | 不改几何确认 | “图层选项已保存 · 成图需要重渲” | 显式重渲；不能交付被清除的当前图 |
| 回退 | ≤base：清 base_image/kmz/pip；所有回退总清 final_image/layer_doc；受影响 step pending；最多 2 次 | 未提供回退必然清 proposed/改 manual 的事实 | “已回退到{stage} · 剩余 {count} 次回退”；列实际失效产物 | 从返回阶段执行；不得自动开 run |
| 重跑检索 | run 本身不是通用失效 API；较晚阶段要先执行合法回退至 research，再运行，清理按回退规则 | 新结果以服务端返回 spec 为准；不承诺保留所有人工修改或全部 proposed | “重新检索可能改变已有要素”；人工修改存在时明确警告 | 选择续跑，或显式回退/清空后重跑；受回退上限限制 |
| 取消 run | 请求停止活动 run；事实未规定取消后最终 status、输出清理或 stage 重置 | 不假定清 proposed/恢复 origin | 先“正在取消…”；detail 确认后显示实际保留产物与阶段 | run 确认结束后，按返回状态继续/重试/回退 |

**精度边界：**给定事实没有列出 `saveMapWorkflowDraft` 每条分支对 `kmz / pip / layer_doc` 的完整赋值。已明确的是失效语义与回退清理；编辑保存后须以返回 detail 为权威，不能在设计中虚构额外字段清空。

旧成图若能读取，只能以其原身份展示；不得把历史图片配上最新 spec 的图层描述。

## 6. 编辑通道与 CAS

### 6.1 一次保存的完整时序

| 步骤 | 数据动作 | 界面与成功判定 |
|---|---|---|
| 1. 建立基线 | 读取 detail revision `r`，建立已保存快照 | 草稿 clean |
| 2. 编辑 | 数值编辑/删点/拖拽共用 `cloneSpec → markManual → emit('update')`；保存基线仍是 `r` | SVG 即时更新，显示“未保存”；不是“成图已更新” |
| 3. 本地校验 | 检查坐标、线至少 2 点、面至少 3 点等 | 拒绝操作需可见反馈；不静默失败、不发无效 PUT |
| 4. 用户保存 | 冻结本次提交快照，PUT + `expectedRevision=r` | saving；禁重复提交、禁推进、禁启动 run |
| 5a. 成功 | 接受成功响应中的 revision/规范化结果；若响应不含完整结果，则读取 detail 进行核对 | **服务端写入确认前不得显示成功**；最终草稿与服务端规范化结果一致才退出保存态 |
| 5b. CAS 409 | 不覆盖较新服务端版本；获取最新 detail | 回滚活动编辑草稿到最新服务端版本；本次未提交内容隔离保存为冲突副本，不再冒充当前 spec |
| 5c. 明确拒绝 | requireIdle、校验拒绝等；恢复服务端基线 | 错误 toast；不得清除错误后显示通用成功 toast |
| 5d. 断线/超时 | 提交是否落库未知；读取 detail 核实，不盲重发 | “保存结果待确认 / Save result pending”；仅能核实字段与版本后判定结果 |

“本地回滚”不等于销毁用户劳动：画布恢复服务端事实，冲突副本保留在独立区域供手动重做。

### 6.2 单页多草稿隔离

| 草稿 | 脏标记与保存组 | 防覆盖规则 |
|---|---|---|
| `briefDraft` | 需求区“保存需求 / 放弃修改” | 只提交 brief 修改；不夹带旧 spec/layer_options |
| `specDraft` | 几何区“保存几何 / 放弃修改”；条目内“完成编辑”入口 | 一次只允许一个几何提交事务；同 spec 多脏条目必须明确保存范围 |
| `layerOptionsDraft` | 图层区“保存图层选项 / 放弃修改” | 不与脏 brief/spec 合并提交，否则可能改变既有 `saveMapLayerDoc` 分支 |

共同规则：

- 页面写请求串行执行；每次成功后使用新 revision。
- 轮询更新服务端快照，**不直接覆盖脏草稿**。
- 别处保存改变 revision 时，不只替换旧草稿的 `expectedRevision` 然后提交；需对比其原始基线与最新实体，确认无冲突后显式重新建立提交。
- API 若要求完整对象，必须基于最新服务端对象叠加本组修改；不能提交整个页面早先缓存。
- 切编辑区提示：“保留草稿并切换 / 保存后切换 / 放弃修改”。保留不触发 PUT。
- 切点/线/面 TAB 保留各类选中态与草稿，切换显隐；正在绘制未闭合形状时先完成或取消，不隐式提交。
- 跨要素选择使用稳定 `kind:id`；拖拽期间不把选中目标重定向至另一个要素。

### 6.3 拒绝与互斥表现

| 场景 | 行为与文案 |
|---|---|
| 删除导致线少于 2 点 | 保持原线，定位条目：“线至少需要 2 个点，无法删除。 / A line needs at least 2 points. This point cannot be deleted.” |
| 删除导致面少于 3 点 | 保持原面：“面至少需要 3 个点，无法删除。 / A region needs at least 3 points. This point cannot be deleted.” |
| 无 registration | 只允许数值编辑；不猜像素坐标，不开放拖拽地理写入 |
| 本页编辑中启动 run | 有草稿先保存或放弃；不自动保存后偷偷启动 |
| 其他标签页启动 run | 保留草稿副本，编辑区只读；“运行已在其他窗口启动，暂不能保存。” |
| PUT 返回 requireIdle/workflow_busy | 回滚活动预览到服务端版本，隔离草稿副本；刷新 detail；不得报保存成功 |
| 对方更改/删除选中要素 | 取消失效选中，提示具体要素已变化；不按数组索引选中邻居 |

### 6.4 行为验收断言

1. 纯 zoom/pan 不产生 `emit('update')`、PUT 或几何 revision 变化。
2. 缩放、平移及 meet 信箱边距后拖点，写回经纬度与预期位置一致。
3. 地点列表、全部地点弹窗、线/面顶点编辑均经过同一 CAS 保存路径。
4. 保存成功后刷新，坐标、manual/confirmed、proposed 清理与服务端一致。
5. CAS 409 不覆盖较新数据，不显示成功；画布回到服务端版本，冲突副本仍可查看。
6. 下限删除拒绝有可见反馈，几何不变、请求不发出。
7. A 要素保存、B 要素仍脏时，B 不被悄悄保存或丢弃。
8. run 在编辑过程中启动后，保存被拒有反馈；不能覆盖 agent 新写入的数据。
9. SVG 预览更新不被宣传为 final_image 已重渲。
10. 深链恢复、TAB 恢复与选中恢复均零写入。

## 7. 一键检索完整时序与 V5 订正

| 时点 | 请求/服务端行为 | 停靠与 UI | 失败处理 |
|---|---|---|---|
| 点击前 | 确认需求已保存、subject 存在、没有活动 run、无未处理草稿 | 主按钮“检索并准备底图” | 缺输入先定位需求，不发 run |
| 点击 | `POST /run {mode:'guided', expectedRevision}` | 显示“正在检索资料”；主动作改取消 | busy 读取活动 run；CAS 显示冲突；不改用 auto |
| brief 阶段 | 若当前阶段为 brief，从该阶段执行 | 不新增需求审批弹窗 | 失败停在真实阶段 |
| research 阶段 | 扩展并填写几何；完成时 `proceed=true` | 已填要素可见；全部 proposed 时显示“{count} 个要素待确认”软提示，**不显示受阻** | 使用 #124 分型；已有进度可继续，不默认清空 |
| research → base | guided 自动衔接 base | 显示“资料检索已完成 · 正在准备底图” | mapSpec/vision 缺失按真实前置处理 |
| base 成功，几何已确认 | 写 base 输出与 bbox；结束 guided run；stage style/status awaiting_review | “底图已就绪 · 几何已确认”；主按钮“渲染成图” | 不执行 style/drawing |
| base 成功，几何未确认 | 同样结束 guided run | “底图已就绪 · 几何未确认”；主按钮“确认几何”；未确认标签持续可见 | 不把停靠伪装成服务端 blocked |
| 人修改几何 | PUT + CAS；仅改坐标按成图失效处理 | 保存后按返回未确认数更新；不自动重跑 research/base | 409 回滚活动草稿，保留冲突副本 |
| 人修改范围 | PUT 后底图需重做 | 主按钮“准备底图”；底图重新就绪后停 | 不静默复用旧范围底图 |
| 人要求重跑检索 | 若阶段已较晚，先确认合法回退至 research；按需选择续跑或清空 | 明示人工几何可能被新研究改变；回退清理可见 | 上限用尽时禁用回退，不能用重跑绕开 |
| 人点击渲染 | 必要时推进 style，然后 manual drawing | 才开始作图；成功进入成图待交付 | 不自动交付 |

高级 auto 启动前警告：

> **自动运行可能直接开始作图。** 服务端不会因几何未确认而停止；此模式可能越过人工核对并继续后续阶段。需要先看底图再核对，请使用“检索并准备底图”。  
> **Auto may start drawing without review.** The server does not stop for unconfirmed geometry. This mode may bypass human review and continue to later stages. Use “Research & prepare base” to inspect the base first.

抽屉确认按钮：“仍然自动运行 / Run Auto anyway”。该确认仅认可运行风险，**不清 proposed、不记录几何 confirmed**。

### 可直接收入设计文档的事实校正说明

> **V5 事实校正：**当前服务端不存在“未确认几何不得进入 drawing”的强制闸门。`accuracy.ts:88-95` 定义未核验几何的识别条件；`store.ts:575-578` 明确将仅因 `geometry_unverified` 而 blocked 的旧状态转换为可进入 base 的状态，并注明该变化来自 #111 提交。相关几何 issues 为软提示，research 与 base 均可继续推进。因此，不得将“确认几何”描述为服务端合法性的开关。
>
> 本 Issue 不修改服务端几何校验与精确度闸门口径。替代验收为：默认主界面的“一键检索”使用 guided，在 base 完成后结束 run，永不自动进入 drawing；保存与确认几何同样不启动 drawing；drawing 只能由用户在停靠点显式点击启动。保留 run/step 状态证据以及“底图就绪、几何未确认、作图未开始”的截图。高级 auto 仅存在于 AI 活动抽屉，启动前明确提示可能越过未确认几何，并留存入口与警告截图。若需对所有客户端强制阻止未确认几何进入 drawing，应另开 Issue，不纳入本次实现。

## 8. 状态持久化、刷新与并发

### 8.1 刷新恢复

恢复顺序：

1. GET detail，取得真实 stage/status、steps、outputs、issues 与 run。
2. 从持久事实派生停靠点，不读取“上次点击了哪个按钮”来决定流程。
3. `msstage` 用于查看对应阶段，`msrun` 用于查看对应历史运行；它们不覆盖实际当前状态。
4. 选中历史 run 时明确标“历史运行”，全局推进仍绑定最新 task revision。
5. 恢复失效实体时显示“所选阶段/运行已不可用，已返回当前状态”，不触发写入。
6. 深链恢复不发 PUT、run、advance、confirm 或 deliver。

停靠推导优先级：

`活动 run → 真实失败/受阻 → 未保存/冲突草稿 → 当前成图待交付 → 底图就绪且几何待确认 → 底图就绪可作图 → 当前阶段启动动作`

查看历史成图不改变这个流程优先级。

### 8.2 轮询与图片一致性

- 运行中沿用每 3 秒 detail 轮询；检测到终态后先完成一次最终结果读取，再停止运行轮询。
- 产物已落盘且 detail 可读取时，目标 ≤5 秒呈现；以实际时间戳验收。
- 不用本地计时猜测成图已完成。
- 所选图片、layer_doc、语义必须同 revision。缺历史配套数据时显示“此版本图层信息不可用”，不能拼最新 spec。
- 对非运行停靠页，建议增加窗口聚焦刷新；若希望持续感知其他用户启动，可采用低频只读刷新。该频率是设计新增，不冒充现状。

### 8.3 多标签页/多人冲突

冲突横幅放在**发生冲突的编辑区顶部**，动作条同时显示摘要；AI 活动抽屉不是冲突处理入口。

| 动作 | 推荐文案 | 真实含义 |
|---|---|---|
| keep | 保留我的草稿 / Keep my draft | 仅保留冲突副本；不强制覆盖。查看最新数据后手动重做或显式重新应用 |
| discard | 放弃草稿并使用最新版本 / Discard draft & use latest | 丢弃冲突副本，使用最新服务端状态 |
| 查看差异 | 查看冲突内容 / Review conflicts | 展示基线、本地改动、服务端版本；不自动合并坐标 |

横幅：

> 此任务已在其他窗口更新。你的修改尚未保存，画布已恢复为最新服务端版本；可保留草稿后重新处理。  
> This task changed in another window. Your edits were not saved, and the canvas now shows the latest server version. Keep your draft to reapply it.

`workflow_busy` 横幅：

> 此任务已有运行中的操作。结束前不能启动新运行或保存编辑。  
> This task already has an active run. New runs and edits are unavailable until it ends.

### 8.4 断线与超时

**假设的 UI 阈值，不作为服务端失败判据：**

| 观测 | 呈现 |
|---|---|
| 单次轮询失败 | 保留最后已知状态，显示“连接中断，正在重新获取状态”及最后成功刷新时间 |
| 连续约 15 秒无法读取 detail | “状态暂不可确认”；不把 running 改 failed |
| 仍能读取 detail，但观测活动长时间未更新 | 若存在可靠心跳/活动时间，超过约 90 秒提示“长时间未观察到更新，可能已中断”；注明“任务仍报告运行中” |
| 只有 detail 请求成功，没有心跳字段 | 只能说明服务器可访问，不能说明 agent 存活；显示最后可见活动时间，不编造心跳 |
| 服务端明确返回 failed | 才展示失败分型与重试 |
| 服务端明确确认运行已结束/取消 | 按返回状态恢复可操作；不推断为失败 |

“可能已中断”提供“刷新状态 / Refresh status”为主动作，取消作为次动作；不得自动重试，从而造成重复 run。

## 10. 假设与遗留

1. **需新增 guided API 能力。**  
   新增 `mode='guided'` 及 base 完成即停的服务端执行边界；建议能力字段 `capabilities.guidedToBase`，名称待实施确定。能力未知时使用明确的 manual 分步入口，不降级 auto。

2. **需核对 style 推进与交付响应契约。**  
   已知 `/advance`、`/deliver` 存在，但事实未列出完整请求/响应。实施时明确 style 跳过后的 revision 返回、交付成功记录与 completed 状态的对应；不增加自动几何确认。

3. **需补齐历史图片快照身份。**  
   detail 不直接提供历史 final_image 列表。优先从已有 runs/outputs/交付记录取得同 revision 的图片、layer_doc、语义；不足时增加只读快照字段/接口。取不到时显示不可用，不拼接最新数据。

4. **需确认持久运行模式与停止原因是否可读。**  
   停靠可先由 steps/outputs/stage/status 推导；若 runs 未保存 mode，建议补 `mode`，并可补 `stop_reason='base_ready'`，便于刷新解释和验收。不得依赖浏览器内存完成恢复。

5. **心跳时间与冲突草稿恢复为设计假设。**  
   15/90 秒仅是 UI 提示阈值。若 observed 无可靠活动时间，需补只读 `last_activity_at` 或降级为“状态暂不可确认”；本地草稿恢复必须绑定 task、基线 revision，恢复后不自动 PUT。

6. **保存分支的细粒度清理与 #124 动作绑定须在实施中核对。**  
   本文仅承诺事实明确的 restart、失效、回退清理与 CAS；不为未知分支造字段。验收用返回 detail 检查实际产物与阶段，同时确保所有恢复动作遵守原 manual/guided 边界，不以 auto 绕过人工停靠。
