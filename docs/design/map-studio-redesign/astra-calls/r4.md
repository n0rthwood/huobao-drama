## 必须产出

### 1. 历史兼容三政策（必须分开写，逐条可执行）
用三张独立小节，每节给：适用范围、用户可见行为、内部行为（阶段/字段）、验收方式、禁止事项。
1. **新任务政策**：默认主题 atlas-tint、无纸纹、底图走缓存。包括「用户怎么知道底图来自模板缓存」（一句话 + 证据入口），以及默认主题的呈现方式（既然没有主题选择器，要不要在「更多」里显示「制图主题：默认（atlas-tint）」只读字样）。
2. **旧任务再次生成政策**：要素样式按默认主题重建（drawing 阶段由 resolveMapStyle 驱动）；旧 texture_image 不再参与合成。要说明：任务 1 这类既有任务打开时，UI 会不会提示「本任务的要素样式已按默认主题重建」；以及 brief.map_style 字段只读兼容的呈现（哪里显示、什么文案、不提供修改入口）。
3. **已有历史成图与人工编辑样式保留政策**：已交付版本、人工 PUT 的 layer_doc 原样保留，不重渲不改写；只有用户显式重做（回退重跑 drawing）时才按新政策。给「显式重做」的操作路径与警告文案（会改变视觉样式，是否先提示）。

### 2. 纸纹残留迁移（V9/V10）
- 识别条件（按 v2 原文 + `facts.md` 事实）：`outputs.texture_image.provenance.source='diffusion-texture'` 且（renderer 含 relief 或 texture run_id 早于最近 base run）。给出 SQL 层面的「清单字段」（只读字段名列表，不写 SQL 语句）与每行要记录的信息（task id、title、texture path、texture run_id、最近 base run_id、判定原因、是否会跳过）。
- dry-run 报告的形态（命令行输出格式示例、统计汇总、可导出的清单）。
- apply 的规则：备份原字段到 history snapshot（字段名与结构）、幂等、在飞任务（status running）跳过、失败可回滚（回滚顺序）。
- 用户可见影响：旧任务打开后 texture 字段为 null 的界面表达；重渲时不再叠纸纹的前后对比证据要求。
- 明确「不重渲真实历史任务」的验收策略：专用样本任务如何复刻旧状态（列出要伪造的字段组合，例如 provenance.source + run_id 关系），样本的创建/清理规则。

### 3. 底图模板缓存（V25-V27）
- 缓存键规范：字段清单（bbox 的量化方式与精度、像素尺寸、投影、DEM manifest sha、NE/OSM manifest 指纹、renderer 版本号来源、叙事河豁免集指纹），每个字段给「如何计算/取值的文字描述 + 规范化顺序」，并说明为什么 bbox 用像素尺寸而非画幅、豁免集为什么要进键。
- 键的序列化与目录布局建议（`DATA_ROOT/map-data/base-cache/<key>/…`，manifest.json 内容字段：key 各分量原值、产物 path/width/height/sha256、created_at、renderer 版本、atlas 版本）。
- 原子写入与完整性：tmp + rename、sha256 校验、损坏重建、单飞（同一键并发只渲染一次）的语义；TTL/容量上限（是否要，给取舍）。
- 只缓存纯底图：明确不含任务要素、不含 pip 细节框、不含标题。
- 用户可见语义：底图区域的一个小标注「模板缓存命中 / 新渲染」，以及「为什么这次没等很久」；不要暴露内部键（可放在 tooltip/证据面板）。
- 验收断言：完整键一致命中；renderer/manifest/豁免集任一变化未命中；损坏文件重建；并发单飞（观察日志）；命中证据 = key + manifest + sha；耗时仅参考。
- 「同 bbox + 画幅」的旧表述要纠正为「完整键一致」（V27）。

### 4. 主题简化（V28 + Issue 阶段 3）
- UI 移除清单：任务级 `MapStylePicker`、模块设置 default_style 编辑入口；`GET /styles` 保留但 UI 不暴露。
- 服务端：`resolveMapStyle` 固定返回默认家族（atlas-tint），brief.map_style 只读兼容（存量任务不报错）；新任务的 spec.style 如何记录（theme/map_style 字段值），以及「不因为 brief.map_style 有值就切换家族」的口径。
- 技能/提示词：地图工作室技能里主题分支如何简化为默认主题描述；哪些文档要改（AGENTS.md 地图工作室节、docs/skills/huobao-director 的 API 点）。
- 一个「移除后的界面」小线框（brief 表单区域），并说明用户如果问「为什么没有主题了」在哪看到一句解释。
- 验收：新任务无主题选择入口；存量带 map_style 任务打开不报错、按默认渲染要素样式；实施时如何证明（字段 + 截图）。
