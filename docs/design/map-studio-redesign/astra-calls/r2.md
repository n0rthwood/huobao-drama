# 第 2 轮产出：工作流停靠状态表（服务端阶段 × 运行状态 × manual/guided/auto）

约束与事实见随附 `facts.md`。本轮的硬目标是 v2 第一节（V1-V5）与 V19-V21 的失效口径；不要重复第 1 轮的主界面布局，只给**状态与行为**。

## 必须产出

### 1. 术语与三个模式
用表格定义 manual / guided / auto 三个模式的语义（谁触发、跑几个阶段、停在哪、默认哪个、入口在哪）。注意：guided 是本 Issue 要新增的形态（一键检索到 base 停靠，`facts.md` 第 4 节第 1 条），给它的 API 形状与兼容策略；auto 仅存在于 AI 活动抽屉内，作为高级选项，并明确它的风险（会越过未确认几何，因为服务端 #111 之后不阻塞）。

### 2. 主状态表（核心交付物）
表结构（行 = 阶段 × 人工停靠状态，列 = 事实）。必须覆盖 brief/research/base/style/drawing/complete 全部阶段，以及每个阶段的三种可能状态：进行中（running）、停靠待复核（awaiting_review）、完成（completed）、失败（failed）、受阻（blocked）、跳过（skipped，仅 style）。

每行必须写清 6 件事：
1. 进入条件（服务端前置：mapSpec、base_image、vision 配置、run 互斥）
2. 自动推进终点（这个阶段结束后会不会自动进入下一阶段，取决于模式）
3. 人工停靠点？（是/否 + 停靠含义：看什么、判什么）
4. 确认含义（点「确认/继续」实际写入什么，spec 里 proposed 清除？只推进 stage？）
5. 失败/受阻时的唯一动作与次动作（#124 五种 kind：steps_exhausted / ended_without_delivery / call_error / rejected / mixed）
6. 回退（能否回退到此阶段、上限 2 次、回退后清哪些产出：base_image/kmz/pip、final_image/layer_doc、step 置 pending）
表格过长可拆成「阶段主表」+「失败分型表」。给出每个阶段主色按钮的精确文案（zh + en）。

### 3. 三个人工停靠点详设
分别给：几何确认、底图就绪、成图待交付。
每个停靠点给：
- 人在这一步要看的信息（清单，与主界面哪块对应）
- 「确认」按钮的确切语义与调用（例如 PUT map_spec with cleared proposed / POST advance / POST deliver）
- 不确认时的后果（停在这里、能被回退、autosave 草稿怎么处理）
- 停靠点的可视表达（主色按钮 + 一行状态 + 是否需要 checklist）
- 若服务端此刻并不阻塞（几何确认），UI 如何让人不误以为「点了才算合法」

### 4. 「完成编辑」vs「确认几何」语义分离（V4）
- 给出两个动作的精确定义（谁改什么、写哪张表/字段、是否推进阶段）。
- 给出两条字符串文案族（按钮、成功 toast、失败 toast、旁注说明），zh + en。
- 给一个「用户视角流程」示例：AI 填了 15 个地点 → 人改 3 个 → 完成编辑 → 确认几何 → 底图 → 渲染。每一步界面状态与按钮变化写成编号序列。

### 5. 编辑失效矩阵（V4 + 服务端事实）
表列：编辑动作（改 brief 文本 / 只改主题 / 改 extent 或 bbox / 改要素坐标 / 改 layer_options / 回退 / 重跑检索 / 取消 run）/ 服务端后果（stage 回退到哪、哪些 outputs 被清、proposed 清除、origin 变 manual）/ UI 必须显示什么（例如「成图已过期」「底图需要重做」「已转为人工几何」）/ 允许的下一个动作。
必须以 `facts.md` 第 3 节 `saveMapWorkflowDraft` 与 `applyRollback` 的行为为准，不要臆造。

### 6. 编辑通道与 CAS（V19-V21）
- 一次保存的完整时序（编辑 → 草稿 → 保存 → PUT → 成功/409 → 本地回滚 → toast），写清楚「不得显示保存成功」的判定点。
- 单页多处草稿（briefDraft/specDraft/layerOptionsDraft）如何避免互相覆盖：脏标记、保存按钮分组、切块时的提示。
- 点数下限拒绝、跨要素选中、编辑过程中 run 启动（409 workflow_busy / requireIdle）的表现。
- 给行为验收断言列表（纯 zoom/pan 零写入、save 后刷新一致、409 不覆盖、下限拒绝有反馈）。

### 7. 一键检索的完整时序（V2/V5）
以表格给：点击 → 请求 → 服务端阶段循环 → 停靠 → UI 呈现 → 若失败 → 若人改几何后重跑。
明确：
- research 完成但几何全是 proposed 时的 UI 表现（软提示、不是 blocked）
- base 成功且有人工确认的几何 → 停靠；base 成功但几何未确认 → 也停靠（UI 强调「未确认」标签）
- drawing 只能由人在停靠点点击启动；auto 模式例外并给出警告文案
- 订正 V5：给一段可直接放进设计文档的「事实校正说明」，包含证据（accuracy.ts:88-95、store.ts:575-578、#111 提交）与本 Issue 不改服务端口径的声明，以及可执行替代验收（默认流程永不自动进 drawing + 截图证据；auto 模式在抽屉内且明确警告）。

### 8. 状态持久化与刷新
- 页面刷新后如何恢复到同一停靠点（detail 轮询 + 深链 msstage/msrun；恢复不触发写）。
- 多标签/两人同时打开同一任务：CAS 冲突、workflow_busy、conflict keep/discard 的建议文案与位置。
- 断线/超时：running 状态的超时呈现（观测心跳），何时显示「可能已中断」，何时真的失败。

### 9. 与本轮状态表配套的文案表
`mapStudio.stage.*`、`mapStudio.status.*`、停靠点文案、失败分型横幅文案（zh/en），键名沿用现有命名风格。
