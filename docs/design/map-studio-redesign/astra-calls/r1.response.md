## 1. 设计原则

1. 主界面始终同时显示地图身份、所选图片身份及状态、唯一下一步动作，不以日志替代结果。
2. 当前成图获得最大固定空间，几何编辑器其次；资产表单、历史与 AI 过程默认收起。
3. 「一键检索」止于底图就绪，「确认几何」只确认，「渲染成图」只由用户另一次显式点击启动。
4. 图片、图层文档和语义描述必须来自同一快照；无法证明同源时显示缺失，不拼接当前数据。
5. 「完成编辑」保存局部几何，「即时上图」更新编辑预览，二者均不暗示服务端成图已更新。
6. 深链恢复只改变本地 UI 状态，任何保存、确认、生成、交付均须独立用户动作。

## 2. 注意力预算与视觉层级

以全屏面板 **1440×900** 为基准；比例包含区域内间距，合计 100%。较矮窗口允许内容区滚动，顶栏和停靠条固定，不压缩按钮与编辑输入框。

| 区域 | 占视口高度比例 | 信息密度 | 是否可折叠 | 默认可见性 |
|---|---:|---|---|---|
| 单一顶栏 | 6%，54px | 低：宿主身份、阶段/状态一句话、AI 活动、更多 | 否 | 始终 |
| ①资产信息摘要 | 8%，72px | 中：需求摘要、参考图缩略 | 可展开 brief 表单 | 摘要可见，表单收起 |
| ②当前成图 | 48%，432px | 低：图片、身份角标、一句下一步说明 | 不允许完全收起 | 始终，空态也保留 |
| ③点线面核对与编辑 | 30%，270px | 中高：单类画布与条目 | 可收起、可进入编辑专注模式 | 有几何时展开；无几何时占位 |
| ④动作条／停靠条 | 8%，72px | 低：停靠原因、唯一主按钮 | 否 | 始终 |

**分配取舍：**

- ②不是结果卡片网格，而是一张大图。图层栏打开时占②宽度的 28%，不增加纵向区块。
- ③使用「画布 62%＋当前类别列表 38%」双栏；长列表内部滚动，不把②挤出首屏。
- 「放大编辑」进入同面板专注模式：②保留图片身份摘要，③占剩余内容区；关闭恢复原比例和滚动位置。这是显式工作模式，不是默认布局。
- 展开 brief 表单使用①下方局部覆盖面板，不长期推低成图；存在未保存草稿时关闭需明确保留或放弃。
- 空态不把编辑器空间让给日志；保留流程预期。用户首次完成检索后，布局不发生大幅跳变。

### 3.2 阶段轨的最小表达

主界面只显示一个状态句，例如：

> 底图已就绪 · 待复核几何

服务端可能已经是 `stage=style, status=awaiting_review`；状态句依据完成的步骤解释，不伪造服务端阶段。浮层同时显示：

> 当前服务端阶段：质感底纹；该步骤固定跳过，不生成纸纹。

六个服务端阶段仍完整保留：**需求 → 资料检索 → 底图 → 质感底纹 → 作图 → 完成**。不再竖排六行，不在每阶段旁常驻回退按钮。

### 3.3 编辑器行为边界

- TAB 是硬显隐：地点 TAB 只画地点，线 TAB 只画线，面 TAB 只画面；底图始终保留。
- 切 TAB 保留各类别选中项、缩放和局部草稿；正在画线时切到面，线草稿暂停且隐藏，不提交、不丢弃。返回线 TAB 继续。
- 有未完成绘制时显示“线有未完成编辑”，不以隐藏草稿充当已保存几何；确认几何、渲染均须先处理草稿。
- 地点列表提供名称、经纬度、删除和保存；“全部地点”弹窗复用同一草稿与保存通道，避免产生第二份数据副本。
- 线／面条目内始终有「完成编辑」位置：
  - 正在编辑且有合法修改：提交该条目草稿。
  - 正在编辑但点数不足：禁用并给明确反馈。
  - 未在编辑或无修改：禁用，提示“没有待保存的编辑”；「继续编辑此形状」另作中性操作。
- 「完成编辑」不等于全任务几何确认；服务端因人工编辑设置的 confirmed 字段照实呈现，但 UI 仍保留整体核对停靠。
- 无 registration 时只允许数值编辑，显示“缺少地理配准，无法在图上拖动”；不猜测坐标。

## 6. 当前成图主视图：快照身份模型

### 6.1 建议结构

建议将 **产物类型** 与 **展示身份** 分开，避免一张已交付图片无法同时作为上一版显示。

| 字段 | 含义 |
|---|---|
| `snapshot_id` | 不可变图片快照标识，深链定位主键 |
| `artifact_kind: base \| draft \| final` | 产物实际类型 |
| `kind: draft \| final \| previous \| delivered` | 当前展示身份；base 单独显示“底图” |
| `run_id` | 实际生产该图片的 run，不填当前活动 run 代替 |
| `revision` | 图片发布时的产物 revision，不随普通 detail 更新变化 |
| `stage` | 生产图片的阶段 |
| `produced_at` | 实际产出时间；未知显示未知 |
| `path, width, height` | 图片位置与像素尺寸 |
| `provenance_rev` | 指向生产时输入及来源快照的不可变标识 |
| `spec_revision, brief_revision` | 生产使用的几何、需求版本；也可用内容指纹实现 |
| `layer_options_revision` | 生产使用的图层配置版本 |
| `layer_doc_ref, semantics_ref` | 同一图片快照关联的数据；允许缺失 |
| `delivery_id` | 若已交付，指向既有交付版本，不改变图片原始身份 |

这些字段是建议的读取契约。事实底座只证明现有图片带 `run_id/provenance` 等，**不能据此假定图片 revision 和历史同源语义已齐全**。

### 6.2 默认选择规则

| 优先级 | 判定 | 展示 |
|---:|---|---|
| 1 | `final_image` 已发布；生产 stage 为 drawing，任务处于 drawing 收尾或 complete；`run_id` 匹配本轮 drawing run；有稳定 revision | 本轮成图 |
| 2 | 本轮 drawing 的 `render_draft` 已有可读取图片引用，带 run/revision | AI 预览，未定稿 |
| 3 | 历史可验证的最后成功 final；可以来自交付快照 | 上一版；另附已交付标识 |
| 4 | 无可用成图 | 尚未生成成图 |

补充规则：

- “本轮 drawing run”不是“最新 run”：后续 complete run 不会把刚完成的 drawing 图误标上一版。
- 无成图而有 base 时，空态内展示底图，标“底图 · 尚未生成成图”；底图不进入 final 优先级竞争。
- 用户显式选中历史快照后，轮询不抢走选择；显示“新版已就绪”中性导航入口。默认自动视图才自动切新图。
- `outputs.final_image` 非空本身不足以证明“本轮”；身份无法确认时显示“成图版本信息不完整”，不冒充本轮。

### 6.3 视觉身份

| 身份 | 角标文案 | 颜色语义 |
|---|---|---|
| draft | AI 预览，未定稿 | 琥珀色，非交付产物 |
| final | 本轮成图 · rN | 中性深色；完成不自动等于交付 |
| previous | 上一版 · rN | 灰色历史身份 |
| delivered | 已交付 · 版本 N | 绿色完成语义 |
| previous＋drawing running | **上一版 · 正在渲染新版** | 灰角标＋独立进度图标，不把旧图染成“运行中结果” |

失败时改为“上一版 · 新版渲染失败”，不得继续显示正在渲染。

### 6.4 失效规则

| 变化 | 图片呈现 | 工作流处理 |
|---|---|---|
| spec 已编辑，未重渲 | 保留原图，显示 **图与当前几何不一致** | 清除 UI 整体确认；按服务端返回状态行动；一般几何变化不自动重取底图 |
| bbox/extent 变化 | 旧图加不一致提示；旧底图不得当作新范围已就绪 | 展示服务端回 base 的结果，主动作准备底图 |
| brief 变化 | 原图转上一版，提示“需求已变更，请重新准备地图” | 普通 brief 变化显示回需求；受影响底图按服务端失效口径处理，不由 UI 猜测保留 |
| layer_options 变化清空 final_image | 若有历史快照则显示“上一版 · 图层设置已变更”；否则空态 | 主动作重新渲染；旧文件路径缓存不是正式历史来源 |
| 仅更新其他 task revision | 不自动判图过期 | 比较生产输入来源，不能用 `image.revision != task.revision` 一刀切 |

任务级主题入口移除，因此不提供“只改主题”的新 UI 路径。

### 6.5 立即显示与收尾

- 运行中沿用 **每 3 秒 detail 轮询**；drawing 收尾不能只因 status 离开 running 就停止读取。
- 建议 detail 原子发布 `final_image + snapshot_id/revision + layer_doc_ref + semantics_ref`，使“已落盘”和“可读取快照”成为同一次可见更新。
- `render_draft` 更新只替换 draft 身份，不因画面看似完整升级为 final。
- 只有发布的 final 满足 run/revision 判定才显示“本轮成图”。
- 终态已到但快照尚未发布：显示“正在同步成图”，继续轮询；接口应消除这一非原子窗口，而不是无限依靠 UI 等待。
- ≤5s 验收从服务端产物可发布时点到浏览器实际显示计算，记录落盘、detail 返回、图片加载完成时间。3s 周期只是设计手段，慢网络不虚报达标。

### 6.6 大图与查看器

点击②图片进入全屏只读查看，保留身份角标、快照选择器和“图层”入口。缩略图与全屏共用选中快照；关闭全屏只关闭显示层，不清除图片选择或其他深链状态。

## 7. 图层描述查看器

### 7.1 入口和布局

- ②右上“图层”中性按钮打开右侧栏；成图待交付状态默认展示该栏。
- 左侧是所选图片，右侧上半部为层列表，下半部为选中层描述。
- 全屏时仍使用右侧栏；窄屏改为下方可展开面板。
- 查看器不复用图层编辑器的写按钮，不提供“保存描述”。

### 7.2 层 → 要素映射

| 情况 | 规则 | 显示内容与文案 |
|---|---|---|
| 有 `semantic_id` 锚定 | 在该图片快照的 semantics 中匹配 kind＋id；不跨类别猜测 | 层名、对应要素名、description、keywords；条目级 manual 标记按 #125 数据显示 |
| 多层共用要素 | 每层独立显示同一个要素快照描述 | “与其他 N 个图层共用要素描述”；不合并层，也不复制为可写字段 |
| 无锚定层 | 不按名称模糊匹配 | 层自身 name、类型、几何摘要；“此图层未关联语义要素” |
| #125 字段缺失 | description/keywords 缺失均正常降级 | 显示可用名称和几何摘要；“暂无要素描述” |
| 锚点存在但目标缺失 | 视为快照关联缺失，不查询当前 spec 补齐 | “该快照中找不到关联要素”，保留层自身摘要 |
| 图片缺同源 layer_doc | 不使用当前 outputs.layer_doc 冒充 | “此版本未保存图层数据”，禁用层选择 |

### 7.3 版本与不一致规则

- 查看器标题显示“对应图片 rN”，其数据跟随 `mssnapshot`，不跟随最新 spec。
- “图与当前几何不一致”时，历史描述仍可读；禁用「定位到当前编辑器」，提示“当前几何已变更，无法保证对应位置一致”。
- 无同源语义时仅显示层自身几何摘要；#125 合入后，**包含字段的新快照**自动显示描述，不回填或改写旧图。
- 人工 PUT 的历史 layer_doc 原样保留，不能因描述缺失触发自动生成或重渲。

### 7.4 空态与缺字段文案

| 场景 | 中文 | English |
|---|---|---|
| 无成图 | 成图生成后可查看图层 | Layers will be available after rendering. |
| 无 layer_doc | 此版本未保存图层数据 | No layer data was saved for this version. |
| 无 description | 暂无要素描述 | No feature description is available. |
| 无锚定 | 此图层未关联语义要素 | This layer is not linked to a semantic feature. |
| 锚定失效 | 该快照中找不到关联要素 | The linked feature is missing from this snapshot. |
| 不一致 | 当前几何已变更，无法保证对应位置一致 | Geometry has changed; matching positions cannot be guaranteed. |

## 8. AI 活动抽屉

### 8.1 入口与尺寸

顶栏固定「活动轨迹图标＋AI 活动」，有运行时附小型动态标记，有失败时附警示点；不显示日志条数形成额外 chip。

桌面抽屉宽 **560px**，可切全屏；不关闭宿主地图面板。默认当前活动 run，无活动 run 时默认最近 run；深链显式指定 run 时优先恢复该选择。

### 8.2 内部结构

| 分区 | 数据源 | 默认形态 | 空态 |
|---|---|---|---|
| 运行列表 | `detail.agent.runs` | 顶部当前 run 选择器，可展开历史 | 尚无运行记录 |
| 逐轮记录 | `detail.agent.rounds/attempts`＋所选 run observed | 当前轮展开，历史轮折叠 | 此运行暂无逐轮记录 |
| 调用与消息 | `/runs/:id/observed`；`/calls/:id/messages` | 调用列表；点 call 才加载消息 | 此调用暂无消息 |
| 失败现场 | 所选 run 的 error_detail、rounds、problems、steps_used | 失败 run 默认展开 | 此运行未记录失败现场 |
| 模型与运行设置 | 既有模型配置和 mode 绑定 | 默认折叠 | 配置不可用时说明，不伪造默认值 |
| 任务变更／交付历史 | `detail.history`、既有交付记录 | 折叠只读 | 暂无历史记录 |

**历史失败详情前提：** 当前 detail 的 `error_detail` 不能冒充所选历史 run 的错误。若 observed 未提供历史错误，需扩展同一读取接口；不新增表，也不凭当前错误推断历史失败。

auto 放在这里，因为它影响代理推进策略，不是用户每次制图必须选择的输入；主路径不再暴露 manual/auto 开关。

### 8.3 只读与操作边界

| 操作 | 放置 | 规则 |
|---|---|---|
| 查看 run/round/call/消息 | 抽屉 | 纯 GET |
| 切换模型 | 抽屉「模型与运行设置」 | 显式保存配置；不自动重试，运行中禁止改当前 run |
| 续跑／重试 | ④唯一主动作 | 抽屉只显示“返回主界面处理”，不复制同权按钮 |
| 清空 research progress | 抽屉「研究进度」危险操作 | 非运行时可用，二次确认；调用既有 clear 端点，不自动再跑 |
| cancel | ④更多菜单 | 抽屉只显示取消状态，不另设同权按钮 |
| 回退 | 顶栏更多／阶段轨选中目标后的确认入口 | 同一命令入口逻辑；上限 2 次，运行中禁止 |
| auto 开关 | 抽屉高级设置 | 明示“仅影响适用运行段；一键检索仍止于底图，不自动确认几何” |

### 8.4 请求时序

1. 打开抽屉：复用当前 detail 的 runs/rounds/attempts，不重复请求整任务。
2. 确定所选 run：请求 `GET /runs/:id/observed`。
3. 展开轮次：筛选已取 observed 内容；只有接口本身支持分页时才继续分页，不能假定已有分页字段。
4. 选中 call：确认它属于所选 run，再请求 `GET /calls/:id/messages`。
5. 切换 run：保留已读缓存，取消或忽略旧请求结果；消息响应不能落到新选中 call。
6. 当前运行抽屉打开时，随 detail 刷新更新该 run 的观测；历史终态不持续轮询。
7. 关闭抽屉停止观测刷新；主 detail 轮询不受影响。

深链：`msactivity` 控制开关，`msrun` 选 run，`mscall` 选 call，`mscf` 按阶段筛选，`msround` 选轮次。

## 9. 动作条：唯一主动作矩阵

### 9.1 API 记法与约束

- `RUN(m)`：既有 `POST /tasks/:id/run {mode:m}`。
- `SEARCH`：建议 `POST /tasks/:id/run {mode:'guided', stop_at:'base', expectedRevision}`。
- `ADVANCE`：既有 `POST /tasks/:id/advance`，继续使用现有请求体与 CAS。
- `SAVE`／`CONFIRM`：复用既有草稿 PUT、`writeBrief` 和几何接受写入通道；确切路由及确认字段不在事实底座中，不新增猜测端点。
- `DELIVER`：既有 `/deliver` 写操作；实施沿用现有客户端方法、参数与 CAS。
- 取消、回退、续跑的确切路由未给出，复用现有 #124/页面命令，不新造路由。
- 下表 `*` 覆盖所有值；按**上方规则优先**匹配，覆盖六阶段×六状态×三模式，不把无意义组合解释为合法操作。

### 9.2 全局覆盖规则

| 阶段 × status × mode | 主动作／API | 次要动作 | 禁止动作与原因 |
|---|---|---|---|
| `* × running × *` | 「正在检索／准备底图／渲染…」禁用 | 取消、AI 活动 | 所有编辑、确认、生成、交付：避免并发写与身份混乱 |
| `* × failed × *` | 按第 9.4 节 | 同表 | 不忽略失败直接推进 |
| `* × blocked × *` | 「处理阻塞项」→聚焦首个 blocking issue；定位完成且可重试后才显示重试 | 查看现场、允许的回退 | 禁止把 soft geometry 问题伪装成服务端阻塞 |
| `complete × completed × *` | 「查看交付」只读 | 下载、交付历史、既有允许的显式重做入口 | startRun 已拒绝 completed，不直接再跑 |
| `非 complete × completed × *` | 「刷新状态」GET detail | AI 活动 | 状态组合不一致，禁止猜测写操作 |
| `* × idle/awaiting_review × *`，有 CAS 冲突 | 「查看并处理冲突」 | 保留草稿副本、放弃本地草稿 | 保留不等于覆盖服务端；不可复用旧 revision 重试 |
| 同上，有未保存 brief/几何/layer 草稿 | 「保存需求／保存编辑／保存图层」→对应 SAVE | 放弃修改 | 确认、生成、交付禁用 |
| 同上，无上述覆盖条件 | 进入阶段表 | — | — |

主色按钮可以是“定位问题”而非写请求；不能为了保持按钮可点而提供不安全的运行。

### 9.3 阶段 × idle/awaiting_review × mode

`manual/guided/auto` 三列相同处明确合并；mode 不改变人工停靠。

| 服务端阶段 | manual | guided | auto | 自动终点／人工停靠 | 次要动作／禁止动作 |
|---|---|---|---|---|---|
| 需求，subject 缺失 | 补全需求，无 API | 同左 | 同左 | 保存需求后才可检索 | 禁止 run |
| 需求，输入有效 | 一键检索 → SEARCH | 同左 | 同左 | 自动经过资料检索、底图，止于底图完成 | 编辑 brief；禁止自动 drawing |
| 资料检索 | 一键检索／继续检索 → SEARCH，已有进度沿用既有续跑语义 | 同左 | 同左 | 同上 | 清空进度、配置模型收进高级入口 |
| 底图未完成 | 准备底图 → SEARCH，从当前阶段起执行 | 同左 | 同左 | base 完成即停；不重跑已完成 research | 禁止提前确认“底图已就绪” |
| 质感底纹，或作图前；底图已完成、几何未整体确认 | 确认几何 → CONFIRM | 同左 | 同左 | 停留原阶段，不启动 run | 禁止生成和交付 |
| 质感底纹，或作图前；已确认且无草稿 | 渲染成图 → 见下文 | 同左 | 同左 | drawing 最终图产出后停靠 | 更多：回退、模型设置 |
| 作图，已有本轮 final，尚未进入可交付状态 | 准备交付 → 既有 complete 推进入口 | 同左 | 同左 | 完成细节产物，等待交付 | 不自动交付 |
| 完成，细节产物尚未就绪 | 准备交付 → `RUN('manual')` 执行 complete；若现有状态需 advance 则走 ADVANCE | 同左 | 同左 | complete/awaiting_review | 禁止绕过准备步骤交付 |
| 完成，产物齐全且与当前输入一致 | 交付成图 → DELIVER | 同左 | 同左 | 用户显式交付 | 更多：查看图层、下载；过期图禁止交付 |

**渲染入口建议：** 同一个 `stop_at` 参数扩展支持 `'drawing'`，请求 `{mode:'guided', stop_at:'drawing'}`；从 style 起跳过纸纹后运行 drawing，止于 drawing 完成。这样不使用裸 `auto` 意外进入 complete/交付，也不让用户再点击一次“质感底纹”。

这是新增参数的第二个枚举值，不是现有能力。替代方案为 UI 串行执行既有 manual style 和 drawing，但要处理刷新中断，优先采用服务端有界运行。

### 9.4 #124 五种失败分型

| kind | 横幅核心文案 | 唯一主动作 | 次要动作 | 禁止／限制 |
|---|---|---|---|---|
| `steps_exhausted` | 轮次已用尽，本轮未完成交付 | 续跑当前阶段；使用既有续跑能力 | 切模型、查看轮次；research 可清空进度 | 该阶段不支持续跑时明确改为“重试当前阶段”，不假称续接 |
| `ended_without_delivery` | AI 已结束，但未提交有效产物 | 继续完成当前阶段；无续跑能力则重试 | 切模型、查看最后消息、允许的回退 | 预览不能作最终交付 |
| `call_error` | 模型调用失败，已有结果已保留 | 重试当前阶段 | 切模型；配置无效时主动作改“修复模型配置” | 不循环自动重试，不清空有效研究进度 |
| `rejected` | 产物未通过校验 | 查看并处理问题 → 聚焦可编辑字段／几何；修复保存后变为重试 | 查看 problems、回退 | 切模型不能作为跳过校验手段 |
| `mixed` | 本轮存在多类失败 | 查看并处理问题，打开失败现场 | 按现场提供续跑、切模型、清空或回退 | 不擅自选一种失败原因执行恢复 |

失败横幅无写按钮；所有恢复主命令由④承载。research/base 失败恢复仍携带 `stop_at:'base'`，drawing 恢复携带 `stop_at:'drawing'`，避免恢复时丢失停靠边界。

## 10. 「一键检索／调研」停靠契约

### 10.1 请求与状态序列

选择 **`stop_at`**，不使用 `through`：它直接表达“完成该阶段后停止”，避免被理解为“经过该阶段继续跑”。

建议请求：

> `POST /map-studio/tasks/:id/run`  
> `{ mode:'guided', stop_at:'base', expectedRevision:<当前版本> }`

`guided` 是执行策略，不是用户必须切换的第三个开关。新任务偏好仍默认 manual。

| 顺序 | 服务端应写入 | UI |
|---|---|---|
| 1 | 接受请求，保留既有 busy/brief/配置校验；需求若需执行则先执行 | 一键检索按钮转禁用，显示真实阶段 |
| 2 | `stage=research, status=running` | 资料检索 · 进行中；几何更新可只读预览 |
| 3 | research step completed；`stage=base, status=running` | 正在准备底图；不要求中途确认 |
| 4 | base 产物与 bbox 写入；base step completed | 显示底图，编辑器获得 registration |
| 5 | **`stage=style, status=awaiting_review`** | “底图已就绪 · 待复核几何”；唯一主动作确认几何 |
| 6 | 人确认，CAS 写成功；不执行 style/drawing | 主动作变为渲染成图 |
| 7 | 人点击渲染；有界执行 style→drawing | 旧图保留，最终图发布后停靠 |

第 5 步沿用“阶段字段指向下一阶段”的现有 finish 语义，不强行写成 `stage=base` 造成重复执行底图。

### 10.2 base 失败

- base 保持失败或受阻的真实状态；保留已经完成的 research 和研究进度。
- 不自动重试，不自动回退 research。
- ④按 #124 分型显示修复／重试；重试从 base 开始并保留停靠边界。
- 如果错误来自研究范围，用户显式改 brief/bbox 或回退，才触发服务端既有失效逻辑。

### 10.3 mode 与兼容

| 请求形态 | 行为 |
|---|---|
| 旧 `{mode:'manual'}` | 保持原样：只跑一个阶段 |
| 旧 `{mode:'auto'}` | 保持原样：按 proceed 连续推进，可能越过未确认几何 |
| 新 `{mode:'guided', stop_at:'base'}` | 连续执行到 base 完成，必停 |
| 新 `{mode:'guided', stop_at:'drawing'}` | 显式渲染操作执行到 drawing 完成，必停 |
| 新 manual/auto 请求带 `stop_at` | 建议 stop_at 作为更强上限；manual 仍可提前单阶段停止，auto 不得越过边界 |
| guided 未带合法 stop_at | 拒绝并返回可读参数错误，不回退为 auto |

新版一键检索始终发送 guided/base，**不受抽屉保存的 auto 偏好影响**。存量 UI／技能的无参数调用不变；技能简化主题分支时，应同步采用有界检索请求。

### 10.4 V5 订正与结论

**事实：当前服务端没有“未确认几何禁止 drawing”的闸门；旧 auto 可越过未确认几何。**

订正验收：

1. 新版 UI 一键检索，manual/auto 偏好下均实测 base 完成即停。
2. 未点击确认几何时，新版 UI 不发送 drawing 请求。
3. 确认成功只写确认，不启动 drawing；点击渲染才启动。
4. 编辑几何或需求后撤销 UI 整体核对状态，恢复相应停靠。
5. 不把“直接调用旧 auto API 被服务端阻止”列为本 Issue 验收。

**建议：本 Issue 内 UI 人工停靠足够，配合新增服务端 stop_at 实现可靠检索停靠。** 它不是安全边界；若要求所有客户端都不得越过确认，须另开 Issue 修改闸门，不能在本 Issue 偷改精确度口径。

整体核对状态建议绑定本次加载后的几何/brief 来源版本；刷新后无法证明已整体核对时，保守重新要求确认，不新增持久化确认闸门。

1. 先解析、校验 URL，加载 detail，再验证实体归属。

## 14. 本轮遗留与假设

1. **有界运行接口：** 需新增 `guided + stop_at`，建议支持 base/drawing 两个边界；旧 manual/auto 无参数行为保持不变。若只批准 base 枚举，drawing 的 style 跳过须用既有 manual 调用串联，并处理刷新中断。
2. **不可变图片快照：** detail 尚未证明可列出历史 final、draft 的稳定 revision 和同源 layer_doc/semantics。需扩展现有 outputs/run 读取契约；不能只靠内存保留旧 URL。历史缺失时诚实降级，不保证可回看不存在的元数据。
3. **历史失败证据：** `/runs/:id/observed` 是否完整保存历史 error_detail、problems、steps_used 尚未给出；需保证该读取契约满足 V33。没有记录的旧运行显示缺失，不能用新 run 信息补造。
4. **整体确认与 UI 保障：** 假设可复用既有接受几何的写通道；另加本地整体核对状态，不新增服务端闸门。刷新后不能证明确认则重核对。需评审接受“新版 UI 保证、旧 API 不保证”的 V5 订正。
5. **交付准备判定：** complete 的细节渲染与 `/deliver` 的具体调用边界须实施时沿用现有客户端；按钮必须依据真实产物就绪条件，不把所有 `complete/awaiting_review` 直接判成可交付。
6. **历史三政策分别验收：** 新任务固定 atlas-tint、无纸纹、底图缓存；旧任务显式再生成时重建默认要素样式且不用旧 texture；已有历史成图及人工 layer_doc 原样保留。迁移按指定 provenance/run 时序识别，逐条列清单、备份 history snapshot、dry-run→apply，跳过 running；只用复刻样本验证，不重渲真实历史任务。
7. **本 Issue 不只是前端：** 固定样式解析、纯底图成品缓存、texture 迁移、技能主题分支简化均在范围内。缓存完整键包含 bbox、像素尺寸、投影、DEM/NE/OSM manifest、renderer、河豁免集；原子写、sha256 校验、进程内单飞，不能把“生成快”当命中证据。前端仍只用 `/map-studio`，宿主名称/描述只读。
8. **实施验收边界：** #125 先合并、文件不相交；未合入时按缺字段降级。后续实现必须验证 zoom 三级逆换算、把手拖拽／空白平移、类别硬显隐、地点与顶点写入、CAS 回滚、点数反馈、平滑阈值、缓存键、深链零写入及 ≤5s 成图显示；本轮仅为设计，不声称这些行为已经实现或通过验证。
