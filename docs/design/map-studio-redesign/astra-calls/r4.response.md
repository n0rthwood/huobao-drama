## 2. 纸纹残留迁移（V9/V10）

### 2.1 判定与只读清单

候选条件严格为：`outputs.texture_image.provenance.source = 'diffusion-texture'`，且以下至少一项成立：

- **R1 relief-base**：当前有效 `outputs.base_image.provenance.renderer` 含 `relief`。
- **R2 texture-before-base**：texture 所属 run 早于任务最近实际产出 base 的 run。

`run_id` 仅是关联身份，**不假设字符串/整数大小等于先后**。以持久化运行时序或有序历史记录证明先后；失败且未产出 base 的运行不算最近 base。时序缺失且 R1 不成立时标 `undetermined`，不 apply。R1 成立即使 R2 无法判断也仍是候选，报告注明证据不足项。

SQL 层只读投影字段清单（逻辑字段，不指定未经核实的表名）：

`task.id`、`task.title`、`task.status`、`task.revision`、`outputs.texture_image`、`outputs.texture_image.path`、`outputs.texture_image.run_id`、`outputs.texture_image.provenance.source`、`outputs.base_image.run_id`、`outputs.base_image.provenance.renderer`、`runs.id`、`runs.stage`、`runs.started_at`、`runs.completed_at`、`runs.status`、`history.revision`、`history.outputs.base_image.run_id`。

其中 title、运行时间/历史路径为**字段映射假设**：实际存储若不同，由脚本读取适配层投影为以上逻辑列，不为方便迁移新增业务列。无法确定最新 base 时必须记录，不猜。

每行固定输出：`task_id, title, revision, status, texture_path, texture_run_id, latest_base_run_id, base_renderer, reason[], chronology_evidence, skip, skip_reason, texture_before_sha256`。源不匹配和 texture 为 null 的任务计入扫描统计，不作待修改行；running 候选也列出，`skip=true`。

### 2.2 dry-run 报告

拟议命令入口为模块迁移工具 `map-studio texture-migration --dry-run --export <报告目录>`；下例是**格式示例，不是执行输出**：

```text
MODE dry-run   MIGRATION texture-detach-v1   REPORT sample-20261119
TASK  TITLE      TEX_RUN BASE_RUN REASON                ACTION
s-01  样本-relief r010    r011     relief-base           would-detach
s-02  样本-时序   r020    r021     texture-before-base   would-detach
s-03  样本-在飞   r030    r031     relief-base           skip:running
s-04  样本-未知   unknown r041    chronology-unknown    skip:undetermined
scanned=6 candidates=3 would_change=2 skipped_running=1
undetermined=1 no_texture=1 source_not_matching=1 errors=0 writes=0
EXPORT report.json manifest.csv
```

JSON 含报告版本、时间、工具版本、扫描范围、逐行证据与总数；CSV 为同一清单，中文标题按 CSV 规则转义。报告保留路径供运维审计，不直接向普通用户暴露服务端绝对路径。dry-run 不写 DB、不改文件、不创建业务 history。

### 2.3 apply、备份与回滚

1. apply 必须引用已审阅的 dry-run 报告 ID/哈希；不得无条件重新扫描后批量清空。逐任务事务内重新读取 revision、status、纹理原值与判定条件。
2. `status=running` 必须跳过；若任务已变更、报告 revision/原值哈希不匹配，标 `skip:changed-since-report`，要求新 dry-run。不抢正在执行的任务。
3. 同一事务中先追加 history snapshot，再把当前 `outputs.texture_image` 置 null；不触碰图片、layer_doc、历史输出、spec、交付记录。使用现有写锁/CAS 互斥机制，避免检查后 run 启动的竞争。
4. 拟议 history snapshot 结构：`migration {id:'texture-detach-v1', report_id, applied_at, actor, reason[], task_revision_before, task_revision_after, before:{texture_image:<原始完整对象>}, after:{texture_image:null}, before_sha256, after_sha256}`。时间/执行者与普通 history 元数据复用；记录对象必须完整，不只备份 path。
5. 幂等：已为 null 则 `already-detached`；同任务同原字段哈希已有成功迁移记录则不重复备份、不重复递增 revision。失败的事务不得留下“已迁移”记录。
6. 回滚顺序：停止本迁移批次继续 apply → 逐任务检查无 running 且当前仍为该迁移 after 状态/revision → 校验备份完整性及引用文件仍在 → 按该任务迁移逆序恢复 `before.texture_image` 并追加回滚 history → 验证原值哈希。业务 revision 单调递增，不回拨。事务内失败自动撤销；已有后续业务写入则跳过冲突任务，不能覆盖新值。
7. 回滚只恢复引用，不重新启用 drawing 的纸纹消费；恢复历史可追溯性与恢复旧渲染政策是两件事。原纹理文件不在本迁移中清理，便于回滚。

### 2.4 用户可见影响与证据

当前 texture 为 null：显示“纸纹：不使用 / Paper texture: Not used”，不显示损坏缩略图、加载错误或可点击空预览。确有迁移 history 时补“旧纸纹引用已移至历史记录；已生成图片未改变。 / The legacy texture reference is archived; existing images are unchanged.”无迁移记录的新任务不能显示这句。

历史图片含纸纹仍按原图显示；历史 texture 深链可读回历史快照，否则提示“当前任务不再使用纸纹，可查看历史版本。 / Paper texture is no longer used by this task. View a historical version.”只改视图，不恢复字段。

前后证据须同时包含：样本旧纹理输入与截图、新 drawing 不含 texture 的输入/provenance、新截图、相同 bbox/尺寸/base sha、各自 run/revision。允许默认要素样式同时变化，明确指出，不能把全部视觉差异归因于纸纹。原历史图 sha 未变化另列为保留证据。

### 2.5 专用样本矩阵与创建/清理

不重渲真实任务 1 或其他真实历史任务。使用隔离测试数据目录和模块测试任务创建能力，任务标题统一 `[126-texture-sample]`，记录 owner、样本 ID、创建时间。**假设**测试夹具可在隔离 DB 中写入合法旧输出；若无此能力，用测试专用种子工具，不给生产开放伪造入口。

| B | source=diffusion-texture；renderer 不含 relief；texture run 早于最近 base | 由 R2 迁移 |
| C | source=diffusion-texture；renderer 不含 relief；texture run 晚于 base | 不迁移 |

## 3. 底图模板缓存（V25-V27）

### 3.1 范围与完整键

缓存仅承载 `renderReliefBase` 的纯底图，不含任务点线面、标题、标签、pip 细节框、纸纹或 layer_doc。base 阶段其余输出与任务归属不直接复用；特别是 pip/KMZ 依既有流程处理。

**范围假设及取舍**：V25 描述的是 DEM/NE/OSM program 底图。earth/image 不具备同一渲染依赖，不套该键、不改用户 base_mode；显示“当前底图来源不使用模板缓存 / This base source does not use template caching”。若要求这两种来源也缓存，需另定义来源内容指纹，不能在本设计中假装已覆盖。

以下是拟议 cache schema v1。规范化后得到的输入必须同时用于渲染及 registration，不能“键用量化 bbox、渲染用原 bbox”。

| 固定顺序 | 键分量 | 取值、计算与规范化 |
|---:|---|---|
| 1 | `schema_version` | 固定 `1`；序列化/量化规则改变即升级。 |
| 2 | `bbox` | 使用语义/调研最终确定的实际 bbox，顺序 west,south,east,north；每值量化至 1e-7 度，以整数度×10^7 编码，半档远离零，负零归零。只消除浮点尾差，不合并相邻视野。跨日期线沿既有 bbox/投影表示保留展开区间，不擅自排序经度或把 180 转 -180；不支持的 bbox 仍按既有校验报错。 |
| 3 | `width,height` | 实际输出像素宽高，正整数，先宽后高；不使用“横版/竖版/16:9”等画幅标签，同画幅不同像素会改变像素结果与平滑尺度。bbox 描述地理范围，像素尺寸描述栅格采样，两者都必须有，不是用尺寸替代 bbox。 |
| 4 | `projection` | 模块实际投影 ID 加所有影响投影的参数；按属性名排序、单位固定、数值使用明确精度的规范字符串。不得仅凭 UI 标签推断投影。 |
| 5 | `dem_manifest_sha256` | 读取实际使用的 DEM manifest 的既有 sha；小写 64 位 hex。 |
| 6 | `ne_manifest_sha256` | 实际加载的 NE manifest 内容 sha；若内置数据没有独立 manifest，由构建生成数据清单及内容 sha，不用文件 mtime。 |
| 7 | `osm_manifest_sha256` | 实际使用 osm-rivers 或内置 manifest 的内容 sha，并编码来源标识，防止不同回退来源同名。未使用的数据源用显式 `none`，不能拿 `unknown` 当稳定指纹。 |
| 8 | `renderer_version` | 拟议构建注入的 relief renderer 内容版本：由渲染代码及影响像素的依赖、固定色板/配置的构建清单生成 sha；发布产物记录可追溯 commit。开发环境同样生成内容指纹，不用永远不变的 `dev`。 |
| 9 | `river_exemption_fingerprint` | 分别规范 `exemptRivers`、`namedRivers`：使用 renderer 真正匹配的 token/ID，名称 Unicode NFC，去重并按 UTF-8 字节排序，两数组保持分组；固定对象顺序后 SHA-256。不得为“方便命中”无依据地小写/去空格。相同规范化集合必须传给 renderer。 |
| 10 | `atlas_version` | 实际加载 atlas 数据/布局配置的内容版本；若模块并无独立 atlas 版本，显式记录 `none`，相关实际内容仍由上述 manifest/renderer 覆盖。不虚构版本。 |

豁免集必须入键：同 bbox 和数据下，叙事河豁免会改变被画出的河流，因而像素不同。集合为空须编码空数组，不能省略。输入缺可靠指纹时绕过缓存并报告来源不完整，不制造共用 unknown 键；这类环境不能通过缓存上线验收。

1e-7 度是**设计选定精度**，不是现有实现事实；实施须在模块允许的最大尺寸/投影范围验证量化误差小于 0.1px。若不成立，升级 schema 使用更细精度或无损规范数值，不暗中放宽误差或沿用旧键。

### 3.2 序列化、目录与 manifest

顺序固定为上表；使用 UTF-8 紧凑 canonical JSON，无多余空白，嵌套对象按键排序，数组按规定顺序；bbox 为整数，其余数值类型固定。`key=sha256(canonical_key_components)`，小写十六进制。task_id、run_id、标题、生成时间不入键。

```text
DATA_ROOT/map-data/base-cache/<key>/
  manifest.json
  base.png
DATA_ROOT/map-data/base-cache/.tmp-<key>-<unique>/
```

manifest 拟议字段：

- `schema_version,key,key_components`：规范键各分量，含河集合的规范原值与摘要；`source_inputs` 保存生产该缓存时的原始 bbox、投影配置、输入 manifest 指纹来源及 renderer/atlas 版本来源。
- `artifacts[] {path,width,height,sha256}`：path 为缓存目录内相对路径，禁止越界；目前纯底图 `base.png`。不记录任务私有输出路径。
- `registration`：由该规范 bbox、投影和像素尺寸产生，命中时随图一起验证/复用。
- `created_at,renderer_version,atlas_version`：UTC 时间与可追溯版本；重复信息必须与键一致。

命中请求自己的原始 bbox 可能与生产者有微小量化差异；该请求 provenance 另存 requested_bbox/effective_bbox，不把缓存生产者原值伪装成此次输入。

任务 `outputs.base_image` 保持当前 run 身份，拟议新增 `provenance.base_cache {status:'hit'|'miss'|'rebuilt'|'bypass',key,manifest_sha256,artifact_sha256,renderer_version,reason}`。命中时也不能复用旧 task/run_id。manifest 通过模块只读证据接口提供，客户端不直接访问文件系统绝对路径。

### 3.3 完整性、原子发布与单飞

- 读：重算键、校验 manifest 结构/分量/版本，验证图片 sha256、实际宽高与 registration 一致；不只做 exists/mtime 检查。缺文件、校验失败、manifest 不一致均为 miss/rebuilt，不把坏图显示为就绪。
- 写：在相同文件系统独立 tmp 目录完成渲染、sha、manifest；文件完成并关闭后以目录 rename 原子发布。读者只看正式目录；任何半成品不算命中。失败清理自己的 tmp，记录真正失败原因，不写伪成功 manifest。
- 损坏：隔离坏条目、重新生成。显示“模板校验失败，正在重新渲染 / Template verification failed; rendering again”。若重建失败，沿用 base 阶段失败态，不拿坏文件降级成功。
- **进程内单飞**：规范 key 对应一个进行中 promise；首个请求校验/渲染，后续同键请求等待其结果，不再调用 renderer。成功或失败后移除 pending 项；失败传播给所有等待者，下次请求可重新尝试。某任务取消只取消其等待/绑定，不终止其他等待者依赖的共享计算。
- 多进程不承诺只渲染一次；原子发布竞争者必须验证已发布获胜条目后复用，不能覆盖有效目录。若实际部署有多渲染进程且要求全局一次，需另加跨进程锁；不得用进程内单飞日志宣称全局保证。
- 日志最小观测事件：`base_cache.lookup/hit/miss/corrupt/singleflight_join/render_start/publish/error`，携 key、请求 run_id 与 producer 标识；日志在 AI 活动/证据入口，不默认铺主界面。

### 3.4 保留策略与可见语义

v1 **不自动 TTL、不自动容量淘汰**：内容寻址已保证版本失效，TTL 不增加正确性；自动淘汰若删除历史图引用会破坏 V8。取舍是磁盘增长，需要运维按 bytes/条目数观测。缓存命中后把产物复制到任务产物目录，或使用独立生命周期的硬链接，保证删缓存不删历史图；不能把历史输出仅指向可淘汰缓存路径。人工清理仅删除非在写条目，先导出清单；容量自动上限留到有引用保护的 GC 方案后，不在本轮偷加。

底图区域只放一个来源标注；命中对应“模板缓存命中 / Template cache hit”，miss 为“新渲染 / Newly rendered”，损坏恢复为“重新渲染（缓存校验失败） / Re-rendered (cache verification failed)”。等待单飞不能在产物校验前标 hit。tooltip/来源证据可显示 key、manifest、sha；普通标签不显示长 key。

### 3.5 缓存验收断言

| 拟议行为案例 | 必须观察的结果 |
|---|---|
| cache-complete-key-hit | 两次完整规范键相同；第二次 status=hit，manifest 与产物 sha 一致，无第二次 renderer 调用。耗时仅附录。 |
| cache-key-components-invalidate | 单独改变像素尺寸、有效 bbox、投影、DEM/NE/OSM 任一 manifest、renderer、atlas、任一河集合，均不复用旧 key。 |
| cache-normalization | 河集合顺序/重复项不改变规范键；bbox 量化边界两侧使用实际 effective_bbox 验证图与 registration，不只是字符串相等。 |
| cache-corruption-rebuild | 分别损坏图片和 manifest；都触发重建，损坏字节未输出，重建后 sha 可验证。 |
| cache-singleflight | 同进程同键并发，日志仅一个 render_start/publish，其他为 join；失败后无悬挂 pending，再请求可重试。 |
| cache-pure-base | 不同标题/任务要素共用相同完整键，纯底图无这些内容；任务自己的 pip/标题没有被缓存带入。 |

V27 的验收表述统一为“**完整键一致**才命中”，禁止使用“同 bbox + 画幅即可命中”。

## 5. 图层描述查看器契约（V14/V16、Issue 阶段 4）

### 5.1 身份与锚定

查看器输入不是实时任务 semantics，而是**所选图片快照**的 `layer_doc` 与同源 semantics。沿用 01 §6 的 `run_id + revision + artifact kind` 身份；agent 预览与最终图不可混用。

**字段假设**：图层 `semantic_id` 锚定语义条目的 `id`，或者图层 `feature_id` 锚定要素 ID。#125 已知的是 `semantics.points/lines/regions[].description?:string, keywords?:string[]` 及条目级 manual 标记；具体 ID、manual 字段名尚未给出。建立模块内读取适配层 `describeLayer(layer, semantics)`，不要求 #125 为查看器改字段。

适配层文字判定规格：

| 判定顺序 | 行为 |
|---|---|
| 0. 快照一致性 | 图片、layer_doc、semantics 的来源 run/revision 不一致时，拒绝拼接；返回元数据不可用状态，不使用当前 spec 补齐。 |
| 1. 解析显式 semantic_id | 只在同快照中按明确 kind+ID 或全局唯一 ID 查找；找到一条则为锚定要素。 |
| 2. 无 semantic_id，存在 feature_id | 使用 #125 实际定义的关联表/字段映射；有唯一映射才锚定。不是按名称或几何距离猜测。 |
| 3. 两种 ID 冲突或多条匹配 | 标“要素关联不明确 / Feature link is ambiguous”，降级图层摘要；不能任选一条。存在但失效的 semantic_id 不默默改用另一条相似要素。 |
| 4. 无有效锚定 | 返回图层自身 name、类型、几何摘要。 |
| 5. 格式整理 | description 去掉空白后为空视作缺失；keywords 去空、去重，作为文本标签转义；不运行 HTML。manual 从该语义条目读取，不从任务级或相邻图层继承。 |

返回的视图字段建议为 `source, featureId, title, description, keywords, geometrySummary, isManual, warning`，仅是呈现模型，不写回持久化字段。若 #125 命名变化，只改 ID/manual 适配与契约测试，UI 不散布多套字段猜测。

### 5.2 显示优先级与缺失值

| 优先级 | 条件 | 显示 |
|---:|---|---|
| 1 | 唯一锚定且非空 description | 要素 description；非空 keywords 作为补充标签。缺 keywords 不降低 description 优先级。 |
| 2 | 唯一锚定但无 description | 要素 name + 类型 + 几何摘要；keywords 若独立存在仍可显示，但不代替描述、不自动生成文字。 |
| 3 | 无有效锚定 | 图层自身 name + 类型 + 几何摘要。 |

点摘要用该快照坐标；线/面摘要用类型与顶点数（长度/面积只有现成可信计算结果才显示）。无几何显示“几何信息未记录 / Geometry metadata unavailable”；无名称显示“未命名要素 / Unnamed feature”或“未命名图层 / Unnamed layer”。不把缺失值显示为 0 或空白错误框。

| 情况 | 中文 | English |
|---|---|---|
| 多层共用要素 | “关联要素：{name}”；各层显示同一描述，不复制成多份可编辑文本 | “Linked feature: {name}”; same description on each layer |
| 无锚定层 | “未关联要素，显示图层摘要” | “No linked feature; showing layer summary” |
| 锚定存在但缺描述 | “暂无要素描述，显示几何摘要” | “No feature description; showing geometry summary” |
| 条目 manual=true | “人工描述”（附在该条描述来源处） | “Manual description” |
| 仅条目被人工修改但无描述 | “人工条目 · 暂无描述”，不伪称存在人工描述 | “Manual entry · No description” |
| 同 revision 元数据缺失 | “该版本的图层描述未记录” | “Layer descriptions were not recorded for this version” |

### 5.3 集成条件

- #125 未合入：semantics 缺 description/keywords 不报错，按表降级；无语义快照只显示同图 layer_doc 自身摘要。没有 layer_doc 时显示空态，不从当前任务拼旧图描述。
- #125 合入：只要所选快照包含合法新字段，读取适配层自动显示，无需开关/重新保存/重渲。老快照未保存描述不会凭空补出；“自动生效”不意味着回填旧历史。
- 契约验收覆盖 points/lines/regions 各一种、共享要素、无锚定、空字符串、缺 keywords、manual 与冲突 ID；分别用缺字段旧快照和含新字段快照运行同一查看器。
- 合并顺序仍为 #125 先、#126 后；降级是兼容历史数据与独立开发验证，不是绕过合并顺序。

### 5.4 只读与 revision 绑定

查看器永远只读，不提供编辑描述或修改几何入口。当前 spec 已编辑但图未重渲：继续显示所选旧图及其同源描述，并显示“图与当前几何不一致 / Image differs from current geometry”。不能隐藏旧图，也不能把描述替换成新 spec。

从旧快照进入“图层编辑器”的快捷入口禁用，提示“请切换到当前可编辑版本 / Switch to the current editable version”；当前合法编辑入口仍按既有规则和 CAS 工作，不因为查看历史而禁用整个任务。若图和 layer_doc 自身不能证实同源，则不显示可疑几何/描述，提示“图层元数据与图片版本不一致 / Layer metadata does not match the image version”，保留图片查看及切换版本能力。

## 9. 假设与遗留（6 项）

1. **存储映射**：SQL 物理表名、最新 base 时序字段、history snapshot 承载形状尚未提供；按 §2 逻辑投影适配。不能证明时序时保守跳过，不用 run_id 大小猜测。
2. **样式内部 token**：atlas-tint 是确定的家族，`spec.style.theme` 的实际值未知；实施用 resolver 实际返回值确定，不凭观测到的 ink 外推。若 schema 不含双字段，只保留既有权威字段。
3. **缓存范围/版本**：本缓存面向 program relief；earth/image 绕过并明示。NE/atlas 版本与构建指纹注入方式须实施前确定；没有可靠指纹就绕过，不能把绕过当缓存验收通过。
4. **快照能力**：历史 layer_doc/semantics 同图 revision 可读与回退前不可变保存未被事实证明；先补模块内小型读/保存契约，缺失时只读降级、禁用不安全重做。
5. **#125 适配与文件边界**：ID/manual 实际字段及双方文件交集待 #125 最终 diff 确定；只改消费适配层，不猜名称、不跨 Issue 改同一文件。
6. **阶段编号与运行前提**：阶段 1/2 的拆分为建议；guided、缓存、迁移及新测试均尚未实现/执行。本轮只交付设计和验收规格，不宣称真实任务、服务或测试已经验证。
