## 1. 设计原则

1. 主界面同时回答地图身份、所选图片身份、当前状态及唯一下一步动作；日志收进 AI 活动抽屉。
2. 默认空间由阶段驱动：核对阶段③点线面最大，成图复核阶段②图片最大；专注模式只是增强，不是满足编辑面积要求的前提。
3. 默认检索采用 guided/base 并停靠；确认几何与渲染成图分开。确认只写既有要素确认状态，渲染只能由显式动作触发，不由刷新、保存、关闭弹窗或深链恢复触发。高级 auto 须单独警告并启动。
4. 图片、图层文档、语义和来源绑定同一冻结快照；无法证明同源时显示缺失，禁止用当前数据补历史图。
5. **一次保存**：页面持有唯一 `specDraft`；地点行、全部地点弹窗、顶点弹窗只修改该草稿，条目“完成编辑 / Finish editing”仅结束局部事务。“保存几何 / Save geometry”是几何草稿唯一服务端写入口，一次 CAS 提交整份 spec + layer_options；不存在按行提交。
6. **深链零写**：恢复 TAB、zoom、选择、点列表及图片仅改变视图；保存、确认、生成、交付必须来自显式用户命令。关闭子层不触发提交。
7. “即时上图 / Live edit preview”指 SVG 编辑预览，不等于服务端成图重渲。已有 layer_doc 的平滑保存会重渲并自动交付，必须在显式保存前告知，不以“只保存草稿”掩盖副作用（`run.ts:444-449,608-639`）。
8. 不维护浏览器整体复核标记。刷新按已保存要素状态重算：UI 未确认徽标统计 `proposed===true`；服务端 `geometryUnverified` 另有 manual/verified/confirmed 与 dataset_missing 口径，两者不混称（`accuracy.ts:88-95`、`run.ts:500-511`）。

## 2. 注意力预算与视觉层级

以 1440×900 面板为参考。顶栏占视口 6%，动作条占 8%，其余 86% 为内容区。下列比例均为**内容区高度**，各表合计 100%；小窗口允许内部滚动，不压缩输入框、焦点目标或按钮。

**核对阶段：base 就绪、几何待核对、等待启动 drawing。**

| 区域 | 内容区比例 | 默认形态 |
|---|---:|---|
| ①资产信息 | 23% | 需求摘要、只读资产信息、参考缩略；brief 表单收起 |
| ②图片身份 | 22% | 底图／上一版身份摘要、缩略图与“展开大图 / Expand image” |
| ③点线面核对 | 55% | 默认最大区；TAB、画布、当前类列表及编辑工具完整可见 |

**成图复核阶段：drawing 完成、complete 待交付、已完成；drawing 运行时也采用此布局保留上一版。**

| 区域 | 内容区比例 | 默认形态 |
|---|---:|---|
| ①资产信息 | 23% | 摘要；运行中只读 |
| ②当前成图 | 52% | 默认最大区；大图、身份、同源图层查看器 |
| ③点线面核对 | 25% | 可展开条带；显示类别、计数、草稿与不一致提示 |

- 依据完成步骤、当前产物及返回状态切换，不单凭 `stage` 名称猜测。base 完成后进入核对布局；drawing 发布本轮 final 后进入成图复核布局。

### 3.3 编辑器行为边界

**页面唯一草稿与一次保存**

- 地点行、全部地点弹窗、线／面顶点弹窗共享页面 `specDraft`；合法编辑只发 `draftChange`。关闭弹窗不提交、不二次保存；文案为“已加入待保存草稿 / Added to unsaved draft”。
- 页面“保存几何 / Save geometry”是该草稿唯一服务端写入口：`PUT /tasks/:id {map_spec, layer_options, expectedRevision}`，提交当前整份草稿。只改 layer_options 时发送服务端原样 spec；不存在只提交部分脏行。
- 保存前结束或撤销未完成局部事务；点数不足等校验问题必须定位反馈，不能悄悄漏交该条目。成功以服务端规范化 spec、layer_options 及 revision 重建基线，随后才显示“已保存 / Saved”，不得以请求副本充当服务端结果。
- 首次成图前的 layer_options 已有持久化和 drawing 消费通道（`run.ts:440-467`、`drawing.ts:87-95`、`task.vue:963-972`）。已有 layer_doc、spec/brief 未变时，同一保存走重渲并自动交付；提交前显示“此次保存将重渲并交付 / Saving will re-render and deliver”（`run.ts:444-449,608-639`）。这不是自动启动 drawing，也不得伪装成无副作用的草稿保存。

**完成编辑与 TAB 仲裁**

- “完成编辑 / Finish editing”只结束局部绘制事务并合入页面草稿；不 PUT、不确认几何、不启动渲染。已有合法数值修改已进入页面草稿时，不要求再逐行完成才能保存。
- 正在绘制且合法时允许完成；点数不足时禁用并提示“点数不足，无法完成编辑 / Not enough points to finish editing”；无局部变更时不产生写入，提示“没有待完成的编辑 / No edits to finish”。
- 切 TAB 保留页面草稿、各类选择及 zoom/pan。存在未结束绘制时，选择“完成编辑并切换 / Finish editing and switch”“放弃局部改动并切换 / Discard local changes and switch”“留在当前类别 / Stay”；不能隐藏未结束事务继续切类。
- TAB 只画当前类别，其他类不画，底图始终保留。完成编辑 ≠ 保存 ≠ 确认几何；改名本身不转 manual，也不清 proposed（`run.ts:500-511`）。

**冲突、拒绝与结果未知**

| 返回／情况 | 界面与处理 |
|---|---|
| 成功 | 使用服务端规范化返回及 revision 建立新基线，所有共享该草稿的视图同步“已保存 / Saved” |
| 明确校验拒绝 | 显示错误；恢复已保存画布，可保留草稿副本供修复；不得显示保存成功 |
| 409 CAS 冲突 | 读最新 detail；保留／放弃本地冲突副本，保留不等于覆盖；重应用后用最新 revision 显式保存 |
| 断线／超时，结果未知 | 显示“保存结果待确认 / Save result pending confirmation”，暂停确认、渲染和重复保存；先 GET detail，不盲重发 |
| detail 可读且 revision 前进、spec 与 layer_options 内容匹配 | 视为已保存，采用该 detail 规范化内容及 revision；若该保存有交付副作用，仍按交付结果核实，不只凭几何匹配宣称交付 |
| detail 不匹配或 revision 未前进 | 不能断言旧请求未落盘；转冲突副本流程，继续按最新事实处理，不自动重放旧请求 |
| detail 仍不可读 | 保持待确认与草稿，提供只读“重新读取 / Read again” |

冲突副本沿用既有 5d 保留口径，不新增草稿管理子系统。

**坐标与输入契约**

无 registration 仅允许数值编辑：“缺少地理配准，无法在图上拖动 / Dragging is unavailable without georeferencing”。03 必须覆盖指针→viewBox→registration 反投影，复用 meet 信箱边距处理并正确消除 zoom/pan，不重复扣边距。把手拖动改几何，空白底图拖动改视口；鼠标、触摸、笔同口径。纯 zoom/pan 不发 `draftChange`、PUT 或几何 revision 变更。

### 6.1 建议结构

图片引用不是完整快照。最低契约必须绑定图片内容、实际生产 run、生产输入、同源 layer_doc、layer_options、语义及来源；不以最新 task revision 冒充图片 revision。

| 现有字段／存储 | 需新增字段／读取契约 |
|---|---|
| `final_image{path,width,height,source,run_id,provenance}`（`types.ts:215-226`） | `snapshot_id`：不可变标识；`revision`：该产物发布版本；`sha256`：实际图片字节摘要 |
| `outputs.layer_doc`、`outputs.layer_options`（`types.ts:229-240`） | 快照绑定的 layer_doc 与 layer_options；`layer_options_revision` 表示生产使用的配置版本，不随普通 detail 变化 |
| `texture_image{path}` 可进入交付载荷（`delivery.ts:59`） | 同快照纸纹事实三态及证据；字段未记录不解释为无纸纹 |
| history snapshot 的 `stage/brief/map_spec/outputs/research`（`types.ts:242-258`） | `semantics_ref`：冻结语义与来源的读取引用；输入 spec/brief 的冻结值或内容指纹关系 |
| 当前 outputs 与历史 snapshot.outputs | detail 暴露快照清单及按 `snapshot_id` 读取同源载荷的契约；具体保存方案须在 G2 选定后固定 |

最低关系：

- `snapshot_id → {image sha256, revision, run_id, inputs, layer_doc, layer_options_revision, semantics_ref, sources}`；一个引用只指向该图片的冻结数据。没有 run 的人工产物不填当前活动 run 冒充。
- `revision` 为图片／快照发布身份，`expectedRevision` 为任务并发控制版本，二者用途不同。
- `artifact_kind=base|draft|final` 为读取投影分类；“本轮／上一版／已交付”是展示身份，不改变快照。draft 只能在取得可读取产物与身份后加入清单。
- 新产物缺同源元数据属于 G2/G4 未通过，不能以“暂无描述”的诚实降级替代验收；旧产物确实无记录时显示缺失，不伪造。

**保存归属与读取边界**

history 只有最近 30 条，且只有 `snapshot:true` 的动作捕获快照（`store.ts:51,364-372,400-420`）。模块交付日志只有 `final_sha256+result`，没有完整载荷；宿主版本 params 有完整输入，但模块不能直读宿主库（`db.ts:68-77`、`store.ts:551-567`、`map-studio-host.ts:37-46`）。

G2 封闭前必须选定以下一条并贯通所有生命周期事件：

1. **模块自存快照**：在模块现有持久化边界内保存不可变载荷及引用，由模块 detail／快照读取契约返回；不能把 30 条 history 当永久保留。
2. **宿主只读投影**：宿主对版本 params 提供只读投影，模块 API 转出；尚未交付的 drawing、draft 和清除前产物仍须有模块侧保留，不能等待交付后才补存。

两者不新增版本管理、来源管理或 GC 子系统。

**快照生命周期**

| 事件 | 保存方 | 发布边界：保存什么、何时可切换 | 读取入口 | 现状态 |
|---|---|---|---|---|

每一行都必须可验证“清除或发布后仍能读到旧图的原数据”；仅保留旧文件 URL 不满足快照保留。

### 6.5 立即显示与收尾

V15 从**对应产物落盘**计时，到浏览器实际加载并呈现该产物，要求 ≤5s。detail 发布、轮询等待及图片加载全部计入；不能从 detail 可读重新计时，也不能用“每 3s 轮询”推定达标。

### 9.3 阶段 × idle/awaiting_review × mode

以下为默认 UI 主动作；读取到旧 run 的 mode 不会把主按钮变成 auto。auto 只从 §8.3 明确启动。所有写操作使用最新 expectedRevision；运行中只读与取消规则优先。

|---|---|---|---|
| brief，subject 缺失 | 补全需求 / Complete requirements | 保存后重新分派 | 禁止 run |
| brief/research，输入有效 | 一键检索／继续检索 → guided/base | base 完成即停，`style/awaiting_review` | research 进度按既有续跑保留；不自动 drawing |

| `complete · idle`，取消后尚未完成交付 | 交付成图 → `/advance`，重新校验前置 | 重新执行 complete | 不因取消前曾有请求就标已交付 |

| `steps[].status=pending` | 不产生独立主动作 | pending 仅表示步骤待执行，不等于 workflow status | 不显示为可操作停靠，按真实 stage/status 分派 |
| `status=failed`，有待修复问题或草稿 | 修复 → 保存 → 重试，逐次只有一个主动作 | 保存后按返回阶段重新判断，再显式重试 | 禁止跳过脏草稿直接重试 |

`drawing · completed` 指 drawing step 的完成事实；若原始 workflow 仍是 `stage=drawing,status=completed`，先 GET detail 核对，不向错误阶段直接发送 advance。真实引擎完成 drawing 会进入 complete（`run.ts:191-199`）。

**style 的 guided 可达性：** guided/drawing 只从 style/drawing 启动；从 style 启动自动跳过出图，写 `texture_image=null`，随后进入 drawing；style 不单独停靠。guided/base 在 base 完成即结束，永不执行 style。现有 style 行为见 `run.ts:244`；有界执行为新增设计。

**能力与恢复：** detail 以 `run_stop_at: string[]` 暴露两个终点；缺失仅按显式分步 manual，不试探 guided，不自动串发。失败续跑保留原合法运行边界；原边界未知时先明确新的用户命令，不猜测 auto。编辑／回退改变阶段后重新判定边界。

**失败事实：** 普通错误也会写 failed，但 error_detail 只在特定耗尽错误写入，故 null 不能解释为没有失败（`run.ts:305-329`）。主动作修复、保存和重试的优先级同样适用于 §9.4 各 kind。

**交付事实：** complete 已含 pip 渲染和交付；`/deliver` 只重试／补交付，不是准备步骤（`run.ts:264-275`、`routes.ts:141-148`）。

| 项目 | 契约 |
|---|---|
| 前置 | `stage=complete`、非 running、最新 revision、无待保存草稿／冲突；mapSpec、base、final、layer_doc 齐全；图与当前输入一致，平滑和标注校验通过；宿主交付还要求宿主目标存在 |
| 构建校验 | 缺 final/base/layer_doc/spec 为 missing_drawing；平滑／标注问题为 drawing_invalid；读取文件计算 final sha（`delivery.ts:15-67`） |

**失败、取消与重试**

- `buildDeliverable` 校验失败时 complete 回退 drawing（`run.ts:272`）；显示修复问题 → 保存 → 显式重试，不能显示已交付。
- 宿主交付失败且现有产物齐全、仍为 complete、非 running 时，可显式 `POST /deliver` 重试／补交付。它不重渲 pip；若 pip 缺失、失效或尚未执行，应重新执行 complete `/advance`（`routes.ts:141-148`）。
- 请求结果未知时先读取 detail／deliveries，不能把客户端超时当作未交付；核实 version_ids 后更新显示，仍不明确时保留“交付结果待确认 / Delivery result pending confirmation”。幂等是安全保障，不是盲重发理由。
- 普通错误为 failed，error_detail 可以为 null；Stale/Conflict 只结束 run、不改任务状态，需重读而非臆造失败类型（`run.ts:305-329`）。
- 失败、真实受阻、取消确认、proceed=false 或指定终点成功，任一先发生即停止。重试／续跑保留原合法 mode/stop_at；编辑改变阶段后重新分派，不自动切 auto。
- 取消先显示“正在取消… / Cancelling…”。确认后结束活动 run，running step→pending、run_id=null、status=idle（已 completed 保持）；**取消确认后不启动下一阶段**，已产物不声称回滚（`run.ts:586-604`）。
- `409 workflow_busy` 只刷新活动 run；revision 冲突进入冲突处理。刷新、返回页面、恢复深链均不补发运行或交付。

**确认与渲染（V5/M1）——保证范围：**

**确认生命周期**

- 要素确认复用既有 PUT 清 proposed。坐标变化的 manual/confirmed 行为及只改名称不确认均按服务端事实呈现（`run.ts:500-511`）。
- 刷新后从服务端重建草稿和计数，不要求重做不存在的整体确认。UI 徽标计 `proposed===true`；服务端 geometryUnverified 有不同条件，dataset_missing 始终计入核验提示（`accuracy.ts:88-95`）。
- 页面草稿未保存、冲突或结果未知时，先处理保存；确认不会捎带运行。保存后根据新的服务端要素状态决定是否需要确认，再等独立渲染点击。
- 没有待确认字段时不制造空 PUT，也不凭浏览器内存宣称“整体已核对”；仍必须由用户点击渲染才启动 drawing。

**验收方式**

| 场景 | 必须观察的请求与结果 |
|---|---|
| 默认一键检索 | guided/base 请求；research 自动接 base，base 完成即停止，后续无 style/drawing/complete 执行 |

| 独立确认 | PUT 只保存确认状态；轨迹中没有连带 run/advance/deliver |
| 显式渲染 | 点击渲染后才发 guided/drawing；到 `complete/awaiting_review` 停，不执行 complete |
| 刷新与编辑 | 计数与服务端一致；改名不假称确认，保存结果未知先读 detail；不依赖浏览器整体标记 |
