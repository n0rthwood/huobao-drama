# Issue #126 修订 v2（按 Fabel one-shot review 意见 + 补充核实；本评论为阶段 0 设计的约束输入）

评审：Fabel（anthropic/claude-fable-5:max，issuecomment-7006330863）。逐条落实如下；「需核实」项已核实的给出证据。

## 一、P1 工作流闭环（阶段 0 状态表的强制内容）

核实的服务端事实：
- manual 模式每阶段完成后 `status=awaiting_review` 停靠，人点「继续」才推进（run.ts finish()）；auto 模式连续推进到 complete 交付。研究要素确认是独立闸门（pending 几何必须人工确认或改人工，validate.ts），**auto 也不越过未确认几何**。
- 「完成编辑」（commitDraft）只是结束局部草稿写回 spec，不等于确认几何；确认走 PUT map_spec 的 proposed 清除（accept）与研究面板确认按钮。
- 编辑几何后：saveMapWorkflowDraft 对 changed 要素转 manual+confirmed；底图/成图失效口径既有（layer_options 变化清 final_image，run.ts:466；extent 变化回 base）。

阶段 0 设计必须产出「服务端阶段 × 运行状态 × manual/auto」状态表，逐项写清：
1. **一键「检索/调研」= 推进到 base 就绪即停靠**（research→base 自动衔接，base 完成即停，无论 auto/manual；drawing 必须等人核对几何后显式触发）。这是用户工作流「AI 填上 → 底图就绪 → 人核对 → 渲染」的落点；auto 模式保留为高级选项（AI 活动抽屉内），默认 manual。
2. 每个人工停靠点（几何确认、底图就绪、成图待交付）在动作条上是唯一主动作；进行中/失败/回退状态的动作与 #124 分型横幅一致。
3. 「完成编辑」与「确认几何」语义分离并在文案上区分；编辑后失效关系（成图标过期、底图是否重取）按服务端既有口径呈现。
验收：一键调研实测推进到 base 停靠（任务状态 + 截图），未确认几何不得进入 drawing（服务端闸门已有，UI 不得绕过）。

## 二、P1 历史兼容三政策分离（阶段 3 修正）

用户原话「底图和纸纹用不着每次都生成，做成模板调用」+「主题没用就别放，都按默认」。**取舍记录：纸纹自 #107 起新底图不再需要（高程晕渲自带质感）；「模板调用」= 复用渲染成品缓存，不新建模板管理系统；旧纸纹残留清除属于修复不一致，不是取消用户仍想要的效果。** 三政策：
1. **新任务**：默认主题（atlas-tint），无纸纹，底图走缓存。
2. **旧任务再次生成**：要素样式按默认主题重建（drawing 阶段本就重建样式，drawing.ts:117/242/258 由 resolveMapStyle 驱动——已核实固定解析器即改变重建结果）；旧 `texture_image` 不再参与合成。
3. **已有历史成图与人工编辑样式**：已交付版本与人工 PUT 的 layer_doc **原样保留**，不重渲不改写；只有用户显式重做时才按新政策。
- 残留识别：`outputs.texture_image.provenance.source='diffusion-texture'` 且任务 base 为 #107 后 renderer（provenance.renderer 含 relief）或 texture run_id 早于任务最近 base run——迁移脚本逐条列清单，备份原字段到 history snapshot，dry-run 后 apply，在飞任务（status running）跳过。
- 历史兼容验收用专用样本任务（新建测试任务复刻旧状态），不重渲真实历史任务。

## 三、P1 编辑器两处需求差异（修正，不再是设计自由项）

1. **地点 TAB = 完整编辑能力**：列表逐条名称/经度/纬度输入 + 删除 + 保存即时上图（现有地点行已有数字输入，保留并纳入 TAB 大组件）；另提供「全部地点」弹窗批量查看/编辑（与线/面顶点弹窗同构）。验收分别覆盖地点列表写入与线/面顶点写入。
2. **类别显隐 = 硬规则**：当前 TAB 只画当前类要素，其余类**不画**（底图保留）；切换 TAB 即切换显隐。阶段 0 不得弱化。

## 四、P2 成图快照身份（阶段 1/4 修正）

核实：drawing 阶段 `render_draft` 工具已产出预览成图路径（drawing.ts:321-322，与最终渲染同链）；`outputs.final_image` 带 run_id/provenance；交付版本 = sys_task id。
- 主成图视图数据源优先级：本轮 render_draft/final_image（带 run_id + revision）> 上一次成功图（明确标「上一版」）> 空态。生成中保留旧图必须标「上一版 · 正在渲染新版」。
- 图层查看器读取**与所选图片同一 revision** 的 layer_doc/语义（成图 provenance 记录来源；spec 已编辑而图未重渲时标「图与当前几何不一致」）。
- 「立即显示」定义：产物落盘后前端轮询任务详情（既有 detail 刷新通道）≤5s 内呈现，验收测刷新延迟。
- 图层描述对应规则：锚定层 → 其 semantic_id 的要素 description（#125 契约：`semantics.points/lines/regions[].description?: string, keywords?: string[]`，条目级 manual 标记）；多层共用要素 = 各自显示同一描述；无锚定层显示图层自身 name/类型/几何摘要；缺字段降级为几何摘要，不报错。#125 未合入时本 Issue 的查看器先按缺字段降级运行，合入后自动生效（集成条件写明）。

## 五、P2 编辑通道约束（纳入交互状态表与行为验收）

- zoom/pan 后的指针→viewBox→registration 反投影三级换算（现有 eventGeo 已处理 meet 信箱边距，zoom 在其外层加变换，行为测试覆盖「缩放后拖点落预期坐标」「纯 zoom/pan 零几何写入」）。
- 顶点拖拽（pointerdown 命中把手）与空白平移（命中底图）按命中目标区分；触摸/笔同口径。

### 二、详细意见

#### [P1] V5 保证范围与确认状态必须分开裁定

**指向：**README「关键设计裁定／v2 约束覆盖」；01 §8.3、§10.1–§10.4；02 §3.1、§7、§8.1；05 V5/G5；v2 第一节。

**问题：**将服务端禁止进入改为默认 UI 不自动进入，是保证范围变更，不是单纯事实订正。`facts.md` 及相关引文所指向的代码事实仍需核实，不能据此直接获得用户授权。`reviewedInputKey` 又把正式渲染条件绑定到不可恢复的浏览器状态，与刷新恢复及部分动作表不一致。

**修改要求：**在 README、01 §10.4、05 V5/G5 分列原要求、需核实事实、实际保证和不保证范围，裁定前标为“冲突待决”。02 §3.1 优先取消未经确认的独立整体复核门槛；若保留，明确其持久化或经认可的窗口级生命周期，并同步动作表。01 §8.3、§10 将高级 auto 定义为明确启动命令，按最终裁定说明是否越过核对及是否涉及交付，不用“不自动确认”替代风险说明。

#### [P1] 地点与弹窗保存必须一次完成持久化闭环

**指向：**01 §1.5、§3.3、§12；02 §4.1–§4.3、§6；03 §5、§10；用户目标 6b；V11、v2 第五节。

**问题：**“保存到草稿→页面保存修改”把用户要求的一次保存改成了两次提交，不能以组件不直接 PUT 为理由认定满足。多脏条目又同时出现“保存全部”和“A 保存、B 仍脏”两种契约。03 的通用失败分支还未明确排除断线、超时这种结果未知情况，相关服务端保存行为需核实。

**修改要求：**02 §4、03 §5 明确地点行和点列表弹窗的保存由页面统一执行 CAS，成功以权威响应为准，无隐含第二次保存。02 §6 选定提交粒度，规定请求如何排除未提交条目、成功后如何更新其基线。条目“完成编辑”仍可仅结束局部事务，不承担保存全部的仲裁；03 §10 明确引用结果未知处理，禁止立即断言未落盘或盲重发。

#### [P1] 同图快照必须补齐保存生命周期，不能只设计读取适配层

**指向：**01 §6–§7、§14.2；02 §3.3、§8.2；04 §1.3、§2.3–§2.4、§5；05 G2/G4；V8/V9/V13–V16/V30。

**问题：**同 revision 展示要求已经明确，但图片如何稳定找到生产输入、图层、语义和纹理来源尚未闭合。#125 的可选描述字段不自动承担快照保存责任，现有 history/provenance 是否足够需核实。旧历史缺数据可以诚实降级，新产物不能以同样空态通过验收。

**修改要求：**在 04 §5 增加快照生命周期表，覆盖产物发布、人工图层保存、清除或覆盖输出、回退和迁移，并明确保存方、发布边界及读取入口。01 §6 收敛各 revision 字段关系，定义新 draft/final 的最低完整契约。把真实 #125 生产链生成图片后读取冻结描述、修改当前 spec 不改变旧图描述，以及迁移/重做后原图、人工文档和纹理来源仍可追溯列为门禁；能力不足时不得执行使来源不可恢复的操作。

#### [P1] drawing 后交付路径及状态分派仍不确定

**指向：**01 §9–§10、§14.5；02 §1–§2、§6–§8、§10.2；05 V1/V3/G3；v2 第一节及完整流程验收。

**问题：**drawing 停靠后仍可能落到“交付准备接口尚未确认”，安全禁用不是完整交付路径。complete、advance、deliver 的前置、返回和副作用需核实。状态表还存在 style/guided 可达性矛盾、workflow/step 的 pending 混用，以及取消、`proceed=false`、未知失败分型的动作缺口。01 中失败优先于草稿/冲突的匹配规则，也未闭合失败后修复保存再重试的路径。

**修改要求：**02 §1.3、§10.2 补请求—前置—输出—副作用表，确定 drawing 后唯一合法路径及交付成功判据，必要时同步 01 §6 的图片来源规则。02 §1–§2 用可因子化表覆盖每个 stage×workflow status，并区分 manual、auto、guided/base、guided/drawing 的可达性和终点。01 §9、02 §6–§7 明确修复、保存、冲突处理、重试的唯一优先级，续跑保留真实 mode/stop_at 边界，取消后不得隐式启动下一阶段。

#### [P1] 核对阶段默认编辑空间必须大于重复底图展示

**指向：**01 §1.2、§2、§4.2；03 §1.1；用户目标 1、6b；V11/V12 对应编辑器要求。

**问题：**01 的核对状态给②约 432px、③约 270px，还重复展示底图，默认注意力与当前任务相反。“放大编辑”入口不能替代用户要求的大组件，也不能证明普通布局已经放出更多信息。

**修改要求：**01 §2、§4.2 改为阶段驱动的默认空间分配：核对阶段③最大，成图复核阶段②最大。03 §1.1 明确普通布局可见的字段和操作，专注模式只作为增强，不作为满足基本面积要求的前提。

#### [P2] 首次平滑保存与编辑失效矩阵必须闭合

**指向：**02 §3.1、§5；03 §2.1、§5.2、§7、§10.2.1；用户目标 6a/6b；v2 第五、六节、V22。

**问题：**首次成图前没有 `layer_doc` 时，平滑值如何保存并被 drawing 消费仍需核实。新增/删除整个要素、仅改名称、纯确认的失效后果及 `layer_options` 引用处理未完整定义，转人工和待核对计数还使用了不同表述。建议值返回 0 也不能作为“已证明 0.05 超限或不存在非零解”的证据。

**修改要求：**03 §10.2.1 明确首次成图前的真实持久化与消费契约；02 §5 补齐编辑类型、转人工边界及产物失效行，并统一已核实的未确认口径。03 §7 保留返回 0 时关闭平滑的动作，但限制无解断言；验收覆盖多段建议、复算结果与刷新恢复。

#### [P2] 迁移幂等必须区分有效迁移与已回滚迁移

**指向：**04 §2.3、§8.1–§8.2；05 G8；V9/V10。

**问题：**按现有文字，“同任务同原字段哈希已有成功记录即跳过”会阻止回滚后再次 apply。跳过 running 也不能单独证明迁移与新 run 启动不存在竞争，共用互斥/CAS 及备份与清空的原子性均需核实。

**修改要求：**04 §2.3 将幂等判定改为有效迁移状态，明确回滚后重新 apply 的关联记录及单调 revision。加入 `apply→rollback→新 dry-run→apply`、重复 apply、重复 rollback 的断言。04 §8 将生产 apply 与工具交付分开，放在快照保留、新合成链及回滚样本通过之后，并明确并发保护前提。

#### [P2] 顶点行深链必须绑定版本，不能只依赖行号有效

**指向：**03 §5.3、§11.2、§12.5；05 V32/G9；v2 第九节及正文深链验收。

**问题：**顶点插删后，同一行号可能仍合法却已指向另一个顶点，仅检查“行不存在”无法兑现失效回退。刷新、新标签、关闭子层回父级的证据也不能被“零写、失效回退”两项概括。

**修改要求：**03 §11.2 给行定位绑定可读取的几何版本或 revision，不匹配时退到要素级并提示，不新增稳定顶点 ID。05 V32 分别映射刷新、新标签、关闭子层、失效实体和越界 zoom，并断言恢复不触发保存、生成、确认或交付。

#### [P2] 触摸、笔和键盘必须具有完整的非 hover 编辑路径

**指向：**03 §3.2、§3.4、§5.3、§9、§11.1；用户目标 6a/6b；v2 第五、九节。

**问题：**“触摸/笔同口径”和“键盘全功能”仍有原则声明多于操作路径的部分。选边插点、新建线面、追加到最低点数、重叠候选消歧和纯键盘平移尚未逐项闭合，点列表不能替代尚未完成的新形状创建。

**修改要求：**03 §9 定义上述动作的非 hover 入口及焦点返回，保留不做双指缩放的取舍时仍须保证触摸可完成缩放和编辑。03 §11.1 拆分键盘、触摸/笔场景，并补第二触点、pointercancel、Esc、未越阈值及拖回原坐标的零提交断言。

#### [P2] 资产、描述和来源展示必须使用明确的生产者契约

**指向：**01 §7.2–§7.4；04 §5.1–§5.2、§6.1–§6.3；05 G4；用户目标 1、3；V16/V29/V30。

**问题：**只读权限明确不等于宿主描述和参考图已经可读，模块 API 是否提供投影需核实，不能用 brief 备注替代宿主描述。#125 条目级 manual 是否表示描述文本为人工来源也需核实。缺描述降级还遗漏了用户要求的来源，图片 revision 不能替代数据或研究来源。

**修改要求：**04 §6 增加展示项—宿主/brief 来源—模块 API 字段—缺失状态映射，不新增宿主写权限或跨模块直读。01 §7、04 §5 明确类别/ID 关联、manual 和来源字段及快照归属；不能证明描述来源时显示“人工条目”而非“人工描述”，禁止按名称模糊关联或用当前语义补历史图。

#### [P2] 缓存 canonical 规则和失败结果需要可执行边界

**指向：**04 §3.1–§3.5；V25–V27、v2 第七节。

**问题：**“无损、确定性、canonical JSON”尚不足以唯一指导数值序列化，投影参数的“明确精度”也可能被实施为舍入。河流集合/NFC 规范化是否等价于既有匹配语义，以及 manifest、回退来源、renderer 指纹是否覆盖实际像素输入，均需核实。缓存写入或发布竞争失败时的任务结果尚未完整定义。

**修改要求：**04 §3.1–§3.2 指定与实际数值模型兼容的规则及等价表示、相邻数值、零的例子，不新增 bbox 或投影舍入。未经核实不借缓存改变河流匹配语义，并逐项登记实际像素输入。§3.3–§3.5 定义读写/发布失败的任务状态与 `base_cache.status/reason`，不得伪报 hit；保留原子写入、sha256、进程内单飞，命中以键、manifest、sha 为证，不以耗时替代。

#### [P2] 所选历史图事实与下一次生成政策必须分开

**指向：**04 §1.1–§1.3、§2.4、§4.1、§6.2；用户目标 3、5；V7/V8/V13/V14/V28/V29。

**问题：**当前 `texture_image=null` 不能证明所选历史图片未叠纸纹，统一显示“纸纹：不使用”会再次制造图文矛盾。固定默认解析政策也不等于遗留主题字段已失去其他副作用，旧客户端提交后是否改写或触发失效需核实。打开历史任务不重建、人工文档原样保留是已确认政策，不能为统一观感改为自动重渲。

**修改要求：**04 §2.4 分别展示“所选图片使用旧纸纹／未使用／未记录”和“再次生成不使用纸纹”，绑定各自数据源；§1 补历史图提示及合法显式重做入口。§4.1、§6.2 定义创建、更新、模块设置请求中遗留主题字段的处理，避免无效主题差异单独触发重建，同时保留 v2 要求的历史字段与 `GET /styles`。

#### [P2] 验收映射必须区分索引、依赖和批准状态

**指向：**README「v2 约束覆盖／实施前置」；04 §7–§9；05 §1–§4、G1–G9；v2 第九节、V32–V34。

**问题：**“34 条都有落点”只能证明存在索引，不能证明政策冲突和关键契约已经闭合。04 的跨文档引用也不能代替与 05 逐项对齐，六项假设不能无标识地替换 G1–G9。行为表虽已有可观察断言，但有界运行、结果未知、首次平滑保存及版本失效等关键路径仍有缺口。

**修改要求：**README、05 将每项标为设计闭合、依赖待核实或政策待批准，并保留 G 编号及对应阻断条件。04 §7 与 05 同步补有界终点及取消/续跑、坐标 fixture 的经纬度 oracle 和误差界、指针取消零写、首次平滑保存、超时结果未知、跨版本深链、真实 #125 冻结描述、失败 run 完整回看及迁移/缓存场景。≤5s 显示延迟必须保留为实测断言，不能由轮询周期推定通过，所有测试表继续标明尚未执行。

**[P3] 合并删减项：**① 03 §8 的来源 popover、复制、额外来源深链若无明确验收收益，退回解释性 tooltip，若保留操作则明确命名“查看来源”；② 03 §11.2 的布局、滚动、筛选等附加深链可减，不能删除必需的 TAB、zoom、选择和点列表恢复；③ 04 §3 的 `atlas_version` 仅在对应独立像素输入时保留，“缓存淘汰必然破坏历史”的理由应与任务产物独立保留政策一致，不因此新增 GC 系统；④ 01 §12 删除与跨 TAB 完成/放弃/留在当前类仲裁冲突的“暂停绘制草稿”说明；**修改要求：**以上只做范围收敛和内部一致性修正，不新增来源管理、版本管理或缓存治理子系统。

- **M1｜README「关键设计裁定」、01 §8.3/§10、02 §3.1/§8.1、05 V5/G5：**分开服务端事实核实与用户保证范围裁定，统一整体复核生命周期和 auto 启动语义，未裁定前不得将 V5 标为已覆盖。

- **M5｜01 §9、02 §1–§2/§6–§8、05 V1/V3：**补全状态组合与唯一主动作分派，修正 style/guided 和 pending 矛盾，并覆盖失败后修复保存、冲突、取消、未知失败及保留原运行边界的续跑。
- **M6｜01 §2/§4.2、03 §1.1、05 用户目标映射：**改为核对阶段③最大、成图复核阶段②最大的默认布局，并明确普通编辑布局可见的信息与操作。

- **M8｜04 §2.3/§8.1–§8.2、05 G8：**用有效迁移状态定义幂等与回滚后再 apply，补齐并发保护前提及重复转换验收，并将生产 apply 放在快照保留和回滚样本通过之后。
- **M9｜03 §5.3/§11.2/§12.5、05 V32/G9：**为顶点行深链绑定版本并规定不匹配时退到要素级，逐项补刷新、新标签、关闭子层、失效目标和恢复零写入断言。
- **M10｜03 §3/§5.3/§9/§11.1：**补齐触摸、笔和键盘的选边、插点、新建与追加顶点、候选消歧、视图移动及焦点返回路径，并覆盖取消和无实际变更时的零提交。
