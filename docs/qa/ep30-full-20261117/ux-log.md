### 画中画回归与修复（并发重填导致）

- 并发会话重绘 prop 259 后重填 ep 30 设计卡，#66/#91 的库楚肖像 image 层被丢掉，但旧图层段仍渲染该插图——且因锚点只存 asset_id=75（无 kind），下游把角色 75（库楚）误标成道具 75（洛色林扎仓，drama 7）。图正确（src.path 是库楚肖像）、名错误。
- 根因修复（#110，commit 06775c42）：LayerAnchor 增 asset_kind；草稿 image 层 src/anchor 都带 kind；buildSegmentDraft 按 anchor.asset_kind 精确收集资产；前端类型同步。回归测试覆盖撞号解析。
- 数据修复：#66 移除越界喀什里克 marker（p_93804782 不在细节1取景框，在细节4），恢复库楚肖像画中画；#91 额尔齐斯河旧 id r_d21b8a8d 改锚当前河道 r_66f405aa（含 __2），恢复库楚肖像画中画。两镜重新草稿/渲染/确认设计卡/确认关键帧，衔接帧 hash 更新；#66 冻结旧衔接帧的排队视频任务 4748 已取消重提。
- UX 发现：设计卡编辑器里连续点「添加图层 + 改类型 + 选画中画」时，懒重渲染会让 @eN ref 错位，UI 点击把图层类型/锚点写串（polyline 锚到库楚语义、image 层空锚点）。改用 API PUT 整卡修复。建议：图层行编辑用稳定 key（图层 id）而非 index，避免重排后 ref 失效。
