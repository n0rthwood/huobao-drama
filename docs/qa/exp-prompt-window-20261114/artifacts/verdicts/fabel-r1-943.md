## 逐份意见

**X**

优点：
- 关键帧两条（mid/last）机位、景别、光线、构图、四肢状态齐全（「骑者各自端坐马背、双手握着缰绳搁在鞍前，双腿垂在马腹两侧、双脚踩在马镫上」），自足可独立出图；附图 3/4 证实同款提示词确实渲出了「对岸右缘骑队 + 多柱细烟」与「空营 + 残烟」的目标画面，且与设计卡 gen_plan 的 mid/last 逐点对应（ipm0「撤离—空营」完整落地）。
- C 衔接规则执行到位：first 留空；第一段 0–1 秒逐项复述 caption（米黄底色、两块红褐多边形、左下角外侧白色小圆点，与附图 1 完全吻合），无人、无 @ 角色、段内无切镜，「切到 @乌格拉河畔」从 1 秒段才出现。
- **mid_frame_time 对齐是 X 的决定性优点**：存在以 5.5 秒为起点的分段，且该段开头「队伍成一列纵队……队尾几骑在草地起伏处半隐」与 mid_frame_prompt 原文同句，引导帧注入点与文字画面一致；全片保持同一远景固定机位家族，撤离→隐没→空营的弧线单调递进，即使被实际 6.58 秒视频截断也能平滑降级。

硬伤：
- **时间轴总长违规（与 Y 共享）**：规则明言「总时长以提交时长为准」，提交时长 = gen_s = 5.5 秒，X 却写到「8.5-11秒」，把成片 11 秒当成了模型视频时长；且「1-5.5秒」单段 4.5 秒超过 ~3 秒分段口径。
- 小毛病：首段「镜头静止极缓推近」把「静止**或**极缓推」两个选项叠在一起写，自相矛盾；8.5 秒处的「切到」实为同机位延续，宜写「仍取」。

**Y**

优点：
- 关键帧提示词、信息头、0–1 秒衔接复述段与 X 逐字相同，同样高质量；首段「镜头极缓推近」措辞比 X 更干净。
- 「4-8秒：切到近岸前景的反向中景平视固定机位」是有想法的调度——从罗斯一侧的近岸回望蒙古人离去，叙事视点好。

硬伤：
- **直接违反 mid_frame_time 硬规则（维度 4）**：规则要求「mid_frame_time 有值时，必须有某个分段的起点正好落在该秒数，且该段开头画面与 mid_frame_prompt 一致」，Y 的切点是 0 / 1 / 4 / 8，**没有任何分段起点落在 5.5 秒**；更糟的是 5.5 秒落在「4-8秒……反向中景」段中间——引擎会在 5.5 秒注入 mid 关键帧（远景宽幅骑队纵队，附图 3），与文字声明的反打中景机位正面打架，成片必然在 5.5 秒出现一次画面跳变/瞬移。
- 与 X 共享的总时长违规（「8-11秒」vs 提交时长 5.5 秒），且 ipm0 的核心收束「空营」被排到 8 秒之后，在实际 ~6.6 秒的模型视频里只能靠尾帧引导硬掰，文字时间轴上根本不存在。
- 反打镜头的表现力因此不成立：好调度若不能通过引导帧机制落地，就只是纸面上的分镜。

## 取舍

**胜者：X。** 两份的关键帧与衔接段完全同质，胜负全在视频分段——X 把 5.5 秒切点与 mid 关键帧严格对齐、单机位弧线可平滑降级，Y 则踩中 mid_frame_time 硬规则并让反打机位与注入的引导帧互相打架；二者共同的硬伤是把 11 秒成片时间轴当成了 5.5 秒提交时长。

若只能用 X 的小修方案：按提交时长重排时间轴——`0-1秒` 衔接复述不动；把 mid_frame_time 改为 **3.5 秒**；`1-3.5秒` 写上马、成列纵队启程（段尾状态即 mid 画面），`3.5-5.5秒` 段首对齐 mid 关键帧后写越坡隐没、残烟空营、收在尾帧构图；同时把「镜头静止极缓推近」改成「极缓推近」单一写法。这样切点、段数（ceil(4.5/3)=2 个内容段）与总长全部归位，还顺带消解了「5.5 秒满员骑队 → 6.58 秒全空」只剩 1 秒清场的瞬移风险。
