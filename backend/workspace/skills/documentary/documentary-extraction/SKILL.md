# 纪录片 / 历史题材：提取附加规范

叠加在 extractor 基础规范之上，冲突时以本文件为准。工具怎么调用看工具描述，这里只写**写什么**。

## 提取顺序（硬规则）

1. `read_script_for_extraction` 读完整剧本，`read_existing_characters` 看项目已有角色。
2. `read_character_roster` 读本集的**选角名册**。
   - 返回 `usable=true`：名册就是契约，**直接照它执行**——不要重新判断谁该建卡，不要改名册上的名字。
   - 返回 `usable=false`（还没有名册，或剧本改动后名册过期）：按下面的判定程序把本集人选一次定齐，
     调用 `save_character_roster` 生成**草稿**（状态「待复核」，等人在集页面确认）。
3. 再求证：只对名册上的关键历史人物检索（整次运行的检索次数有限，名册之外的人不要查）。
4. 最后调用 `save_dedup_characters` 保存：**名册上的每一个人都要建卡，名册之外的人一个都不建**。

名册是跟着这一集走的契约，不是一次运行的临时清单：

- 名字以名册为准。你写的译名/头衔写法若与名册近似，会被自动归位成名册上的名字（`renamed_to_roster`）；
  归不了位的名字**不会写库**，会出现在 `not_in_roster` 里。
- 已有可用名册时再调用 `save_character_roster` **不会改写它**：工具只回报你的提案与名册的差异
  （`proposed_additions` / `proposed_removals`）。把这些差异写进你的结束语，交给人到集页面
  「选角名册」里复核增删——系统不会自动采纳，你也不许绕开。
- 保存后工具会把名册与本集已建的角色卡对账并返回 `missing_from_roster`（名册上还缺卡的人）：
  非空就**立刻再次调用** `save_dedup_characters`，只传这些人把他们补齐。
- 没有名册、或名册因剧本改动而过期时调用 `save_dedup_characters` 会被直接拒绝，一个角色都不会保存。
- 单资产重提取（人点某张已有卡的「重新提取」）：完整性只按那一个人判定，名册其余成员不在本次范围内；
  该目标即使不在名册上也会照常保存（它的字段在发起时已被清空，拒绝保存等于把卡清空），
  但要把「他不在名册上」写进结束语，交给人复核是否补进名册。

### 名册判定程序（只在没有可用名册时执行；按剧本顺序机械走一遍，不要凭印象回忆）

从剧本第一行读到最后一行。每遇到一个**被点名的人**（有专名，不是「士兵」「随从」这类群体），
当场按顺序回答三问，任一为「是」即登记，并记下是哪一条：

1. **决策**：他在本集做了决定、下了命令、签发了谕令或条约？
2. **行动**：他在本集有动作——出发、率队、测绘、谈判、交付、修筑？
3. **亲历**：他在本集事件的现场，剧本写出了他的处境或反应？

三问全为「否」才跳过（只被一笔带过、无决策无行动的人，以及后世的史家与转述者）。
无名群体（士兵、随从、俘虏、船工）永远不登记——群体写进场景与分镜。
远方下令、本集不正面出场的君主按**决策**登记。

### 同一个人只登记一条（合并规则）

登记前先合并，下列情形都是同一个人，只登记**一条**：**译名变体**（沃尔孔斯基／沃尔康斯基）、
**别名与简称**、**头衔与本名**（「西伯利亚总督」与其本名指同一人时按本名登记）、
**带括号的定位**（「彼得一世（沙皇）」与「彼得一世」）。用剧本里最常用的写法作为 `name`。

- `name`：就是角色卡的名字，保存时原样再用一次；不要写空格与 `@ / : * ? " < > |`（会被自动替换成 `_`）。
- `basis`：剧本里点到他的那句（或那段）原文。
- `reason`：按**决策／行动／亲历**哪一条入选，并写明具体是哪个动作。

## 角色

**谁该建卡（硬规则）**：解说词里被点名、且对本集事件有**决策或行动**的历史人物，一律建卡——
包括只在远方下令、本集没有正面出场的君主（如同时在南线出兵的清朝皇帝）。
不建卡的是：只被旁白一笔带过且无决策无行动的人物、后世的史家与转述者、
以及无名群体（士兵、随从、俘虏、船工）——群体写进场景与分镜，不占角色卡。
这条规则由上面的**名册判定程序**机械执行：名册一经生成，建卡范围就以名册为准，不再临场判断；
名册的增删由人在集页面「选角名册」里完成。

- `role`：短身份标签，≤12 字（「沙皇 · 谕令签发者」）。
- `description`：1–3 句，含 ①身份地位 ②所属势力/朝代 ③年代与此时处境 ④本集叙事作用。
- `appearance`：年龄感、体态、脸型、发型、髭须形状；历史人物按已确证的画像特征写。
- `styling`：**≥2 项可穿戴或可持有的身份符号**，逐项写死款式与颜色。符号类别：冠冕/头饰/发辫形制、
  绶带与勋章、胸甲与戎装、朝服与补子、袍服纹样与腰带、佩剑与权杖、印信与文书、仪仗持物。
- **辨识度优先（硬规则）**：一个人物有多套史实成立的造型时，选身份辨识度最高的那套。
  彼得一世写「胸甲戎装 + 圣安德烈蓝绶带」，不写同样属实却像平民的素色长外套；清帝写朝服朝珠朝冠，不写便服。

## 三视图禁背景（硬规则）

角色设定图是纯白背景。身份**只能**靠穿戴与持物表达；**禁止**把宫殿、战场、地图、旗帜、桌案、
仪仗队列等环境元素写进任何字段——它们会被提示词 Agent 落进画面，毁掉设定图版式。

## 场景

`prompt` 必须能读出 ①年代（建筑形制、材料工艺，写具体形制不写「古代风格」）②地域（地理气候植被）
③功能（谈判厅/驿站/工坊/军帐，功能决定陈设）。禁止晚于该年代的物件。
`time` 仍是**时段**（清晨/正午/黄昏/夜晚…），年代写进 `prompt`，不要把年份填进 `time`。
`lighting` 只用该年代可得的光源（日光、月光、烛火、油灯、炉火、火把），并与 `time` 一致。

## 道具

`description` 必须含 **年代 + 用途 + 材质工艺**（「17 世纪末手抄羊皮纸文书，鹅毛笔书写，蜡封朱印，边缘磨损」）。
禁止现代加工痕迹（激光切边、机制螺丝、塑料件），除非年代本身允许。

## 背景信息载体（exposition，硬规则）

解说词常常提到一些**本集不出场、却必须让观众看见**的实体：组织（谢苗诺夫近卫团）、
远在他处的人物（彼得一世）、异地发生的事件与其现场（波尔塔瓦战役）。
过去这些实体没有任何落点，于是「近卫团出身、受彼得一世器重」这一句只能拍成
「一个人站在空操场」。现在它们必须被提取成**背景信息载体**。

判定（三问任一为「是」即登记为载体）：

1. 旁白**点名**了这个实体，而它**本集画面里不会出现**——注意判据是「会不会出现在画面里」，
   **不是**「有没有动作」：远在彼得堡签发谕令的沙皇、远在北京发兵的皇帝都有决策动作，
   但本集没有一个镜头拍得到他们本人，所以他们**同时**是名册上的人物**和**背景信息载体；
2. 不给它一个画面，观众就听不懂这句旁白在说什么；
3. 它是组织、军团、条约、战役、异地城市这类**不能靠一个在场人物代替**的东西。

> 反例：本集随队出发、测绘、谈判的人物都会入镜，**不是**载体。
> 判不准时问一句「这一集有没有哪个镜头能拍到他本人」——答案是「没有」就登记为载体。
>
> **注意**：三问只回答「它**能不能**当载体」。本集**要不要真的建**，由下面「视觉计划」的预算决定。

落库规则（**不新增资产类别**，仍用现有三类）：

- **人物**（不在场的君主、统帅）→ `save_dedup_characters`，传 `exposition: true`。
  载体就是他的**肖像**：`appearance` / `styling` 照常按已确证画像写。
  载体不占选角名册——名册只管本集出场的人，`exposition: true` 的人不会被名册拦下，
  也不要为了它去改名册。该人物若已有角色卡（彼得一世），**不要重复建卡**，
  按同一个名字再保存一次即可，系统会在原卡上补标记。
- **组织 / 条约 / 文书 / 勋章**→ `save_dedup_props`，传 `exposition: true`。
  道具是这个抽象实体的**可画器物**：团旗、制服前襟、勋章、谕令原件、印信。
  `description` 仍按道具规则写年代 + 用途 + 材质工艺，不要写成一段历史介绍。
  **被点名的军团/近卫团必须有一件道具载体**（团旗或制服前襟，二选一即可），
  名字带上番号（「谢苗诺夫近卫团团旗」）。操练场之类的场景可以另外建，但**不能代替**这件器物——
  场景拍的是空地，观众认不出是哪支部队。
- **异地事件 / 战场 / 城市**→ `save_dedup_scenes`，传 `exposition: true`。
  `location` 写地点本名（波尔塔瓦），`time` 仍是时段，`prompt` 写该事件现场的年代/地域/功能。

写法纪律：

- 载体是**视觉承载**，不是知识卡片：每一个都要能被画出来。画不出来的（「国力对比」
  「外交转向」）不要登记成载体，它们属于表达设计要解决的问题。
- 不要把本集真正出场的人物、地点标成载体；标错会让它们在分镜里被当成「旁证」使用。
- 一个实体只登记一次，择**最能承载它**的那一类：近卫团用团旗/制服（道具），
  不要同时再建一个「近卫团」角色。

## 视觉计划与资产预算（硬规则，角色 / 场景 / 道具每次提取都先做）

资产不是名词清单，而是**关键帧与视频的参考图**。一集纪录片的镜头数有限，资产多了用不上，
少了旁白就没有画面解释。基础规范里「没有数量上限」「宁可备而不用」**在纪录片里不适用**，以本节为准。

角色、场景、道具是三次互不相见的独立提取，所以**每一次都要先把全集的视觉计划完整做一遍**，
再只保存属于本次类别的那几项。三次做出的计划应当一致。

1. **算镜头预算**：先数剧本里以空行分隔的自然段有几段（节拍标记不算段），再**逐段**数字数，不要用全集总字数去除。
   每段算 1 个镜头；超过 80 字算 2 个，超过 160 字算 3 个。全集加总记为 N。
2. **逐段定主画面**：主画面解释的是这一段**新增的信息**——观众听这一段时，屏幕上最该看到的一样东西
   （一个地点 / 一张地图 / 一件器物 / 一个人物），可以再加最多一个辅画面。
   这一段新增的就是主场景本身（全景、形制、构造）时，主画面用主场景；新增的是一件被点名的器物、
   另一个地点或几处地点的关系时，主画面就是**它**，不要退回到前面已经用过的主场景。
   问的是「画面拍什么才能解释这句旁白」，不是「这句话里有几个名词」。
3. **定每个主画面的资产归属**——按下面的顺序逐条判断，第一条命中就停，三次提取据此得到同一个答案：
   1. 几个地点在旁白里**只以名字出现、意义在于它们的相互位置**（内外层次、前哨、路线、方位、分布）→
      **一张地图**（`asset_type: "map"` 的道具）。全集这类关系通常只需要一张，不给每个地名各建场景。
      地图只用于**地理**位置；数据曲线、坐标图、原理示意图不是地图，交给图层卡片，不建资产。
      地图由**场景提取**保存（见第 7 步）：「这个地点单独建场景还是画进地图」是同一次判断，不交给另一次提取。
   2. 一个**场所**，或场所里**搬不走的东西**（建筑、殿堂、佛像、灵塔、碑、壁画、城墙构件、遗址、坑位、探方、大型仪器设备）→
      **场景**。「搬得走」的标准是一个人能拿起或放上桌面；占一个房间、要接电或固定安装的设备，
      以及埋在坑里、还没取出的遗物，都算搬不走。场所与它里面的主体只建一个资产
      （殿与佛像、灵塔殿与灵塔、实验室与仪器、遗址与遗迹、车马坑与坑中车马），主体写进场景 prompt；
      场景名写画面里实际看到的那个具体场所（「殷墟车马坑」而不是笼统的「殷墟遗址」）。
      **这一条与本次提取的是哪一类无关**：道具提取时遇到它们，答案仍是「场景」，本次不保存。
   3. 能拿起、搬动、摆上桌的**器物**，且旁白点了它的名字 → **道具**。样品、标本、出土文物、文书、信号器具
      都是器物，不是现象；同一段里并列点名的几件同类小物件（如骨骼、木头、木炭三种样品）合成**一件**道具。
      纪录片里道具**不要求**剧本描写了外观、也不要求有人手持（基础规范的这几条判定标准不适用）：
      只要它是某段**新增信息**里点名的器物、且被选为这一段的主画面就建；外观缺的按年代与用途写，不编造细节。
      反过来，只在列举里顺带一提、不是任何一段主画面的器物，不建。
   4. 被点名、对本集有决策或行动的**人** → 角色（按名册规则）；不在场但某段主画面必须是他的肖像 → 角色载体。
      组织、机构、工程、朝廷、部族都不是人，**不进名册、不建角色卡**。
   5. **动作与现象**（燃烟、发掘、测量、辩经、行军）不是资产：资产只是动作发生的场所与被点名的器物，动作写进分镜。
      同一句里动作与器物要拆开判：「守军以烟火与号炮为信」里烟火是现象，号炮是器物（信号器具）。
   6. 年份、数字、度量、专名提示，以及数据曲线、坐标图、原理示意图 → 图层卡片，**既不是地图也不是道具**，不建资产。
4. **合并**：同一样东西在多段出现只算一个；一个地点只建**一个时段**、**一个时代**的版本
   （不为「夜里的烽火」「古时的都城」另建一份同地点场景，时段与古今差异交给关键帧提示词），
   除非旁白在两段里分别描写了它两种不同的样子。异地地点只有在某段主画面就是「这个地方本身的样子」时才建场景。
5. **预算检查**：资产数不是要填满的配额，也不是越少越好。目标是三类合计约为 N 的一半到三分之二（向上取整），
   **上下限同样是硬约束**，绝不超过 N。每个资产必须是**至少一段的主画面**，或**至少两段的辅画面**。
   **数总数的方法**：把计划表里出现的不同资产名（含本集已保存的场景、地图）逐个列成一行清单，再数清单的长度，不要心算。
   超过三分之二时，逐个检查最弱的辅画面并删掉，直到每个多出来的资产都能说出它独占的那一段。
   **低于一半时不合格，必须补**：按段落顺序，找主画面只是在重复已用资产、但这一段点名了器物或另一个地点的段落，
   把它的主画面换成那件器物或那个地点（按第 3 步判类别），直到达到下限。剧本里再也找不到被点名的器物或地点时才允许低于下限，
   并逐段写明理由。
6. **先写计划，再保存**：在调用任何保存工具**之前**，先在回复正文里写出计划表
   `段落 | 镜头数 | 主画面 | 资产（类别） | 归属依据（第几条）`，以及 N、目标区间和三类合计数。
   保存时**严格照这张表**，保存后不要重新规划；结束语引用这张表写本次保存结果。
   **道具提取在场景提取之后运行**：先调用 `read_existing_scenes` 与 `read_existing_props` 查看**本集已关联**的场景和地图
   （`asset_type` 为 `map`），计划表里的场景与地图**直接采用这些已保存的结果**，不再自己另定；
   已保存场景所在场所里的主体（殿里的佛像、实验室里的仪器、坑里的车马）不得再建成道具，已在地图上的地点不得再另建。
   道具提取按上面的方法数「已保存的场景与地图 + 本次计划的道具」，低于下限时由道具提取用被点名的器物补足。
   地图按名字去重（同名自动合并）；不要把项目里其它集、其它用途的地图当成本集的地图沿用。
7. **只保存本次类别**，归属固定，不允许推给另一次提取：
   - 场景提取：保存场景（`save_dedup_scenes`），**以及**第 3 步第 1 条的地图（只用 `save_dedup_props`，每项都写 `asset_type: "map"`，
     description 只写剧本支持的对象、时代、空间范围、用途与粒度，缺的逐项标「待补充」）；地图不是场所，**不得**出现在 `save_dedup_scenes` 里；
   - 道具提取：只保存器物与组织载体（`asset_type: "prop"`），不建地图；
   - 角色提取：只保存人物。
   归本次类别的必须保存，不得写成「建议另行处理」；不归本次类别的只写进计划表。
   本次类别在计划表里没有资产时，保存空列表就是正确结果——**不要为了这一类有东西可存而改动别的类别的判定**。
   保存前逐项自检：它在计划表里吗？表里给它的类别就是本次类别吗？任一为「否」就不保存。
   系统会拒收不属于本次提取的条目（场景提取的非地图道具、道具提取的地图），被拒条目列在返回值 `rejected` 里。
