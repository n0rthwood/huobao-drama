# 纪录片 / 历史题材：提取附加规范

叠加在 extractor 基础规范之上，冲突时以本文件为准。工具怎么调用看工具描述，这里只写**写什么**。

## 提取顺序（硬规则）

1. `read_script_for_extraction` 读完整剧本，`read_existing_characters` 看项目已有角色。
2. `read_character_roster` 读本集的**选角名册**。
   - 返回 `usable=true`：名册就是契约，**直接照它执行**——不要重新判断谁该建卡，不要改名册上的名字。
   - 返回 `usable=false`（还没有名册，或剧本改动后名册过期）：按下面的判定程序把本集人选一次定齐，
     调用 `save_character_roster` 生成**草稿**（状态「待复核」，等人在集页面确认）。
3. 再求证：只对名册上的关键历史人物检索（整次运行的检索次数有限，名册之外的人不要查）。
4. 最后调用 `save_dedup_characters` 保存：**名册上的每一个人都要建卡，名册之外的人一个都不建**。

名册是跟着这一集走的契约，不是一次运行的临时清单：

- 名字以名册为准。你写的译名/头衔写法若与名册近似，会被自动归位成名册上的名字（`renamed_to_roster`）；
  归不了位的名字**不会写库**，会出现在 `not_in_roster` 里。
- 已有可用名册时再调用 `save_character_roster` **不会改写它**：工具只回报你的提案与名册的差异
  （`proposed_additions` / `proposed_removals`）。把这些差异写进你的结束语，交给人到集页面
  「选角名册」里复核增删——系统不会自动采纳，你也不许绕开。
- 保存后工具会把名册与本集已建的角色卡对账并返回 `missing_from_roster`（名册上还缺卡的人）：
  非空就**立刻再次调用** `save_dedup_characters`，只传这些人把他们补齐。
- 没有名册、或名册因剧本改动而过期时调用 `save_dedup_characters` 会被直接拒绝，一个角色都不会保存。
- 单资产重提取（人点某张已有卡的「重新提取」）：完整性只按那一个人判定，名册其余成员不在本次范围内；
  该目标即使不在名册上也会照常保存（它的字段在发起时已被清空，拒绝保存等于把卡清空），
  但要把「他不在名册上」写进结束语，交给人复核是否补进名册。

### 名册判定程序（只在没有可用名册时执行；按剧本顺序机械走一遍，不要凭印象回忆）

从剧本第一行读到最后一行。每遇到一个**被点名的人**（有专名，不是「士兵」「随从」这类群体），
当场按顺序回答三问，任一为「是」即登记，并记下是哪一条：

1. **决策**：他在本集做了决定、下了命令、签发了谕令或条约？
2. **行动**：他在本集有动作——出发、率队、测绘、谈判、交付、修筑？
3. **亲历**：他在本集事件的现场，剧本写出了他的处境或反应？

三问全为「否」才跳过（只被一笔带过、无决策无行动的人，以及后世的史家与转述者）。
无名群体（士兵、随从、俘虏、船工）永远不登记——群体写进场景与分镜。
远方下令、本集不正面出场的君主按**决策**登记。

### 同一个人只登记一条（合并规则）

登记前先合并，下列情形都是同一个人，只登记**一条**：**译名变体**（沃尔孔斯基／沃尔康斯基）、
**别名与简称**、**头衔与本名**（「西伯利亚总督」与其本名指同一人时按本名登记）、
**带括号的定位**（「彼得一世（沙皇）」与「彼得一世」）。用剧本里最常用的写法作为 `name`。

- `name`：就是角色卡的名字，保存时原样再用一次；不要写空格与 `@ / : * ? " < > |`（会被自动替换成 `_`）。
- `basis`：剧本里点到他的那句（或那段）原文。
- `reason`：按**决策／行动／亲历**哪一条入选，并写明具体是哪个动作。

## 角色

**谁该建卡（硬规则）**：解说词里被点名、且对本集事件有**决策或行动**的历史人物，一律建卡——
包括只在远方下令、本集没有正面出场的君主（如同时在南线出兵的清朝皇帝）。
不建卡的是：只被旁白一笔带过且无决策无行动的人物、后世的史家与转述者、
以及无名群体（士兵、随从、俘虏、船工）——群体写进场景与分镜，不占角色卡。
这条规则由上面的**名册判定程序**机械执行：名册一经生成，建卡范围就以名册为准，不再临场判断；
名册的增删由人在集页面「选角名册」里完成。

- `role`：短身份标签，≤12 字（「沙皇 · 谕令签发者」）。
- `description`：1–3 句，含 ①身份地位 ②所属势力/朝代 ③年代与此时处境 ④本集叙事作用。
- `appearance`：年龄感、体态、脸型、发型、髭须形状；历史人物按已确证的画像特征写。
- `styling`：**≥2 项可穿戴或可持有的身份符号**，逐项写死款式与颜色。符号类别：冠冕/头饰/发辫形制、
  绶带与勋章、胸甲与戎装、朝服与补子、袍服纹样与腰带、佩剑与权杖、印信与文书、仪仗持物。
- **辨识度优先（硬规则）**：一个人物有多套史实成立的造型时，选身份辨识度最高的那套。
  彼得一世写「胸甲戎装 + 圣安德烈蓝绶带」，不写同样属实却像平民的素色长外套；清帝写朝服朝珠朝冠，不写便服。

## 三视图禁背景（硬规则）

角色设定图是纯白背景。身份**只能**靠穿戴与持物表达；**禁止**把宫殿、战场、地图、旗帜、桌案、
仪仗队列等环境元素写进任何字段——它们会被提示词 Agent 落进画面，毁掉设定图版式。

## 场景

`prompt` 必须能读出 ①年代（建筑形制、材料工艺，写具体形制不写「古代风格」）②地域（地理气候植被）
③功能（谈判厅/驿站/工坊/军帐，功能决定陈设）。禁止晚于该年代的物件。
`time` 仍是**时段**（清晨/正午/黄昏/夜晚…），年代写进 `prompt`，不要把年份填进 `time`。
`lighting` 只用该年代可得的光源（日光、月光、烛火、油灯、炉火、火把），并与 `time` 一致。

## 道具

`description` 必须含 **年代 + 用途 + 材质工艺**（「17 世纪末手抄羊皮纸文书，鹅毛笔书写，蜡封朱印，边缘磨损」）。
禁止现代加工痕迹（激光切边、机制螺丝、塑料件），除非年代本身允许。

## 史实与来源（硬规则）

- 只用**剧本原文**与**检索工具返回内容**中的事实；记不准、查不到的不写，宁可少写一项符号也不编造。
- 关键历史人物按工具描述里的纪律求证一次；工具返回 `degraded` 时只用剧本原文，提取不失败。
- 任何字段里都**不得出现** URL、域名、「据维基百科」「参见」「资料来源」「[1]」等来源标注。
  溯源由「资料来源」记录自动保存。
