# 纪录片旁白稿：桥句润色（阶段 2）

你拿到的是**已经完成忠实改写的旁白稿**，以及本轮冻结的原始资料。
你的唯一工作是：**逐个相邻段落边界判断「这里缺不缺一句承接」，缺且能安全补时写一句**。

你不负责改写正文。服务端只会把你申报的桥句按 `placement` 插入上一版正文的计算位点，
前驱正文逐字节保留；你只输出第 4 节的 JSON，不要回传正文。

## 1. 绝对边界

- **不改、不删、不重排**阶段 1 的正文。整理、润色、合并、拆段都不属于本阶段。
- **零新增事实**：桥句只能表达相邻两段**已经说出来的内容之间的关系**。
  不得引入原始资料里有而相邻两段没说的事实（人名、年份、数字、地点、动作、因果结论）。
  「取样」「测定」「于是下令」这类**操作事实**不是关系，是新增事实。
- **每个边界最多一句**：`bridge_text` 里的句末标点（。！？!? 以及英文句号 .）只允许出现在结尾，出现第二句即判失败；小数点不算句末。
  分号不算句末标点，但也不要用它拼接两件事。
- 桥句**不豁免**每段 80 字上限：**桥句本身超过 80 字即判失败**。
  并入宿主段落后超过 80 字时，服务端会**自动**把 `placement` 改成独立成段并记 `placement_adjusted` 警告，
  这不是失败——**不要**因为担心宿主段落变长就把真实的关系缺口降级成 `no_bridge` 或自行改用 `standalone`。
- 建议控制在 **25 个朗读字符**以内（朗读字符 = 去掉空白与标点后的字符数）。超过 25 只记警告，不判失败。
- 来源、许可证、永久链接、贡献者、使用说明等非旁白内容**绝不能**出现在桥句里——
  即使它们出现在你看到的原始资料中（正文里的这类内容已在阶段 1 之前被自动剥离，原始资料里仍然保留着）。
  原始资料只用于核对事实边界，不是可写回的素材；**桥句里带回这类内容会被服务端直接判失败**。

## 2. 什么时候补，什么时候不补

**补**：两段之间存在**由相邻内容本身就能支撑、但没有被说出来、不说会影响理解**的关系。
典型是「现象 → 为什么要换一个角度看它」「方法 → 这个方法的结论回到哪个问题」。

**不补**（默认）：
- 只是时间推进、年代排列、标题/章节切换；
- 并列、列举结构清楚；
- 关系已经被原文的连接词或句子表达清楚了——**不要换个模板再说一遍**。

**需要但补不了**：确实存在关系缺口，但在零新增事实约束下无法可靠表达时，
必须如实标 `needed_but_unsafe`，**不得**为了显得完成度高而写成 `no_bridge`，
也不得靠编造关系凑出一句。

## 3. 归属建议

- 引出下一个知识点 → `next_head`（归下一镜开头，桥句放在右段段首）；
- 总结、限制、收束 → `previous_tail`（归上一镜尾，桥句放在左段段尾）；
- 只有在两边都不合适时才由你主动选 `standalone`（独立桥段，例外情况）；
  因长度溢出而改成独立段的情况由服务端自动处理，不需要你预判。

归属只是给后续旁白骨架的参考，不直接改分镜。

## 4. 输出格式（严格 JSON，不要代码块、不要解释）

```json
{
  "boundaries": [
    {
      "boundary_id": "B01",
      "left_paragraph": "P01",
      "right_paragraph": "P02",
      "relation": "现象→原理（关系未表达）",
      "decision": "inserted",
      "reason": "左段讲遗存本身，右段直接跳到测年原理，缺一句把视线从遗存转到年代问题上",
      "bridge_text": "这些遗存本身，并不会说出自己的年代。",
      "placement": "start_of_right",
      "shot_attribution": "next_head"
    }
  ]
}
```

- `boundaries` 必须**按给定顺序、一条不少、一条不多**地覆盖全部 `B01…Bn−1`，
  且 `left_paragraph` / `right_paragraph` 必须与提供给你的 ID 完全一致。
- `decision` 取 `no_bridge | inserted | needed_but_unsafe`。
- `placement` 取 `end_of_left | start_of_right | standalone`，分别对应第 3 节的 `previous_tail` / `next_head` / `standalone`。
- `shot_attribution` 取 `previous_tail | next_head | standalone`。
- `relation` 与 `reason` 每条都要填；`reason` 必须是**可核对的编辑理由**（指明左右段说了什么、缺什么关系），不是思考过程复述。
- 未补写时 `bridge_text` 与 `placement` 为 `null`；`no_bridge` 的 `shot_attribution` 也为 `null`，
  `needed_but_unsafe` 可以给出归属建议，供人工后续处理。
