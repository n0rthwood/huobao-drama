# ドキュメンタリープロジェクト：キーフレームと動画プロンプト追加仕様（段組み合わせ `combo` で分岐）

`prompt-generator/keyframe-prompt` と `prompt-generator/video-prompt` の上に重ねられる。矛盾する場合は**本ファイルを優先**する。

ドキュメンタリーの各ショットには設計カード `design_card`（情報点 / レイヤー段の計画 / 生成段の計画 / 予算）と、人が選んだ段組み合わせ `combo` が付いている。
プロンプトを書く前にまずそれらを読む：**プロンプトは設計カードを実行するものであり、もう一度創作の決定をやり直すものではない**。

## 1. まず `combo` を見て、それから何を書くか決める

| `combo` | キーフレームプロンプト | 動画プロンプト |
|---|---|---|
| `A`（レイヤー段 ▣ のみ） | **書かない**。ショット全体をレイヤー段が描画する（ベース画像 = `layer_plan.base` + 計画レイヤー） | **書かない** |
| `B`（生成段 ▶ のみ） | 書く：先頭 / 中間 / 末尾の三スロットを通常のキーフレーム規範に従って書く | 書く：通常の動画プロンプト規範に従う |
| `C`（レイヤー段 ▣ → 生成段 ▶） | 先頭フレームは**衔接フレーム ◆**（レイヤー段の末尾フレームを継承、固定、出図しない）：**`first_frame_prompt` を書かない**；中間・末尾は通常どおり書く | 書く |
| `D`（生成段 ▶ → レイヤー段 ▣） | 末尾フレームは**衔接フレーム ◆**（レイヤー段の先頭フレームを継承、固定、出図しない）：**`last_frame_prompt` を書かない**；先頭・中間は通常どおり書く | 書く |

バッチタスクはすでにこの表で処理待ちショットとスロットを絞り込んでいる。それでも `A` のショットや衔接フレームのスロットのリクエストが届くなら、
その設計カード / 段組み合わせがまだできていないということであり — 勝手に拡散プロンプトをでっち上げてはならない。

## 2. `gen_plan.reference_assets` はハード制約：全項目を @ で参照する

生成段が存在するとき（`combo` が `B` / `C` / `D`）、`design_card.gen_plan.reference_assets` の各素材
（肖像、背景の情報担体）は、あなたが書くプロンプトの中で `@资产名`/`@name` で参照されなければならない。

- サーバーが一件ずつ照合する：ある参照素材がそのプロンプトで @ 参照されていない → 整合性問題 `card_ref_unmet`（生成を**阻害**）。
  先頭/中間/末尾の三つのプロンプトそれぞれで判定する。
- 文字による記述で @ を代用しない：「傍らに近衛連隊の将校が立つ」と書いてもその参照画像は生図モデルに送られない。
  `@谢苗诺夫近卫团` と書くことが必須である。
- 一つのショットで二つの実体（人物 + その所属組織）を同時に表現するときは、両方を @ し、画面内の空間的関係
（誰が手前、誰が奥 / 画面中の画面 / 壁の版画か）を明記する。

`layer_plan.must_mark` は**語義項目**（地名、範囲、経路）であり、レイヤー段が描く。**プロンプトに書かない**。
除外されるのは語義項目そのものだけである：その素材が `gen_plan.reference_assets` にも含まれるなら、@ 参照は必須のままである。

## 3. 文字はすべてレイヤーに任せ、プロンプトに書かない

- ネームバー、年代、地名ラベル、経路注記は**すべてレイヤー段のレイヤー**（`layer_plan.planned_layers`）であり、プログラムが描画する。
- プロンプトに「画面には…と書かれている」「タイトルは…」「字幕…」と**決して**書かない — 拡散モデルは乱れた文字を描くし、
  スタイルプリセット自体に `no lettering` が付いている。
- 画面内にネームバーの余地を残す必要があるとき（例：人物を左 1/3 構図に寄せ、右下を空ける）はその構図を書けばよい。ただしネームバーそのものは描かない。

## 4. 前ショットの継承を許可（ドキュメンタリー分岐の例外）

基本の `keyframe-prompt` 規範は各フレームの独立性を求め、継承を禁じている。**ドキュメンタリープロジェクトはこの禁令を解除する**：

- バッチタスクの message には前後ショットの設計カードと画面記述が入っている。同一叙事セグメント内の連続ショット
（同じ場所、同じ人々、同じ出来事の別の段階）は、同じ空間関係と視点を**引き継ぐべき**であり、各自バラバラに書かない
（「船隊の目的地」のショットは前ショットで出現済みの船隊を引き継がなければならない）。
- 継承の書き方はそれでも**自己完結的な記述**である：引き継いだ内容を**改めて書き下す**（同じ川の区間、同じ船隊、同じカメラの向き）。
  「同上一フレーム」「変更なし」とは書かない — 後者は単フレーム出図では何の情報もない。
- 本当に継承しているときだけ継承する；ハードカット（場所替え、時代替え）は従来どおり各自独立である。

## 5. 依然として有効な基本規則

- **絶対画像優先**：キャラクターの種族、服装、色、髪型、体型を書かず、キャラクターは常に `@角色名`/`@name` でのみ指す。
- 各プロンプトは自己完結：サイズ、機位、構図、光、雰囲気をすべて自分で述べる。
- `inherits_first=true` のとき `first_frame_prompt` は空にする；`mid_frame_time` は 0.5 と生成段の長さ `-0.5` の間に置く。
