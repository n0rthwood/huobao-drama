# ドキュメンタリープロジェクト：キーフレームと動画プロンプト追加仕様（device で分岐）

`prompt-generator/keyframe-prompt` と `prompt-generator/video-prompt` の上に重ねられる。矛盾する場合は**本ファイルを優先**する。

ドキュメンタリーの各ショットには表現設計 `intent`（情報点 / device / must_show / overlay_plan）が付いている。
プロンプトを書く前にまずそれを読む：**プロンプトは表現設計を実行するものであり、もう一度創作の決定をやり直すものではない**。

## 1. まず `device` を見て、それから何を書くか決める

| `intent.device` | キーフレームプロンプト | 動画プロンプト |
|---|---|---|
| `map_anim` | **書かない**。ショット全体は決定論的クリップが描画する（ベース地図 = 証拠地図の原本 + オーバーレイレイヤー） | 書かない |
| `archival` | **書かない**。ショット全体は決定論的クリップが描画する（ベース地図 = アーカイブ原本 + ゆっくりとしたプッシュイン） | 書かない |
| `card` | 書く：ベース地図 = 肖像素材の画像か再現静止画。ネームバーは**レイヤー**であり、プロンプトに文字を書かない | 書かない |
| `reenact_still` | 書く：通常のキーフレーム規範に従う | 書かない |
| `reenact_video` | 書く：通常のキーフレーム規範に従う | 書く：通常の動画プロンプト規範に従う |

バッチタスクはすでにこの表で処理待ちショットを絞り込んでいる。それでも `map_anim`/`archival` ショットのリクエストが届くなら、
その `intent` がまだできていないということであり — 勝手に拡散プロンプトをでっち上げてはならない。

## 2. `must_show` はハード制約：全項目を @ で参照する

`device` が `reenact_still` / `reenact_video` のとき、`intent.must_show` の `asset_id` を持つ各項目
（肖像、背景の情報担体）は、あなたが書くプロンプトの中で `@资产名`/`@name` で参照されなければならない。

- サーバーが一件ずつ照合する：ある `must_show` 素材がそのプロンプトで @ 参照されていない → 整合性問題 `intent_unmet`（生成を**阻害**）。
  先頭/中間/末尾の三つのプロンプトそれぞれで判定する。
- 文字による記述で @ を代用しない：「傍らに近衛連隊の将校が立つ」と書いてもその参照画像は生図モデルに送られない。
  `@谢苗诺夫近卫团` と書くことが必須である。
- 一つのショットで二つの実体（人物 + その所属組織）を同時に表現するときは、両方を @ し、画面内の空間的関係
（誰が手前、誰が奥 / 画面中の画面 / 壁の版画か）を明記する。

## 3. 文字はすべてレイヤーに任せ、プロンプトに書かない

- ネームバー、年代、地名ラベル、経路注記は**すべてオーバーレイレイヤー**（`overlay_plan`）であり、プログラムが描画する。
- プロンプトに「画面には…と書かれている」「タイトルは…」「字幕…」と**決して**書かない — 拡散モデルは乱れた文字を描くし、
  スタイルプリセット自体に `no lettering` が付いている。
- `card` ショットのプロンプトはベース地図だけを担う：人物の画面内の位置はネームバーの**余地を残す**こと
（例：人物を左 1/3 構図に寄せ、右下を空ける）。ただしネームバーそのものは描かない。

## 4. 前ショットの継承を許可（ドキュメンタリー分岐の例外）

基本の `keyframe-prompt` 規範は各フレームの独立性を求め、継承を禁じている。**ドキュメンタリープロジェクトはこの禁令を解除する**：

- バッチタスクの message には前後ショットの `intent` と画面記述が入っている。同一叙事セグメント内の連続ショット
（同じ場所、同じ人々、同じ出来事の別の段階）は、同じ空間関係と視点を**引き継ぐべき**であり、各自バラバラに書かない
（「船隊の目的地」のショットは前ショットで出現済みの船隊を引き継がなければならない）。
- 継承の書き方はそれでも**自己完結的な記述**である：引き継いだ内容を**改めて書き下す**（同じ川の区間、同じ船隊、同じカメラの向き）。
  「同上一フレーム」「変更なし」とは書かない — 後者は単フレーム出図では何の情報もない。
- 本当に継承しているときだけ継承する；ハードカット（場所替え、時代替え）は従来どおり各自独立である。

## 5. 仍然有効な基本規則

- **絶対画像優先**：キャラクターの種族、服装、色、髪型、体型を書かず、キャラクターは常に `@角色名`/`@name` でのみ指す。
- 各プロンプトは自己完結：サイズ、機位、構図、光、雰囲気をすべて自分で述べる。
- `inherits_first=true` のとき `first_frame_prompt` は空にする；`mid_frame_time` は 0.5 と `duration-0.5` の間に置く。
