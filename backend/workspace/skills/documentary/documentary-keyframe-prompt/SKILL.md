# 纪录片项目：关键帧与视频提示词附加规范（按段组合 combo 分支）

叠加在 `prompt-generator/keyframe-prompt` 与 `prompt-generator/video-prompt` 之上，冲突时**以本文件为准**。

纪录片的每一镜都带一份分镜设计卡 `design_card`（信息点 / 图层段计划 / 生成段计划 / 预算）与一个由人选定的段组合 `combo`。
写提示词之前先读它们：**提示词是在执行设计卡，不是重新做一次创作决定**。

## 1. 先看 `combo`，再决定写什么

| `combo` | 关键帧提示词 | 视频提示词 |
|---|---|---|
| `A`（只有图层段 ▣） | **不写**。整镜由图层段渲染（底图 = `layer_plan.base` + 计划图层） | **不写** |
| `B`（只有生成段 ▶） | 写：首 / 中 / 尾三槽位按常规关键帧规范 | 写：按常规视频提示词规范 |
| `C`（图层段 ▣ → 生成段 ▶） | 首帧是**衔接帧 ◆**（由图层段末帧继承、锁定、不出图）：**不写 `first_frame_prompt`**；中帧、尾帧照常写 | 写 |
| `D`（生成段 ▶ → 图层段 ▣） | 尾帧是**衔接帧 ◆**（由图层段首帧继承、锁定、不出图）：**不写 `last_frame_prompt`**；首帧、中帧照常写 | 写 |

批量任务已经按这张表过滤过待处理镜头与槽位；若你仍收到一个 `A` 镜头或一个衔接帧槽位的请求，
说明它的设计卡 / 段组合还没做好——不要凭空给它编扩散提示词。

## 2. `gen_plan.reference_assets` 是硬约束：每一项都要被 @ 到

生成段存在时（`combo` 为 `B` / `C` / `D`），`design_card.gen_plan.reference_assets` 里每一个资产
（肖像、背景信息载体）都必须在你写的那条提示词里用 `@资产名` 引用。

- 服务端会逐条核对：某个参考资产没被该提示词 @ 到 → 一致性问题 `card_ref_unmet`（**阻断**生成），
  首/中/尾三条提示词分别判定。
- 不要用文字描述代替 @：写「身旁站着近卫团军官」不会把那张参考图发给生图模型，
  必须写 `@谢苗诺夫近卫团`。
- 一镜要同时表达两个实体（人物 + 他所属的组织）时，两者都 @，并写清它们在画面中的空间关系
  （谁在前景、谁在背景/画中画/墙上的版画）。

`layer_plan.must_mark` 是**语义条目**（地名、范围、路线），由图层段负责画出来，**不要写进提示词**。
被排除的只是这些语义条目本身；若某个底图资产同时出现在 `gen_plan.reference_assets` 里，它仍然必须被 @。

## 3. 文字一律交给图层，提示词里不要写字

- 姓名条、年代、地名标签、路线注记**全部是图层段的层**（`layer_plan.planned_layers`），由程序渲染。
- 提示词里**绝不**写「画面上写着…」「标题为…」「字幕…」——扩散模型会画出乱码文字，
  而且风格预设本身就带 `no lettering`。
- 画面中需要给姓名条留出空间时（例如人物偏左 1/3 构图，右下留空）照写构图即可，但不要自己画那条姓名条。

## 4. 允许承接上一镜（纪录片分支的例外）

基础 `keyframe-prompt` 规范要求每帧独立、禁止承接。**纪录片项目取消这条禁令**：

- 批量任务的 message 里带了前后镜的设计卡与画面描述。同一叙事段里的连续镜头
  （同一地点、同一批人、同一件事的不同阶段）**应当**延续同一套空间关系与视角，
  而不是各写各的（「船队的目的地」那一镜必须延续前镜已经出现的船队）。
- 承接的写法仍然是**自足描述**：把延续下来的内容**重新写一遍**（同一河段、同一支船队、同样的机位朝向），
  而不是写「同上一帧」「保持不变」——后者在单帧出图时没有任何信息。
- 只有确实在延续时才承接；硬切镜（换地点、换时代）照旧各自独立。

## 5. 仍然生效的基础规则

- **绝对图像优先**：不写角色的物种、服装、颜色、发型、体型，角色一律只用 `@角色名` 指代。
- 每条提示词自足：景别、机位、构图、光线、氛围都要自己交代。
- `first_frame_prompt` 在 `inherits_first=true` 时留空；`mid_frame_time` 落在 0.5 与生成段时长 `-0.5` 之间。
