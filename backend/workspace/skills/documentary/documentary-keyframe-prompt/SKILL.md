# 纪录片项目：关键帧与视频提示词附加规范（按 device 分支）

叠加在 `prompt-generator/keyframe-prompt` 与 `prompt-generator/video-prompt` 之上，冲突时**以本文件为准**。

纪录片的每一镜都带一份表达设计 `intent`（信息点 / device / must_show / overlay_plan）。
写提示词之前先读它：**提示词是在执行表达设计，不是重新做一次创作决定**。

## 1. 先看 `device`，再决定写什么

| `intent.device` | 关键帧提示词 | 视频提示词 |
|---|---|---|
| `map_anim` | **不写**。整镜由确定性片段渲染（底图 = 证据地图原图 + 叠加图层） | 不写 |
| `archival` | **不写**。整镜由确定性片段渲染（底图 = 档案原件 + 缓慢推移） | 不写 |
| `card` | 写：底图 = 肖像资产图或再现静帧。姓名条是**图层**，提示词里不写任何文字 | 不写 |
| `reenact_still` | 写：按常规关键帧规范 | 不写 |
| `reenact_video` | 写：按常规关键帧规范 | 写：按常规视频提示词规范 |

批量任务已经按这张表过滤过待处理镜头；若你仍收到一个 `map_anim`/`archival` 镜头的请求，
说明它的 `intent` 还没做好——不要凭空给它编扩散提示词。

## 2. `must_show` 是硬约束：每一项都要被 @ 到

`device` 是 `reenact_still` / `reenact_video` 时，`intent.must_show` 里每一个带 `asset_id` 的条目
（肖像、背景信息载体）都必须在你写的那条提示词里用 `@资产名` 引用。

- 服务端会逐条核对：某个 `must_show` 资产没被该提示词 @ 到 → 一致性问题 `intent_unmet`（**阻断**生成），
  首/中/尾三条提示词分别判定。
- 不要用文字描述代替 @：写「身旁站着近卫团军官」不会把那张参考图发给生图模型，
  必须写 `@谢苗诺夫近卫团`。
- 一镜要同时表达两个实体（人物 + 他所属的组织）时，两者都 @，并写清它们在画面中的空间关系
  （谁在前景、谁在背景/画中画/墙上的版画）。

## 3. 文字一律交给图层，提示词里不要写字

- 姓名条、年代、地名标签、路线注记**全部是叠加图层**（`overlay_plan`），由程序渲染。
- 提示词里**绝不**写「画面上写着…」「标题为…」「字幕…」——扩散模型会画出乱码文字，
  而且风格预设本身就带 `no lettering`。
- `card` 镜头的提示词只负责底图：人物在画面中的位置要给姓名条**留出空间**
  （例如人物偏左 1/3 构图，右下留空），但不要自己画那条姓名条。

## 4. 允许承接上一镜（纪录片分支的例外）

基础 `keyframe-prompt` 规范要求每帧独立、禁止承接。**纪录片项目取消这条禁令**：

- 批量任务的 message 里带了前后镜的 `intent` 与画面描述。同一叙事段里的连续镜头
  （同一地点、同一批人、同一件事的不同阶段）**应当**延续同一套空间关系与视角，
  而不是各写各的（「船队的目的地」那一镜必须延续前镜已经出现的船队）。
- 承接的写法仍然是**自足描述**：把延续下来的内容**重新写一遍**（同一河段、同一支船队、同样的机位朝向），
  而不是写「同上一帧」「保持不变」——后者在单帧出图时没有任何信息。
- 只有确实在延续时才承接；硬切镜（换地点、换时代）照旧各自独立。

## 5. 仍然生效的基础规则

- **绝对图像优先**：不写角色的物种、服装、颜色、发型、体型，角色一律只用 `@角色名` 指代。
- 每条提示词自足：景别、机位、构图、光线、氛围都要自己交代。
- `first_frame_prompt` 在 `inherits_first=true` 时留空；`mid_frame_time` 落在 0.5 与 `duration-0.5` 之间。
