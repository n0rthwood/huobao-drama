# 다큐멘터리 프로젝트: 키프레임과 영상 프롬프트 추가 규범(device 로 분기)

`prompt-generator/keyframe-prompt` 과 `prompt-generator/video-prompt` 위에 덧씌워지며, 충돌 시 **본 파일이 우선한다**.

다큐멘터리의 모든 숏에는 표현 설계 `intent`(정보점 / device / must_show / overlay_plan)가 붙어 있다.
프롬프트를 쓰기 전에 먼저 그것을 읽는다: **프롬프트는 표현 설계를 실행하는 것이지, 창작 결정을 다시 내리는 것이 아니다**.

## 1. 먼저 `device` 를 보고, 그다음 무엇을 쓸지 정한다

| `intent.device` | 키프레임 프롬프트 | 영상 프롬프트 |
|---|---|---|
| `map_anim` | **쓰지 않는다**. 숏 전체를 결정론적 클립이 렌더링한다(베이스 지도 = 증거 지도 원본 + 오버레이 레이어) | 쓰지 않음 |
| `archival` | **쓰지 않는다**. 숏 전체를 결정론적 클립이 렌더링한다(베이스 지도 = 아카이브 원본 + 느린 푸시인) | 쓰지 않음 |
| `card` | 쓴다: 베이스 지도 = 초상 소재 이미지 또는 재연 정지 화면. 네임바는 **레이어**이며, 프롬프트에 텍스트를 쓰지 않는다 | 쓰지 않음 |
| `reenact_still` | 쓴다: 일반 키프레임 규범에 따른다 | 쓰지 않음 |
| `reenact_video` | 쓴다: 일반 키프레임 규범에 따른다 | 쓴다: 일반 영상 프롬프트 규범에 따른다 |

배치 작업은 이미 이 표로 처리 대기 숏을 걸러냈다. 그래도 `map_anim`/`archival` 숏의 요청이 도착한다면
그 `intent` 가 아직 완성되지 않았다는 뜻이며 — 임의로 확산 프롬프트를 지어내서는 안 된다.

## 2. `must_show` 는 하드 제약: 모든 항목을 @ 로 참조한다

`device` 가 `reenact_still` / `reenact_video` 일 때, `intent.must_show` 의 `asset_id` 를 가진 모든 항목
(초상, 배경 정보 담체)은 당신이 쓰는 프롬프트 안에서 `@资产名`/`@name` 으로 참조되어야 한다.

- 서버가 한 항목씩 대조한다: 어떤 `must_show` 소재가 그 프롬프트에서 @ 참조되지 않았다 → 일관성 문제 `intent_unmet`(생성을 **차단**).
  첫/중간/마지막 세 프롬프트 각각에 대해 판정한다.
- 문자 기술로 @ 를 대체하지 않는다: "곁에 근위 연대 장교가 서 있다"고 써도 그 참조 이미지는 생도 모델에 보내지지 않는다.
  반드시 `@谢苗诺夫近卫团` 이라고 써야 한다.
- 한 숏이 두 개체(인물 + 그 소속 조직)를 동시에 표현해야 할 때는 둘 다 @ 하고, 화면 속 공간적 관계
(누가 전경, 누가 배경 / 화면 속 화면 / 벽의 판화인지)를 명시한다.

## 3. 텍스트는 전부 레이어에 맡기고, 프롬프트에 쓰지 않는다

- 네임바, 연도, 지명 라벨, 경로 주기는 **모두 오버레이 레이어**(`overlay_plan`)이며, 프로그램이 렌더링한다.
- 프롬프트에 "화면에 …라고 적혀 있다", "제목은 …", "자막…"이라고 **절대로** 쓰지 않는다 — 확산 모델은 깨진 글자를 그리고,
  스타일 프리셋 자체에 이미 `no lettering` 이 붙어 있다.
- `card` 숏의 프롬프트는 베이스 지도만 담당한다: 인물의 화면 내 위치는 네임바의 **여백을 남겨야 한다**
(예: 인물을 왼쪽 1/3 구도로 치우치게 하고 오른쪽 아래를 비운다). 단, 네임바 자체를 그리지 않는다.

## 4. 이전 숏 이어받기 허용(다큐멘터리 분기의 예외)

기본 `keyframe-prompt` 규범은 모든 프레임의 독립성을 요구하고 이어받기를 금지한다. **다큐멘터리 프로젝트는 이 금지를 해제한다**:

- 배치 작업의 message 에는 앞뒤 숏의 `intent` 와 화면 기술이 담겨 있다. 같은 서사 세그먼트 안의 연속 숏
(같은 장소, 같은 사람들, 같은 사건의 다른 단계)은 같은 공간 관계와 시점을 **이어받아야 하며**, 각자 따로 쓰지 않는다
("선단의 목적지" 숏은 앞 숏에서 이미 나온 선단을 이어받아야 한다).
- 이어받는 쓰법은 여전히 **자기완결적 기술**이다: 이어받은 내용을 **다시 한 번 써 내려간다**(같은 강 구간, 같은 선단, 같은 카메라 방향).
  "윗 프레임과 동일", "변경 없음"이라고 쓰지 않는다 — 후자는 단일 프레임 생성에서 아무 정보도 없다.
- 실제로 이어지는 경우에만 이어받는다; 하드 컷(장소 교체, 시대 교체)은 종전대로 각자 독립이다.

## 5. 여전히 유효한 기본 규칙

- **절대 이미지 우선**: 캐릭터의 종족, 복장, 색, 헤어스타일, 체형을 쓰지 않고, 캐릭터는 언제나 `@角色名`/`@name` 으로만 지칭한다.
- 각 프롬프트는 자기완결적: 사이즈, 카메라 위치, 구도, 빛, 분위기를 모두 스스로 서술한다.
- `inherits_first=true` 일 때 `first_frame_prompt` 는 비워 둔다; `mid_frame_time` 은 0.5 와 `duration-0.5` 사이에 둔다.
