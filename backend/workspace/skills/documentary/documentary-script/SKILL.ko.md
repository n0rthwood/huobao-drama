# 다큐멘터리 프로젝트: 대본 정리 추가 규범(narration-first)

`script-rewriter` 기본 규범 위에 덧씌워지며, 충돌 시 **본 파일이 우선한다**.

다큐멘터리 프로젝트의 "대본"은 연극 대본이 아니라 **내레이션 원고**이다: 저장된 본문은 스토리보드 분해에서 단락별로 그대로 가져와져
각 숏의 해설(`narration_text`)이 되고, 다시 음성과 자막으로 합성된다. 당신이 정리하는 모든 단어는 최종적으로 낭독된다.

## 내레이션이 아닌 내용 (필수)

출처 블록, 저작권·라이선스, URL·영구 링크, 기여자·편집 이력, 서지·인용 주석(ISBN·출판사 포함), 템플릿·편집 설명 및 낭독하지 않는다는 안내를 식별하여 제거한다. 예를 들어 '참고: 책, ISBN 123'은 본문에서 빼되, 낭독할 본문의 '여행기에 따르면' 같은 출처 표현은 보존한다.

## 1. 기본 규범 중 다큐멘터리에서 무효가 되는 세 가지(하드 룰)

- **"대사 구동"을 하지 않는다**: 기본 규범의 "대사로 이야기를 전개하고 내레이션을 줄인다"는 여기서는 **반대**이다 — 다큐멘터리는 해설로 전개되며,
  내레이션은 보충이 아니라 본문이다.
- **대사 행을 쓰지 않는다**: `캐릭터명:(상태)대사` 형식은 일체 금지이며, "누구가 말했다:『…』"식의 대변 표현도 쓰지 않는다.
  역사 인물의 원래 말은 **해설의 간접 전달**로만 나타난다("그는 상소문에 이렇게 썼다, ……"). 별도의 대사 행을 만들지 않는다.
- **씬 헤더를 쓰지 않는다**: `## S01 | 실내 · 카페 | 황혼` 같은 연극식 씬 헤더를 쓰지 않는다.
  `rewrite_to_screenplay` 도구가 반환하는 instruction에는 숏드라마 형식 안내가 포함되어 있으나, 다큐멘터리 프로젝트는 **그 형식 요구를 무시**하고 본 파일의 레이아웃을 따른다.

## 2. 충실성(하드 룰)

- **사실을 추가하지 않는다**: 인물을 보태지 않고, 대사를 보태지 않고, 심리 묘사를 보태지 않고, 세부 장면을 보태지 않는다. 원문에 없는 것은 한 글자도 더하지 않는다.
- **연도, 숫자, 인명, 지명, 관직명, 조약명, 인용문은 원문 그대로 유지**한다 — 재작성하지 않고, 근사치로 바꾸지 않고, 환산하지 않고, 현대식 명칭으로 번역하지 않는다.
- **저자 귀속과 출처 표현은 그대로 베낀다**(『이역록』에 따르면, 툴리션은 돌아오는 길에 기록했다), 주어 없는 문장으로 삭제하지 않는다.
- 정확히 기억나지 않거나 원문에 없는 것은, 지어내기보다 한 문장을 덜 쓰는 편이 낫다.

## 3. 레이아웃(정리이지 재작성이 아님)

정리 동작은 네 가지뿐이다: **단락 나누기, 군더더기 제거, 문장 부호 보완, 고유명 표기 통일**. 순서는 항상 원문을 따르며 서사 순서를 재배치해서는 안 된다.

```
【서막】
1715 년 가을, 상트페테르부르크의 겨울 궁전은 아직 완공되지 않았지만, 차르 표트르 1세의 시선은 이미 동방을 향하고 있었다.

북쪽의 준가르와 남쪽의 청나라 사이에서, 이르티쉬 강은 군대를 내륙으로 보낼 수 있는 유일한 수로였다.

【원정】
그해 겨울, 부흐홀츠는 약 삼천 명의 병력을 이끌고 토볼스크에서 강을 거슬러 올라가라는 명을 받았다.
```

- `【비트명】` 표시로 서사 비트를 표시한다(서막 / 배경 / 전환 / 절정 / 마무리 등). 스토리보드는 비트 경계에서 문단을 자른다.
- 비트 표시 이외의 모든 문단은 **그대로 낭독 가능한 해설 문단**이다:
  - 각 문단은 **하나의 완전한 의미**만 담고, **80 자 이내**로 유지한다(음성 합성의 문단당 하드 상한. 초과 시 스토리보드가 거부한다);
  - 문단은 마침표 / 물음표 / 느낌표로 끝내고, 문장 중간에서 문단을 자르지 않는다;
  - 문단 안에 괄호 주석, 숏 언어(샷 크기 / 앵글 / 카메라 워크), 화면 지시를 쓰지 않는다 — 화면은 스토리보드가 쓴다.
- 분량은 원문과 **대체로 같다**(±5%). 눈에 띄게 길어지면 과장이고, 눈에 띄게 짧아지면 사실 삭제이며, 둘 다 퇴보이다.

## 4. 절차

1. `read_episode_script` 로 원문을 읽는다.
2. `rewrite_to_screenplay` 로 원문을 가져온다(`source_content` 만 사용하고, 그 안의 숏드라마 형식 instruction은 무시한다).
3. 본 파일에 따라 내레이션 원고로 정리한다.
4. 자기 점검: 대사 행 없음, 씬 헤더 없음, 추가 사실 없음, 각 문단 ≤80 자, 연도와 인명이 원문과 한 글자까지 일치.
5. `save_script` 로 저장한다.
