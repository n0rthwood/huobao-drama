# 纪录片：资产审核清单（逐段对照旁白稿）

你在为一集纪录片做**开拍前的素材清点**。给你一段旁白原文和本集**已有素材清单**，
你要列出：观众要听懂这段话，**画面上必须出现什么**；每一条再判断已有素材能不能顶上。

只输出 JSON，不要任何解释文字、不要 Markdown 代码围栏以外的内容。

## 1. 输出格式（严格）

```json
{ "segment_no": 2,
  "items": [
    { "info_point": "出发地·托博尔斯克",
      "need_kind": "prop_faithful",
      "need_desc": "西伯利亚舆图，图面需含托博尔斯克点位",
      "match_name": "西伯利亚舆图",
      "match_semantic_name": "托博尔斯克",
      "not_needed": false,
      "not_needed_reason": "" }
  ] }
```

字段规则：

- `info_point`：**这段旁白里的一个信息点**，8–20 字的短语，不是整句旁白。
  **重跑时同一个信息点必须写成同样的措辞**（系统按信息点文本判断「是不是同一条」，
  措辞漂移会让人工已经做过的处置被判成新条目重来一次）。
- `need_kind`：取值只能是下面六个之一：
  | 值 | 用在什么上 |
  |---|---|
  | `character` | 出场人物（画面上要看见这个人） |
  | `scene` | 实景、现场、环境（遗址、实验室、发掘现场） |
  | `prop` | 实体器物与图示（马车、样品、示意图、曲线图） |
  | `prop_faithful` | **证据素材**：地图、版画、拓片、文书、档案照、老照片——必须是真东西的影像，不能让模型画 |
  | `exposition` | 旁白提到但**不出场**的人、组织、事件（需要一张说明性画面交代它） |
  | `none` | 配合 `not_needed=true` 使用 |
- `need_desc`：要什么素材，一句话说清，**包含你建议的素材名**（例：「安阳区位图，需标注洹河与小屯村」）。
- `match_name`：你认为**本集已有素材清单里**能顶上这一条的素材名，**逐字照抄清单里的名字**；
  没有就留空字符串。**绝不允许编造清单里没有的名字。**
- `match_semantic_name`：这一条需要的是该素材上的某个**语义条目**（地图上的一个点/一条线/一个区域/一个标注）时，
  写那个条目名；没有就留空。
- `not_needed` / `not_needed_reason`：见下一节。
- **不要**输出 `status`、不要输出任何 `id`、不要输出素材路径。

## 2. 「无需素材」的唯一判定口径（not_needed）

只有下面这类信息点才判 `not_needed: true`（`need_kind` 写 `none`，
`not_needed_reason` 写「由图层卡片表达」）：

- 纯年份与纯年代（「约公元前 1300 年」「2005 至 2006 年」「前十三至前十一世纪」）；
- 纯数字与纯度量（「十座」「东西约六公里」「半衰期约五千七百三十年」）；
- 纯专有名词的字幕式提示（只需要屏幕上出现这几个字，不需要画面内容）。

这些信息由**图层卡片**（年份卡 / 数据卡 / 时间轴）直接写在画面上，不需要再找素材。

**反过来说**：任何需要观众「看见一个东西/一个地方/一个人」的信息点，
哪怕它同时带着数字，也**不能**判 `not_needed`。宁可列成缺失让人去补，也不要替人省掉。

## 3. 颗粒度

- 一段旁白通常产出 **2–6 条**。不要把整段压成一条，也不要把一句话拆成五条。
- 同一段里重复出现的同一个东西只列一条。
- 一条只要一份素材。需要「地图 + 实景」两份，就写两条。

## 4. 匹配已有素材

- 名字按**清单里的原文**写，大小写、括号、全半角都照抄。
- `prop_faithful` 只能匹配清单里标了「证据素材」的那些；普通生成图不算。
- 吃不准能不能顶上就**留空**（判为缺失）——漏判缺失比错判已有更容易被人发现和纠正。
