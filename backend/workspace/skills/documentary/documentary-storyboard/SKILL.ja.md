# ドキュメンタリープロジェクト：絵コンテ追加仕様（ナレーション骨格 → 実測音声 → 設計カード）

`storyboard-breaker` の基本仕様の上に重ねられる。矛盾する場合は**本ファイルを優先**する。

ドキュメンタリーの分解は、実際の音声合成を挟んだ**二つの連続した段階**からなる：

```
最終脚本本文
  → 【第1段階】ナレーション骨格：逐語分割してショットごとの narration_text + タイトルへ（save_storyboards）
  → 人間が骨格を確認
  → 一括 TTS：各ショットに**実測**の音声長が付く
  → 【第2段階】設計カード：実測時間に基づき情報点／レイヤー段／生成段／予算を設計（update_storyboard）
```

**第1段階は視覚設計を一切産出しない**：実測時間がなければ、どんな段の予算も推測にすぎない。
**第2段階はナレーション本文を変更しない**：境界は第1段階で確定し、すでに音声化されている。一文字の変更が音声を無効にする。

いま自分がどちらの段階かは、ツールと指示で分かる：`save_storyboards` を呼ぶ＝第1段階、
「設計カードを書け」と指示され `update_storyboard(storyboard_id, design_card)` のみ許される＝第2段階。

# 第1段階：ナレーション骨格

## 1.1 ナレーション欄 = 脚本本文の逐語コピー（ハードルール）

本プロジェクトの脚本本文は**そのままナレーション原稿**である。本文を順に区切り、各区間を**原文のまま** `narration_text` に書く：

- **逐語コピー**：句読点・年号・人名・地名・数字をすべて原文と一致させる。書き換え・推敲・省略・加筆は一切不可。
- **文単位で切る**：句点／疑問符／感嘆符／セミコロンの直後でのみ切る。文の途中で切ってはならない。
- **追加も欠落も不可**：本文の全段落がいずれかのショットに収まること。全ショットの `narration_text` を順に連結すると脚本本文に一致する。
  `save_storyboards` は毎回 `script_coverage.gaps` と `must_fix` を返す：**隙間が残る限りショットを足し続ける**。
  文の境界で新しい `shot_number` を挿入し、漏れた文を逐語で取り込む。隙間を残したまま終えるとタスク全体が失敗になる。
- 1ショット **80 文字以内**（音声合成の1セグメント硬性上限）。原文の段落が 80 文字を超える場合は文の境界で隣接2ショットに分ける。
- ツールが検証する：`narration_text` は脚本本文中に逐語で見つかり、かつ本文と同じ順序でなければならない。書き換えた文は**保存拒否**される。

## 1.2 サーバが強制する3つの拒否ルール

違反ショットは黙って修正されず、**保存拒否**され理由付きで `rejected[]` に並ぶ。`rejected[]` を見たら理由に従って直し、再保存する。

1. **本話のショット数の硬性上限**：`cap = max( min(ceil(ナレーション段落数 × 1.5), ナレーション段落数 + 3), 各段落の ceil(段落文字数 / 80) の合計 )`。
   「ナレーション段落数」＝脚本本文を空行で分割した非空段落の数。`cap` を超えるショットは一律拒否。
   長い段落を 80 字上限のために複数ショットへ分割する場合、上限はその分だけ引き上げられる（文字数ベースの引き上げであり、文境界での分割が必ず収まることを保証するものではない）。
   テンポのために細かく切りたいときは、ショットを増やすのではなく隣接する短文をまとめる。
2. **各ショットは必ずナレーションを担う**：`narration_text` が空なら拒否。ドキュメンタリーに無音の画面のみのショットは存在しない。
   空ショット、トランジション、地図の定場も一区間のナレーションを担う。
3. **同じナレーションを二つのショットが取ってはならない**：同一文（または重複区間）を取った時点で拒否。

## 1.3 この段階で書くのは4項目だけ

`save_storyboards` のドキュメンタリー用スキーマが受け取るのは：

- `shot_number`：ショット番号。
- `narration_text`：本ショットのナレーション（逐語、1.1 参照）。
- `title`：本ショットの主情報点を一文で（「イルティシュ川が唯一の水路である」「近衛連隊出身が指揮権を決めた」）。
- `continuity`：`continue` / `cut`。前ショットとの接続。判断がつかなければ送らない。

**設計カード・画面描写・キーフレームプロンプト・動画プロンプト・尺・アセット紐付けは一切書かない**。
それらは第2段階に属し、第2段階はこのショットが実際に音声化され実測秒数が得られてから始まる。
いま書ける秒数はすべて推定であり、**本ワークフローは推定を受け付けない**。

## 1.4 一ショット一情報点

ショットの境界は尺ではなく**情報点**が決める：一ショットで一つのことを言い切り、言い終わったら切る。
`title` の一文は第2段階で `design_card.info_points[0].text` になる。

情報点と画面が噛み合わないときは、第2段階で**画面を直す**。ナレーションに戻って直してはならない。

# 第2段階：実測ナレーション時間に基づく設計カード

## 2.1 前提（サーバが強制、迂回不可）

- 本話の**ナレーション骨格が人間によって確認済み**であること；
- 本ショットに**現在有効な音声がある**こと：本文・発音マークアップ・現在有効な音声パラメータが音声と一致し、
  音声ファイルが存在し、そこから有限の正の時間が実測されていること。

指示には本ショットの**実測音声秒数**が明示される。これはファイルから測った事実であり、文字数からの推定ではない：
**予算は必ずこれに従う**。「毎秒 4.5 文字」の推定口径はこの段階では使わない。

## 2.2 設計カード `design_card`（全ショット必須）

画面を書く前に次の連鎖をたどり、結論を `design_card` に記す：

```
このショットで観客に届ける情報（info_points[]、12 件以内）
  → どれをレイヤー段が描くか（layer_plan：ベース画像 base ＋ 必須注記 must_mark[] ＋ 計画レイヤー planned_layers[]）
  → どれを生成段が演じるか（gen_plan：参照アセット reference_assets[] ＋ 先頭/中間/末尾フレームの描写）
  → 各段の秒数（budget：layer_s / gen_s）。合計は実測音声時間以上でなければならない
  → なぜそう配分したか（rationale、600 字以内）
```

### 2.2.1 `info_points[]`：伝える情報と、その担い手

各項目 `{ id, text, via }`、最大 12 件：

- `id`：ショット内で一意の短い識別子（`p1`、`p2`…）。`planned_layers` や `rationale` から参照できる。
- `text`：その情報を一文で（「ジュンガルの支配範囲はバルハシ湖まで及ぶ」）。
- `via ∈ layer | generated | narration_only`：
  - `layer` —— レイヤー段がベース画像上に示す（範囲・経路・地点・ネームバー・年代）。
  - `generated` —— 生成段が演じる（出発・行軍・交戦・謁見のような過程のある出来事）。
  - `narration_only` —— ナレーションのみが担い画面は負担しない。多用禁物。多すぎる場合は画面が働いていない。

すべての情報点に担い手が必要。担い手のない項目は `info_point_unassigned`（警告）になる。

### 2.2.2 `layer_plan`：レイヤー段の計画

- `base`：レイヤー段のベース画像。既存素材の具体的なバージョンを指す `{kind:'asset', asset_kind, asset_id, version_task_id}`、
  または前ショットのベースを引き継ぐ `{kind:'inherit_prev'}`（同一の語りの段では連続するショットが**同じ証拠素材を共有**し、
  レイヤー状態だけを変える：S01 で三者の範囲、S04 で河川、S07 で経路。毎ショット地図を差し替えない）。
- `must_mark[]`：本ショットでベース画像上に必ず示す意味項目。各項目 `{ asset_id, semantic_id, name }` を
  `read_storyboard_context` が返す `semantics` 一覧から**逐語コピー**する（`asset_id` ＋ `id` ＋ `name` の三点すべて一致）。
  名称を創作すると `unresolved` と判定され設計カード画面で赤くなる。書かなかったのと同じである。
  ナレーションに現れる地名・水系・湖・城塞・政権範囲・経路はここに対応項目が見つかるはずである。
  図に本当に無い場合は無理に合わせず、`rationale` に「ナレーションは X に言及するが、アセット N の注記に X が無い」と書き、
  素材を替えるか生成段に移す。必要なら `read_image` で原図を確認する。
- `planned_layers[]`：どのレイヤーをどの順で出すか。各項目
  `{ type, text?, anchor?: {asset_id, semantic_id, name}, at_s }`：
  - `type ∈ polygon | polyline | marker | label | card | image`
    （範囲ハイライト／河川・経路・矢印／地点／地名・年代の文字／ネームバー・年カード／挿入小図）。
  - `anchor` は `must_mark` と同じ意味項目を指す。文字レイヤーは `text` に表示文字を書く。
  - `at_s`：レイヤー段の何秒目に出すか。**実測音声のタイムラインで組む**：ナレーションが先に言うものを先に出す。
    「同時に」「二手に分かれて」は**同じ `at_s` の二レイヤー**で、「まず…次に…」は異なる `at_s` で表す。
    `at_s` は当該段の `layer_s` を超えてはならない。
- `must_mark` の各項目は少なくとも1つの `planned_layers` で描かれるべきで、欠けると `must_mark_not_planned`（警告）になる。
- レイヤー段を持つショット（組み合わせ A / C / D）は `base` 必須。無ければ `missing_base` でブロックされる。

### 2.2.3 `gen_plan`：生成段の計画

- `reference_assets[]`：生成段が必ず使う参照アセット（`{kind, id, name}`、アセット単位）。
  プロンプト作成の工程で一件ずつ照合され、`@アセット名` で参照されない参照アセットは生成をブロックする。
  ナレーションが言及するが本ショットに登場しない組織・遠隔地の人物・遠隔地の出来事には、
  `read_storyboard_context` の `exposition_assets` にある視覚的担体アセットを使う。
  例：「彼はセミョーノフスキー近衛連隊の出身で、その連隊はピョートル1世が自ら創設した」なら、
  画面には近衛連隊の視覚的担体とピョートル1世の肖像が同時に必要であり、空の練兵場に立つ一人ではない。
- `first` / `mid` / `last`：三つのスロットの画面描写（一文でよい。正式なプロンプトは後工程が書く）。
  接続フレームはレイヤー段が継承しロックするので**書かない**：組み合わせ C は `first` を、D は `last` を省く。
- 地理関係を生成段で演じさせない：空き地を歩く人では「イルティシュ川を遡上する」を表現できない。それはレイヤー段の仕事である。

### 2.2.4 組み合わせ提案 `suggested_combo`：提案のみ、決定はしない

- 書くのは `suggested_combo ∈ A | B | C | D` だけ。**`combo` は書かない**：サーバはモデルの送る `combo` を必ず無視し、
  段の組み合わせは人間が選ぶ。`rationale` に提案理由を一文で書く。
- 四つの組み合わせの判断基準：
  - **A**「地図／原資料への注記とパン：『どこ・誰・何年』を語る」
  - **B**「AI 生成ショット：『何が起きたか』を語る」
  - **C**「まず位置づけ、それから場面へ」
  - **D**「まず場面、それから地図／文書へ着地」
- A はレイヤー段 ▣ のみ、B は生成段 ▶ のみ、C = レイヤー ▣ → 生成 ▶、D = 生成 ▶ → レイヤー ▣。
  C の生成段の先頭フレームと D の末尾フレームは**接続フレーム ◆** であり、隣接するレイヤーのフレームを継承してロックされる。

### 2.2.5 `budget`：各段の秒数（実測音声が基準）

- `layer_s ≤ 30`、`gen_s ≤ 15` は硬性上限。超過した設計カードはサーバが**保存を拒否**する。
- 提案した組み合わせに従って記入：A は `layer_s` のみ（`gen_s` は null）、B は `gen_s` のみ、C / D は両方。
- **両段の合計は、指示にある実測音声秒数以上でなければならない。** 収まらない場合：
  - 各段の上限を超えない範囲で画面を長くしてよい；
  - 予算に合わせてナレーションを切り詰める・圧縮する・書き換えることは**絶対に不可**。すでに音声化済みであり、
    文字の変更は音声の無効化を意味する；
  - どうしても収まらない場合（例：実測 40 秒に対し組み合わせの上限が足りない）は `rationale` に衝突を明記し、
    人間が骨格段階に戻って切り直せるようにする。

### 2.2.6 `rationale`

600 字以内で、情報点の配分理由、組み合わせの提案理由、前ショットから何を引き継いだか
（「前ショットで出た船団を受け、本ショットは目的地だけを示す」）、および素材不足・注記不足・予算衝突を明記する。

## 2.3 画面の規律

- 画面描写に**ナレーション本文を書かない**。「ナレーション：…」も書かない。ナレーションは専用フィールドを持ち、二重に書くと二度読まれる。
- ドキュメンタリーに**セリフは無い**：`役名：「セリフ」` は禁止。画面の人物に解説を喋らせてはならない。
- 画面には観客が実際に見るものを書く：主体、動作、ショット内の変化（広げられる地図、行進する隊列、めくられる文書）。

## 2.4 尺とビート

- 本ショットの尺 = `budget.layer_s` + `budget.gen_s`（存在しない段は 0）。かつ実測音声時間以上であること。
- 各段の上限は硬性：レイヤー段 30 秒以内、生成段 15 秒以内。
- 脚本中の `【ビート名】` 表記はハードカットの境界であり、1ショットがビートをまたいではならない（第1段階の分割時点で守る）。
- 尺合わせのために二つの主情報点を1ショットへ詰め込まない。一文を二ショットに分けて読ませない。
