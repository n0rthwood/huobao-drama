# ドキュメンタリープロジェクト：絵コンテ分解追加仕様（二段組脚本 + 設計カード）

`storyboard-breaker` の基本仕様の上に重ねられる。矛盾する場合は**本ファイルを優先**する。

ドキュメンタリーの絵コンテは**二段組脚本**である：左段はナレーション（何を語るか）、右段は画面（何が見えるか）。両段は一対一に対応し、同一ショット内では同じ事柄を扱わなければならない。

## 1. ナレーション欄 = 脚本本文の逐語コピー（ハードルール）

本プロジェクトの脚本本文**こそがナレーション原稿**である。分解時は本文を順に段落へ切り分け、各段落を**原文どおり** `narration_text` に書き込む：

- **逐語コピー**：句読点、年代、人名、地名、数字はすべて原文と一致させる。書き換えない、推敲しない、省略しない、語を補わない。
- **文境界で切る**：句点 / 疑問符 / 感嘆符 / セミコロンの後でのみ切ってよく、文の途中で切ってはならない。
- **追加しない、落とさない**：本文のすべての段落はいずれかのショットに収まらなければならず、全ショットの `narration_text` を順に連結すると本文と一致しなければならない。
  `save_storyboards` は呼び出しごとに `script_coverage.gaps` と `must_fix` を返す：**欠落が残っているうちはショットを補い続ける**こと。
  文境界に新しい `shot_number` を挿入し、抜けた文を逐語的に切り込む。欠落を残したまま終えると、絵コンテ分解タスク全体が失敗と判定される。
- 各ショット **≤80 字**（音声合成の一段あたりのハード上限）。原文の段落が 80 字を超える場合は、文境界で隣接する二つのショットに分割する。
- ツールが検証する：`narration_text` は脚本本文に逐語で見つかり、順序も本文と一致しなければならない。書き換えたテキストは**保存を拒否**される。

### 1.1 サーバーが強制する三つの保存拒否ルール

違反したショットは黙って修正されず、**保存を拒否**され、戻り値の `rejected[]` に理由付きで列挙される。`rejected[]` を見たら理由に従って書き直して保存し直す。

1. **本エピソードのショット総数ハード上限**：`cap = min(ceil(ナレーション段落数 × 1.5), ナレーション段落数 + 3)`。
   「ナレーション段落数」= 脚本本文を空行で分割した非空段落の数。`cap` を超えたショットは一律拒否される。
   細かく切りたいときはショット数を増やすのではなく、隣接する短文を併合する。
2. **各ショットは必ず一段のナレーションを担う**：`narration_text` が空だと拒否される。ドキュメンタリーに無音の画面のみショットはない。
   空景、トランジション、地図の定場も一段のナレーションを受け取る。
3. **同一のナレーション段落を二つのショットが重複して受け取れない**：同じ文を二ショットが受け取る（または重なる）と拒否される。

## 2. 画面欄 = `description` は画面のみ（ハードルール）

- `description` にナレーション本文を書かない。「ナレーション：…」も書かない。ナレーションには独立フィールドがあり、二重に書くと二回読み上げられる。
- ドキュメンタリーに**セリフはない**：`キャラクター名：「台詞」` は禁止。画面内の人物に解説を口から言わせることも禁止。
- `description` は視聴者が実際に見るものを書く：主体、動作、フレーム内の変化（広げられる地図、行進する隊列、繰られる文書）。

## 3. 一ショット一情報点

分解の境界は**情報点**で決まり、長さでは決まらない：一つのショットで一つの事柄をはっきり語り、語り終えたら切る。

各ショットは `title` に一文で主たる情報点を明記する（「額尔齐斯河（イルティシ川）が唯一の水路である」「近衛連隊出身であることが指揮権を決めた」）。
同じ文が `design_card.info_points[0].text` になる。画面はその情報点を**表示できなければならない**。

情報点と画面が合わない場合は**画面を直す**。ナレーションを直さない。

## 4. 絵コンテ設計カード `design_card`（各ショットで必須）

ここがドキュメンタリー絵コンテとドラマ絵コンテの最大の相違点である：**まずこのショットをどう作るかを決め、それから画面を書く**。
`description` を書く前に、次の連鎖をたどり、結論を `design_card` に書き込む：

```
このショットが伝える情報は何か（info_points[]、≤12 件）
  → そのどれをレイヤー段が描くか（layer_plan：ベース base + 必須標示 must_mark[] + 計画レイヤー planned_layers[]）
  → そのどれを生成段が演じるか（gen_plan：参照素材 reference_assets[] + 先頭/中間/末尾フレーム）
  → 各段が何秒を取るか（budget：layer_s / gen_s）
  → なぜそう配分したか（rationale、≤600 字）
```

### 4.1 `info_points[]`：このショットが伝える情報、担い手を明記する

各項目は `{ id, text, via }`、最大 12 件：

- `id`：ショット内で一意の短い識別子（`p1`、`p2`…）。`planned_layers` や `rationale` から参照できる。
- `text`：その情報を一文で書く（「ジュンガルの支配範囲はバルハシ湖まで」）。
- `via ∈ layer | generated | narration_only`：
  - `layer` —— レイヤー段がベース画像上に標示する（範囲、経路、地点、ネームバー、年代）。
  - `generated` —— 生成段が演じる（出発、行進、交戦、謁見のような過程のある事件）。
  - `narration_only` —— ナレーションだけが担い、画面は担わない。多用しない。多すぎるのは画面が働いていない証拠である。

すべての情報点に担い手が必要である。担い手のない項目は `info_point_unassigned`（警告）になる。

### 4.2 `layer_plan`：レイヤー段の計画

- `base`：レイヤー段のベース画像。既存素材の具体的なバージョンを指す `{kind:'asset', asset_kind, asset_id, version_task_id}`、
  または前ショットのベース画像を受け継ぐ `{kind:'inherit_prev'}`（同一叙事セグメントの連続ショットは**同じ証拠素材を共用**し、
  レイヤー状態だけを変える：S01 で三方の範囲、S04 で河川、S07 で経路。ショットごとに地図を替えない）。
- `must_mark[]`：ベース画像上に必ず標示する語義項目。各項目は `{ asset_id, semantic_id, name }` で、
  `read_storyboard_context` が返す `semantics` リストの項目を**逐語的にコピー**する（`asset_id` + `id` + `name` の三つとも一致させる）。
  自分で名前をでっち上げると `unresolved` と判定され、設計カードのページで赤く表示され、書かないのと同じになる。
  ナレーションに現れる地名 / 水系 / 湖 / 城砦 / 政権の範囲 / 経路はここに対応項があるべきである。
  地図に本当にその項がない場合は無理に合わせず、`rationale` に「ナレーションは X に触れるが、素材 N の注釈に X がない」と明記し、素材を替えるか生成段に任せる。
  必要なら `read_image` で原本を開いて実際にあるか確認する。
- `planned_layers[]`：どのレイヤーをどの順で現すか。各項目は
  `{ type, text?, anchor?: {asset_id, semantic_id, name}, at_s }`：
  - `type ∈ polygon | polyline | marker | label | card | image`
    （範囲ハイライト / 河川・経路・矢印 / 地点 / 地名・年代テキスト / ネームバー・年カード / 埋め込み小図）。
  - `anchor` は `must_mark` と同じ語義項を指す。文字レイヤーは表示する文字を `text` に書く。
  - `at_s`：レイヤー段内の何秒目に出現するか。ナレーションが先に語るものが先に現れる。
    「同時に」「二手に分かれる」は**同じ `at_s` の二レイヤー**で表現し、「先に…次に…」は異なる `at_s` で離す。
- すべての `must_mark` には少なくとも一つの `planned_layers` が対応して描くべきである。欠けると `must_mark_not_planned`（警告）になる。
- レイヤー段を持つショット（組み合わせ A / C / D）は `base` を必ず指定する。無ければ `missing_base` で阻害される。

### 4.3 `gen_plan`：生成段の計画

- `reference_assets[]`：生成段が必ず使う参照素材（`{kind, id, name}`、素材レベル）。
  プロンプト作成の工程が一件ずつ照合する：`@素材名` で参照されていない参照素材は生成を阻害する。
  ナレーションで触れられるが本ショットに登場しない組織 / 離れた場所の人物 / 離れた場所の出来事は、
  `read_storyboard_context` の `exposition_assets` にある視覚的担体素材を使う。
  例：ナレーションが「彼は谢苗诺夫近卫团（セミョノフスキー近衛連隊）の出身で、その近衛連隊は彼得一世（ピョートル一世）が自らの手で創設した」と語るなら、
  画面には近衛連隊の視覚的担体とピョートル一世の肖像の両方がなければならない。空の練兵場に一人立っているだけではならない。
- `first` / `mid` / `last`：三つのスロットの画面記述（一文でよい。正式なプロンプトは後工程が書く）。
  衔接フレームはレイヤー段から継承され固定されるので**書かない**：組み合わせ C は `first` を、組み合わせ D は `last` を書かない。
- 地理的関係を生成段で演じさせない：空き地を歩く一人では「額尔齐斯河（イルティシ川）をさかのぼって北上」は表現できない——それはレイヤー段の仕事である。

### 4.4 組み合わせの提案 `suggested_combo`：提案のみ、決定しない

- 書くのは `suggested_combo ∈ A | B | C | D` だけである。**`combo` を書かない**：サーバーはモデルが送った `combo` を無視し、
  段の組み合わせは人間が選ばなければならない。なぜその提案かを `rationale` に一文で述べる。
- 四つの組み合わせの判定基準（この口径どおりに判断する）：
  - **A** 「地图/原件上标注与推拉：讲『在哪里·是谁·哪一年』」（地図/原本への標示とプッシュ：「どこ・誰・何年」を語る）
  - **B** 「AI 生成镜头：讲『发生了什么』」（AI 生成ショット：「何が起きたか」を語る）
  - **C** 「先定位再入戏」（まず位置を決め、それから芝居に入る）
  - **D** 「先入戏再落到地图/档案」（まず芝居に入り、それから地図/アーカイブに落とす）
- A はレイヤー段 ▣ のみ；B は生成段 ▶ のみ；C = レイヤー段 ▣ → 生成段 ▶；D = 生成段 ▶ → レイヤー段 ▣。
  C の生成段の先頭フレーム、D の生成段の末尾フレームは**衔接フレーム ◆** であり、隣接するレイヤー段のフレームを継承して固定される。

### 4.5 `budget`：各段の秒数

- `layer_s ≤ 30`、`gen_s ≤ 15` はいずれもハード上限である。超えた設計カードはサーバーが**書き込みを拒否**する。
- 提案した組み合わせに合わせて書く：A は `layer_s` のみ（`gen_s` は null）；B は `gen_s` のみ；C / D は両方。
- 両者の和はナレーション推定長 **以上**でなければならない：ナレーション字数 ÷ **4.5 字/秒** + **0.8 秒**の末尾余白。
  収まらない場合は文境界で隣接する二つのショットに分割する。予算を圧縮しない。

### 4.6 `rationale`

≤600 字。情報点をなぜそう割り当てたか、なぜその組み合わせを提案するか、前ショットから何を受け継いだか
（「前ショットで出現済みの船隊を受け継ぎ、本ショットは目的地を示すだけ」）、素材や注釈の不足があればそれも書く。

## 5. 長さとビート

- `duration` = `budget.layer_s` + `budget.gen_s`（存在しない段は 0）。かつナレーション推定長
  （ナレーション字数 ÷ 4.5 字/秒 + 0.8 秒の末尾余白）以上でなければならない。
- 段ごとの上限はハードである：レイヤー段 ≤30 秒、生成段 ≤15 秒。一ショットに収まらなければ文境界で分割する（§1.1 のショット数上限にも注意）。
- 脚本中の `【拍名】` マーカーはハードな切断境界である：一つのショットがビートをまたいではならない。
- 長さを合わせるために二つの主情報点を一つのショットに詰め込んではならないし、一文を二つのショットに分けて読ませてもならない。
