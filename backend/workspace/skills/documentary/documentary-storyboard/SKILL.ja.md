# ドキュメンタリープロジェクト：絵コンテ分解追加仕様（二段組脚本 + 表現設計）

`storyboard-breaker` の基本仕様の上に重ねられる。矛盾する場合は**本ファイルを優先**する。

ドキュメンタリーの絵コンテは**二段組脚本**である：左段はナレーション（何を語るか）、右段は画面（何が見えるか）。両段は一対一に対応し、同一ショット内では同じ事柄を扱わなければならない。

## 1. ナレーション欄 = 脚本本文の逐語コピー（ハードルール）

本プロジェクトの脚本本文**こそがナレーション原稿**である。分解時は本文を順に段落へ切り分け、各段落を**原文どおり** `narration_text` に書き込む：

- **逐語コピー**：句読点、年代、人名、地名、数字はすべて原文と一致させる。書き換えない、推敲しない、省略しない、語を補わない。
- **文境界で切る**：句点 / 疑問符 / 感嘆符 / セミコロンの後でのみ切ってよく、文の途中で切ってはならない。
- **追加しない、落とさない**：本文のすべての段落はいずれかのショットに収まらなければならず、全ショットの `narration_text` を順に連結すると本文と一致しなければならない。
  `save_storyboards` は呼び出しごとに `script_coverage.gaps` と `must_fix` を返す：**欠落が残っているうちはショットを補い続ける**こと。
  文境界に新しい `shot_number` を挿入し、抜けた文を逐語的に切り込む。欠落を残したまま終えると、絵コンテ分解タスク全体が失敗と判定される。
- 各ショット **≤80 字**（音声合成の一段あたりのハード上限）。原文の段落が 80 字を超える場合は、文境界で隣接する二つのショットに分割する。
- 画面のみのショット（空景、トランジション、地図の定場）はナレーションがなくてよい：`narration_text` を空にするだけで、解説をでっち上げない。
- ツールが検証する：`narration_text` は脚本本文に逐語で見つかり、順序も本文と一致しなければならない。書き換えたテキストは**保存を拒否**される。

## 2. 画面欄 = `description` は画面のみ（ハードルール）

- `description` にナレーション本文を書かない。「ナレーション：…」も書かない。ナレーションには独立フィールドがあり、二重に書くと二回読み上げられる。
- ドキュメンタリーに**セリフはない**：`キャラクター名：「台詞」` は禁止。画面内の人物に解説を口から言わせることも禁止。
- `description` は視聴者が実際に見るものを書く：主体、動作、フレーム内の変化（広げられる地図、行進する隊列、繰られる文書）。

## 3. 一ショット一情報点

分解の境界は**情報点**で決まり、長さでは決まらない：一つのショットで一つの事柄をはっきり語り、語り終えたら切る。

各ショットは `title` に一文で情報点を明記する（「額尔齐斯河（イルティシ川）が唯一の水路である」「近衛連隊出身であることが指揮権を決めた」）。
同じ文を `intent.info_point` にも書く。画面はその情報点を**表示できなければならない**。

情報点と画面が合わない場合は**画面を直す**。ナレーションを直さない。

## 4. 表現設計 `intent`（各ショットで必須）

ここがドキュメンタリー絵コンテとドラマ絵コンテの最大の相違点である：**まず表現方法を決め、それから画面を書く**。
`description` を書く前に、次の連鎖をたどり、結論を `intent` に書き込む：

```
このショットで視聴者に何を理解させるか（info_point、一つだけ）
  → どの手段で表現するか（device）
  → そのために画面に何が具体的に見えていなければならないか（must_show）
  → それらをどのレイヤーで描き、どの順で現すか（overlay_plan）
  → なぜそう選んだか（rationale）
```

### 4.1 `device`：五つの表現手段、ナレーションの性質で選ぶ

| device | どんなナレーションに使うか | 画面は何か |
|---|---|---|
| `map_anim` | 地理、経路、範囲、同時に進む二つの系 | 証拠地図 + ハイライト/矢印/ラベルの逐層出現 |
| `archival` | 条約、文書、版画、器物の原本 | アーカイブ原本そのもの + ゆっくりとしたプッシュイン + ラベル |
| `card` | 人物の初登場、年代、章の転換 | 肖像/静止画 + ネームバー（氏名/肩書/年代） |
| `reenact_still` | 静的な状態、肖像、物件、動作のない状況 | 生成した再現静止画 + ゆっくりとしたプッシュイン |
| `reenact_video` | **過程があり動きのある事件**（出発、行進、遡行、銃火を交える、包囲、乗船、築造、謁見、護送） | 生成モデル動画 |

判定基準：**ナレーションが語っているのは「どこか」「何であるか」「何をしたか」のどれか**。
「どこ / どの範囲 / どの道を」はすべて `map_anim`；身分・出自・年代・数字だけなら `card` か `archival`；
**文中に進行中の動作や過程を表す動詞があれば `reenact_video` を使い、`reenact_still` に格下げしない**。

`reenact_still` は**画面に実際に動作がない**ショット（肖像、器物、空き場、静止した状況）だけに使う。
「船隊が流れをさかのぼる」「大軍がラサ（拉萨）へ進軍する」「偵察隊が船で出発する」「双方が交戦する」のような文は `reenact_video` に属する。
これらを静止画にすると、ドキュメンタリーで唯一動く部分まで凍らせることになる——一つのエピソードに `reenact_video` が一つもなければ、
ほぼ確実に誤判定である。動作を含むナレーションを一文ずつ見直すこと。

`reenact_video` の `deterministic` はデフォルト `none`（ショット全体がモデル動画）；モデル動画の前後に短い
決定論的レイヤークリップを継ぎ足す必要がある場合（例：先に年カードを出す、末尾に地図の小図を圧する）だけ `pre` / `post` を提案する。

地理的関係を `reenact_*` で演じさせない：空き地を歩く一人では「額尔齐斯河（イルティシ川）をさかのぼって北上」は表現できない。

### 4.2 `must_show`：ナレーション中の具体的な名詞はすべて画面に落とす

- ナレーションに現れる**地名 / 水系 / 湖 / 城砦 / 政権の範囲 / 経路**は、いずれかの証拠素材の
  **セマンティック注釈**（`read_storyboard_context` の `props[].semantics`）に対応項がなければならず、`must_show` に書き込む：
  - 区域 → `{kind:'region', asset_id, semantic:'准噶尔汗国'}`
  - 河川/境界/経路の線 → `{kind:'line', asset_id, semantic:'额尔齐斯河'}`
  - 都市/地点 → `{kind:'point'|'label', asset_id, semantic:'斋桑湖'}`
  - 行軍経路 → `{kind:'route', asset_id, from:'西宁', to:'拉萨'}`（両端ともその地図に注釈済みの地名であること）
- `semantic` は `semantics` リストの `name`（またはその `id`）から**逐語的に**取る。自分で名前をでっち上げると
  `unresolved` と判定され、表現設計ページで赤く表示され、書かなのと同じになる。
- 地図に**その項がない**場合は無理に合わせない：`rationale` に「ナレーションは X に触れるが、素材 N の注釈に X がない」と明記し、
  このショットを格下げする（device を変えるか素材を変える）。必要なら `read_image` で原本を開いて実際にあるか確認する。
- **人物の初登場** → `device='card'`、`must_show` は `{kind:'portrait', asset_id:<キャラクター id>}` を伴い、
  `overlay_plan` に `card` レイヤーを置く（フィールドに氏名/肩書/年代）。
- **ナレーションで触れられるが本ショットに登場しない組織 / 離れた場所の人物 / 離れた場所の出来事** →
  `read_storyboard_context` の `exposition_assets` を参照する：`{kind:'exposition', asset_id:<その担体素材>}`。
  例：ナレーションが「彼は谢苗诺夫近卫团（セミョノフスキー近衛連隊）の出身で、その近衛連隊は彼得一世（ピョートル一世）が自らの手で創設した」と語るなら、
  画面には近衛連隊の視覚的担体とピョートル一世の肖像の両方がなければならない。空の練兵場に一人立っているだけではならない。

### 4.3 `overlay_plan`：地図ショットのオーバーレイレイヤーを空にしない

- `device='map_anim'` のとき `overlay_plan` は**空であってはならない**。地図を平面のままプッシュ/パンするのは地図アニメーションではなく、
  まさに本プロジェクトが排除しようとしている誤りである。
- レイヤー型は `polygon`（範囲ハイライト）、`polyline`（河川/経路/矢印）、`marker`（地点）、
  `label`（地名/年代テキスト）、`card`（ネームバー/年カード）、`image`（埋め込み小図）のみから取る。
- 各レイヤーはできるだけ `anchor:{asset_id, semantic_id}` を伴い（`must_show` と同じセマンティック項を指す）、
  `reveal_at`（秒）で出現順を並べる：ナレーションが先に語るものが先に現れる。
- 「同時に」「二手に分かれる」のような並列関係は**同じ時点で二つのレイヤーを出現させる**ことで表現し、「先に…次に…」は `reveal_at` で離す。
- 全体図から局部へプッシュする必要があるときは `viewport:[x,y,w,h]`（正規化 0–1）を使う。

### 4.4 `deterministic`：自分でデフォルトを決めない

クリップ位置はプログラムが device で表を引いて決める（`map_anim/archival/card/reenact_still` → `replace`、
`reenact_video` → `none`）。`pre`/`post`（モデル動画の前後に短い決定論的クリップを継ぎ足す）を提案してよいのは `reenact_video` だけである。
それ以外の場合は**このフィールドを書かない**；範囲外の値はサーバーに捨てられ、デフォルトに戻される。

### 4.5 叙事セグメントの文脈

- `read_storyboard_context` を呼ぶとき、前後ショットの `intent` も読む。同一叙事セグメント（同じベース地図上の連続ショット）は
  **同じ証拠素材を共用**し、レイヤー状態だけを変えなければならない：S01 で三方の範囲、S04 で河川、S07 で経路を出す。
  ショットごとに地図を替えない。
- 後のショットが前のショットを受け継ぐときは、`rationale` に何を受け継いだか明記する（「前ショットで出現済みの船隊を受け継ぎ、本ショットは目的地を示すだけ」）。

## 5. 長さとビート

- `duration` = 当該ショットのナレーション字数 ÷ **4.5 字/秒** + **0.8 秒**の末尾余白、**4–15 秒**にクランプ。ナレーションなしの画面のみショットは 4–6 秒。
- 脚本中の `【拍名】` マーカーはハードな切断境界である：一つのショットがビートをまたいではならない。
- 長さを合わせるために二つの情報点を一つのショットに詰め込んではならないし、一文を二つのショットに分けて読ませてもならない。
