# 纪录片项目：分镜附加规范（旁白骨架 → 实测配音 → 设计卡）

叠加在 `storyboard-breaker` 基础规范之上，冲突时**以本文件为准**。

纪录片分镜分成**两个前后相继的阶段**，中间隔着一次真实的配音：

```
最终剧本正文
  → 【阶段一】旁白骨架：逐字切分成逐镜 narration_text + 标题（save_storyboards）
  → 人工确认骨架
  → 批量 TTS：每镜得到一个**实测**的配音时长
  → 【阶段二】设计卡：按实测时长排信息点 / 图层段 / 生成段 / 预算（update_storyboard）
```

**阶段一绝不产出视觉设计**：没有实测时长，任何段预算都是猜的。
**阶段二绝不改旁白文字**：旁白的边界在阶段一已经定稿并配过音，改字等于作废音频。

你被调用时属于哪个阶段，看工具与指令：调用 `save_storyboards` = 阶段一；
指令要求「填写设计卡」且只允许 `update_storyboard(storyboard_id, design_card)` = 阶段二。

# 阶段一：旁白骨架

## 1.1 旁白栏 = 剧本正文逐字照抄（硬规则）

本项目的剧本正文**就是旁白稿**。拆镜时按顺序把正文切成段，逐段**原样**写进 `narration_text`：

- **逐字照抄**：标点、年份、人名、地名、数字全部与原文一致。不改写、不润色、不缩写、不补字。
- **按句切**：只能在句号 / 问号 / 感叹号 / 分号之后切开，不许在半句处断。
- **不新增、不丢段**：正文每一段都要落到某一镜；全集 `narration_text` 顺序拼接后应当等于剧本正文。
  `save_storyboards` 每次返回 `script_coverage.gaps` 与 `must_fix`：**只要还有缺口就继续补镜**，
  在句界处插入新的 `shot_number`，把漏掉的句子逐字切进去。带着缺口收工会让整次任务判失败。
- 每镜 **≤80 字**（语音合成单段硬上限）。原文某段超过 80 字，就在句界处拆成相邻两镜。
- 工具会校验：`narration_text` 必须能在剧本正文中逐字找到，且顺序与正文一致；改写过的文本会被**拒存**。

## 1.2 服务端强制的三条拒存规则

违规的镜不会被静默修正，而是被**拒存**并在返回里列进 `rejected[]`（带原因）。看到 `rejected[]` 就按原因改写后重新保存。

1. **本集镜头总数硬上限**：`cap = max( min(ceil(旁白段数 × 1.5), 旁白段数 + 3), 各段落 ceil(该段字数 / 80) 之和 )`，
   其中「旁白段数」= 剧本正文按空行切分后的非空段落数。超出 `cap` 的镜一律拒存。
   长段落按 80 字上限必须拆成多镜时，上限会相应抬高（但只按字数抬高，不保证句界切分一定装得下）。
   想按节奏多切镜时先合并相邻短句，而不是靠增加镜数。
2. **每一镜必须承载一段旁白**：`narration_text` 为空会被拒存。纪录片没有纯画面无声镜；
   空镜、过渡、地图定场同样要领一段旁白。
3. **同一段旁白不能被两镜重复领取**：两镜领同一句（或互相重叠）即拒存。

## 1.3 骨架这一步只写四个字段

`save_storyboards` 的纪录片 schema 只接受：

- `shot_number`：镜号。
- `narration_text`：本镜旁白（逐字照抄，见 1.1）。
- `title`：一句话写明本镜的主信息点（「额尔齐斯河是唯一水道」「近卫团出身决定了指挥权」）。
- `continuity`：`continue` / `cut`，与上一镜的衔接关系；拿不准就不传。

**设计卡、画面描述、关键帧提示词、视频提示词、时长、资产绑定一个都不要写**——它们属于阶段二，
而阶段二要等这一镜真的配完音、拿到实测秒数之后才开始。现在写出来的任何秒数都是估算，
而本流程**不接受估算**。

## 1.4 每镜一个信息点

拆镜的边界由**信息点**决定，不是由时长决定：一镜讲清楚一件事，讲完就切。
`title` 里的那句话，到阶段二会成为 `design_card.info_points[0].text`。

信息点与画面对不上，就在阶段二**改画面**，不要回头改旁白。

# 阶段二：按实测配音时长填设计卡

## 2.1 前置（服务端强制，不可绕过）

- 本集**旁白骨架已由人工确认**；
- **本镜已有当前有效配音**：文本、发音标记、当前生效的配音参数与音频一致，音频文件存在，
  并且实测出一个有限的正数时长。

指令里会直接给出这一镜的**实测配音时长（秒）**。那是文件探测出来的事实，不是按字数估算的数字：
**预算一律以它为准**。任何「按 4.5 字/秒估算」的口径在这一步都不适用。

## 2.2 设计卡 `design_card`（每一镜必填）

写画面之前先把下面这条链走完，结论写进 `design_card`：

```
这一镜要让观众接到哪些信息（info_points[]，≤12 条）
  → 哪些信息由图层段画出来（layer_plan：底图 base + 必须标出的语义 must_mark[] + 计划图层 planned_layers[] + 屏幕文字的成套位置 text_layout）
  → 哪些信息由生成段演出来（gen_plan：参考资产 reference_assets[] + 首/中/尾帧描述）
  → 两段各占多少秒（budget：layer_s / gen_s），两段之和必须 ≥ 实测配音时长
  → 为什么这样安排（rationale，≤600 字）
```

### 2.2.1 `info_points[]`：本镜要传达的信息，逐条标明由谁承担

每条 `{ id, text, via }`，最多 12 条：

- `id`：本镜内唯一的短标识（`p1`、`p2`…），`planned_layers`、`rationale` 里可以引用它。
- `text`：一句话写清这条信息（「准噶尔的控制范围到巴尔喀什湖」）。
- `via ∈ layer | generated | narration_only`：
  - `layer` —— 由图层段在底图上标出来（范围、路线、地点、姓名条、年代）。
  - `generated` —— 由生成段演出来（出发、行进、交火、觐见这类有过程的事件）。
  - `narration_only` —— 只由旁白讲，画面不承担；谨慎使用，一镜里 `narration_only` 过多说明画面没干活。

每条信息点都要有归属。没有归属的条目会被标成 `info_point_unassigned`（警告）。

### 2.2.2 `layer_plan`：图层段计划

- `base`：图层段的底图。取 `{kind:'asset', asset_kind, asset_id, version_task_id}` 指向一张已有素材的具体版本，
  或 `{kind:'inherit_prev'}` 承接上一镜的底图（同一叙事段的连续几镜**应当共用同一张证据素材**，只改图层状态：
  S01 出三方范围、S04 出河流、S07 出路线，而不是每镜换一张地图）。
- `must_mark[]`：本镜必须在底图上标出来的语义条目，每条 `{ asset_id, semantic_id, name }`，
  **逐字照抄** `read_storyboard_context` 返回的 `semantics` 列表里的条目（`asset_id` + `id` + `name` 三项都要对上）。
  自己编一个名字会被标成 `unresolved`，在设计卡页亮红，等于没写。
  旁白里出现的地名 / 水系 / 湖泊 / 城寨 / 政权范围 / 路线都应当在这里找到对应项；
  本集没有这条语义时，**不要**写一条留空的 `must_mark` 等人工补标注：要么改用该资产现有标注确实支持的表达，
  要么换一张真有这条标注的资产；都不行就按 2.2.7 说明缺口，不保存这张卡。
  必要时用 `read_image` 打开原图确认到底有没有。
- `planned_layers[]`：计划画哪些层、按什么顺序显现。每条
  `{ type, text?, anchor?: {asset_id, semantic_id, name}, role?, fields?, at_s }`：
  - `type ∈ polygon | polyline | marker | label | text | image`
    （范围高亮 / 河流·路线·箭头 / 地点 / 钉在语义位置上的地名 / 屏幕文字模板框 / 内嵌小图）。
  - **屏幕文字一律用 `text` 模板文本框**：`{ type:'text', role, fields }`，`role` 与 `fields` 的键逐字取自
    `read_storyboard_context` 的 `text_spec.roles`，字数上限取自同一份 `text_spec.capacity`；
    细节规则见 `layer-text-design` 技能（类型边界、成套位置、同屏与节奏、失败处置）。
    不再使用 `card`；`label` 只用于钉在底图语义位置上的文字，必须带 `anchor`。
  - `anchor` 指向与 `must_mark` 同一条语义项，且必须是**本镜底图那张资产、那个版本**上真实存在、
    类型相容、几何完整的条目：`polygon` / `polyline` 用带折点的 `region` 或 `line`（`polygon` ≥3 点、
    `polyline` ≥2 点），`marker` 用 `point`，带位置的 `label` 用 `label`。不指向画面上具体位置时不写 `anchor`。
  - `at_s`：该层在图层段内第几秒出现。**按实测配音的时间轴排**：旁白先说哪个，哪个先出现；
    「同时」「分两路」用**同一 `at_s` 的两层**表达，「先…后…」用不同 `at_s` 拉开。
    `at_s` 不得超过本段的 `layer_s`。
- `text_layout`：屏幕文字的成套位置（`text_spec.layouts` 里的 id）。有计划 `text` 层就必须选一套；
  先读底图主体位置再选（主体在右选左侧的套，主体在左选右侧的套）。同一 zone 里后出现的框替换先出现的
  （heading 2s → statement 4s 是同一条主叙事线），同一 `at_s` 的同区两个框才是冲突；
  `date` 可与主信息框同屏，`keyword` 只在概念必须被记住时叠加。
- 每一条 `must_mark` 都应当有至少一层 `planned_layers` 把它画出来；缺的会被标成 `must_mark_not_planned`（警告）。
- 有图层段的镜（组合 A / C / D）必须给出 `base`，否则阻断 `missing_base`。

### 2.2.3 `gen_plan`：生成段计划

- `reference_assets[]`：生成段必须用到的参考资产（`{kind, id, name}`，资产级）。
  写提示词的环节会逐条核对：没被 `@资产名` 引用的参考资产会阻断生成。
  旁白提到但本镜不出场的组织 / 异地人物 / 异地事件，用 `read_storyboard_context` 的 `exposition_assets` 里那个视觉载体资产。
  例：旁白说「他出身谢苗诺夫近卫团，那支近卫团是彼得一世亲手筹建的」，画面上必须同时有近卫团的视觉载体与彼得一世肖像，
  而不是一个人站在空操场上。
- `first` / `mid` / `last`：三个槽位的画面描述（一句话即可，正式提示词由后续环节写）。
  衔接帧由图层段继承、锁定，**不要写**：组合 C 不写 `first`，组合 D 不写 `last`。
- 不要用生成段去演地理关系：一个人在空地上走路表达不了「溯额尔齐斯河北上」——那是图层段的活。

### 2.2.4 段组合 `combo`

- 填写 `combo ∈ A | B | C | D`，可同时填写 `suggested_combo`；已有组合保留，由人工审阅或改选。
  `rationale` 里用一句话说明选择理由。
- 四种组合的判据（照此口径判断）：
  - **A** 「地图/原件上标注与推拉：讲『在哪里·是谁·哪一年』」
  - **B** 「AI 生成镜头：讲『发生了什么』」
  - **C** 「先定位再入戏」
  - **D** 「先入戏再落到地图/档案」
- A 只有图层段 ▣；B 只有生成段 ▶；C = 图层段 ▣ → 生成段 ▶；D = 生成段 ▶ → 图层段 ▣。
  C 的生成段首帧、D 的生成段尾帧是**衔接帧 ◆**，由图层段相邻那一帧继承并锁定。

### 2.2.5 `budget`：两段各多少秒（以实测配音为准）

- `layer_s ≤ 30`，`gen_s ≤ 15`，都是硬上限；超限的设计卡会被服务端**拒绝写入**。
- 按建议组合填：A 只写 `layer_s`（`gen_s` 置 null）；B 只写 `gen_s`；C / D 两段都写。
- **两段之和必须 ≥ 指令里给出的实测配音秒数**。装不下时：
  - 可以在不超过单段上限的前提下加长画面；
  - **绝不允许**为了迁就预算去截断、压缩或改写旁白——旁白已经配过音，改字等于作废音频；
  - 实在装不下（例如实测 40 秒而组合上限不够），就在 `rationale` 里写明冲突，由人回到骨架阶段重新切镜。

### 2.2.6 `rationale`

≤600 字，写清：为什么这样分配信息点、为什么建议这个组合、承接了前一镜的什么
（「接前镜已出现的船队，本镜只把目的地标出来」）、以及任何缺素材/缺标注/预算冲突的情况。

### 2.2.7 资产依据与可实现性（AI 填卡的硬约束）

这一节只约束 **AI 自动生成与 AI 写工具**。人工可以补信息、建标注、扩展设计，不受此限；
AI 也不得自动重写历史卡、删层或覆盖已有制作产物。

1. **以现有资产和既有制作能力完成设计。** 设计必须能用当前可用的资产图像、属性、语义和既有渲染能力实现；
   不得把尚未存在的信息、尚未创建的标注、猜测的点位或路线写成已经具备的实现条件。
2. **选择资产前先确认依据。** 先读与该用途相关的现有信息，确认实际引用的资产与版本；文件名、资产标题、
   其他版本的图、别的资产的语义，都不能代替本次引用对象的证据。涉及画面内容时用 `read_image` 看原图，
   不要声称看过没读过的内容。
3. **区分「尚未读取」与「已确认不存在」。** 没读就读；读过确认没有，就不能继续当它存在，
   也不能用「待人工补充」当作完成设计的理由。
4. **所有依赖都要真实、相容、可执行。** 需要绑定画面内位置、对象、路线或区域的图层，必须引用底图那张资产、
   那个版本上真实存在、含义与类型相容、几何完整的语义（`polygon` / `polyline` 用带折点的 `region` 或 `line`，
   `marker` 用 `point`，带位置的 `label` 用 `label`）。ID / 名称只能取自真实清单：不得杜撰、不得用资产名冒充语义、
   不得借用别的资产或不相容版本上的同名语义；**语义真实存在但几何为空，同样不算依据**。
   底图与生成段 `reference_assets` 必须是**现在就有图**的资产（有原件或已生成图），不能按「以后会出图」规划；
   把底图钉在某个 `version_task_id` 时，该资产的标注必须能确认是针对那一版做的，确认不了就不要钉版本。
5. **按实际依赖判断要不要锚定。** 纯章节标题、定义、说明这类排版元素用 `text` 模板文本框，本来就不锚定；
   但不能因为类型是 `label` 就自动免除依据——`label` 已经要求带 `anchor`，内容实际指向某地某线某范围时仍须满足第 4 条。
   **空锚点本身不是错误；需要锚定却留空才是错误**（留空的几何层渲染时会被整层丢弃）。
6. **无语义资产可以用于它实际支持的用途。** 没有标注的图可以做背景、整体展示或其他不依赖缺失标注的表达，
   不要求每张图先标注；但不得把普通河网说成某条特定历史航线，也不得把「图上有河」当成「已具备这条路线的可执行几何」。
7. **可以换表现手法，不得静默丢任务。** 某种做法实现不了时换一种现有资产支持的表达，但信息点一条都不能少，
   脚本/用户明确要求的视觉任务也不能取消；不得改旁白逐字内容，不得把必须由画面呈现的关系退成纯旁白。
8. **现有条件不够时不要保存成完成卡。** 先找可行替代；仍不行就不要调用 `update_storyboard` 保存这张卡，
   改为说明：受影响的镜与图层、所需依据、当前资产缺什么、为什么现有替代不行。可以说明人工补哪些标注会改变可行性，
   但那只是缺口说明，不是本次设计已完成。
9. **工具拒绝要在当前循环内处理。** `update_storyboard` 返回具体层的引用/类型/几何错误时，按真实返回改正后重试，
   不要删引用字段、不要改称「无锚定」、不要改走人工写入路径绕过，也不要自造字段宣称成功。

**合格的写法**

- 地图资产有 `ln-2（吉尔吉斯河，line，42 个几何点）`，本镜要描这条河：`polyline` 锚 `ln-2`，底图就是该资产。
- 一张没有任何标注的河网图，本镜只要「江淮水网的整体面貌」：读过原图后整体展示，不加任何无依据的路线或地点。
- 纯章节标题「第二章 永徽年间」：用 `text` 模板文本框（`heading`，必要时加一个 `date`），不写 `anchor`；
  旧的 `card` / 无锚点 `label` 已不再接受。
- 人物肖像作 `image` 层：锚到该肖像资产，前提是它确实有图。

**不合格的写法**

- 资产没有「邗沟走向」这条语义，却写 `anchor.semantic_id = '邗沟走向示意图'`（拿**资产名**冒充语义）。
- 五个几何层全部把 `anchor` 留空，`rationale` 写「待人工标注后补」——这就是被禁止的「待补成功卡」。
- 另一张地图上有同名的 `ln-7`，就把它借来给本镜底图用（跨资产借用，坐标落不到本镜底图上）。
- 语义 `rg-3` 真实存在但只有 1 个点，仍拿它做 `polygon`（几何不足，渲染时整层被跳过）。
- 底图写死 `version_task_id = 旧版本`，而该资产的标注是针对另一版图做的（版本不相容）。
- 图上确有河流，就说成「这是史载的那条漕运航线」（把普通地物说成未证实的历史结论）。
- 用户明确要求「画面上看出两路并进」，却因为难做改成只由旁白讲（静默丢掉视觉任务）。

**保存前自检**：信息点与视觉任务是否完整 → 实际引用的资产与版本是否核验过 → 语义归属与含义是否相容 →
必要几何是否可执行 → 无锚定的层是否确实不依赖画面位置 → 有没有「待人工补」占位 → 工具是否真的接受了写入。

## 2.3 画面栏的纪律

- 画面描述里**不写旁白文字**，不写「旁白：…」。旁白有独立字段，双写会被念两遍。
- 纪录片**没有对白**：禁止 `角色名：「台词」`，禁止让画面里的人物开口说解说词。
- 画面写观众实际看到的：主体、动作、镜头内的变化（展开的地图、行进的队列、翻动的文书）。

## 2.4 时长与节拍

- 本镜时长 = `budget.layer_s` + `budget.gen_s`（不存在的那段按 0 算），并且必须 ≥ 实测配音时长。
- 单段上限是硬的：图层段 ≤30 秒、生成段 ≤15 秒。
- 剧本里的 `【节拍名】` 标记是硬切边界：一镜不得跨节拍（这条在阶段一切镜时就要遵守）。
- 不要为了凑时长把两个主信息点塞进一镜，也不要把一句话拆到两镜去念。
