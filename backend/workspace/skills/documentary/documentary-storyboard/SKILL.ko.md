# 다큐멘터리 프로젝트: 스토리보드 추가 규범(내레이션 골격 → 실측 음성 → 설계 카드)

`storyboard-breaker` 기본 규범 위에 덧씌워지며, 충돌 시 **본 파일이 우선한다**.

다큐멘터리 분해는 실제 음성 합성을 사이에 둔 **연속된 두 단계**로 이루어진다:

```
최종 대본 본문
  → 【1단계】 내레이션 골격: 원문 그대로 분할해 숏별 narration_text + 제목 작성(save_storyboards)
  → 사람이 골격을 확인
  → 일괄 TTS: 숏마다 **실측** 음성 길이가 생긴다
  → 【2단계】 설계 카드: 실측 길이에 맞춰 정보점 / 레이어 구간 / 생성 구간 / 예산 설계(update_storyboard)
```

**1단계는 시각 설계를 전혀 만들지 않는다**: 실측 길이가 없으면 어떤 구간 예산도 추측일 뿐이다.
**2단계는 내레이션 본문을 고치지 않는다**: 경계는 1단계에서 확정되어 이미 음성이 생성되었고, 한 글자만 바꿔도 음성이 무효가 된다.

지금 어느 단계인지는 도구와 지시로 알 수 있다: `save_storyboards` 호출 = 1단계,
“설계 카드를 작성하라”는 지시와 함께 `update_storyboard(storyboard_id, design_card)`만 허용 = 2단계.

---

# 1단계: 내레이션 골격

## 1.1 내레이션 단 = 대본 본문 원문 그대로 복사(하드 룰)

본 프로젝트의 대본 본문이 **곧 내레이션 원고**다. 본문을 순서대로 끊어 각 구간을 **그대로** `narration_text`에 적는다:

- **원문 그대로 복사**: 문장부호·연도·인명·지명·숫자를 모두 원문과 일치시킨다. 고쳐 쓰기, 윤문, 축약, 가필 모두 금지.
- **문장 단위로 끊기**: 마침표 / 물음표 / 느낌표 / 쌍반점 뒤에서만 끊고, 문장 중간에서 끊지 않는다.
- **추가도 누락도 금지**: 본문의 모든 문단이 어느 숏엔가 들어가야 한다. 모든 숏의 `narration_text`를 순서대로 이으면 대본 본문과 같아야 한다.
  `save_storyboards`는 매번 `script_coverage.gaps`와 `must_fix`를 돌려준다: **빈틈이 남아 있는 한 숏을 계속 보충한다**.
  문장 경계에서 새 `shot_number`를 끼워 넣고 빠진 문장을 원문 그대로 담는다. 빈틈을 남긴 채 끝내면 작업 전체가 실패 처리된다.
- 숏당 **80자 이하**(음성 합성 단일 구간 하드 상한). 원문 문단이 80자를 넘으면 문장 경계에서 인접한 두 숏으로 나눈다.
- 도구가 검증한다: `narration_text`는 대본 본문에서 원문 그대로 발견되어야 하고 순서도 본문과 같아야 한다. 고쳐 쓴 문장은 **저장 거부**된다.

## 1.2 서버가 강제하는 세 가지 거부 규칙

위반한 숏은 조용히 교정되지 않고 **저장 거부**되어 사유와 함께 `rejected[]`에 나열된다. `rejected[]`를 보면 사유대로 고쳐 다시 저장한다.

1. **본 화 숏 수 하드 상한**: `cap = max( min(ceil(내레이션 문단 수 × 1.5), 내레이션 문단 수 + 3), 각 문단 ceil(문단 글자 수 / 80)의 합 )`.
   여기서 “내레이션 문단 수”는 대본 본문을 빈 줄로 나눈 비어 있지 않은 문단의 수다. `cap`을 넘는 숏은 모두 거부된다.
   긴 문단을 80자 상한 때문에 여러 숏으로 나눠야 하면 상한도 그만큼 올라간다(글자 수 기준의 상향일 뿐, 문장 경계 분할이 반드시 담긴다는 보장은 아니다).
   호흡 때문에 더 잘게 끊고 싶다면 숏을 늘리지 말고 인접한 짧은 문장을 합친다.
2. **모든 숏은 내레이션을 담아야 한다**: `narration_text`가 비면 거부된다. 다큐멘터리에는 무음의 화면 전용 숏이 없다.
   빈 숏, 전환, 지도 설정 숏도 한 구간의 내레이션을 맡는다.
3. **같은 내레이션을 두 숏이 가져갈 수 없다**: 같은 문장(또는 겹치는 구간)을 가져가면 거부된다.

## 1.3 이 단계에서 쓰는 필드는 네 개뿐

`save_storyboards`의 다큐멘터리 스키마가 받는 것은:

- `shot_number`: 숏 번호.
- `narration_text`: 이 숏의 내레이션(원문 그대로, 1.1 참조).
- `title`: 이 숏의 주 정보점을 한 문장으로(“이르티시강이 유일한 수로다”, “근위연대 출신이 지휘권을 결정했다”).
- `continuity`: `continue` / `cut`. 앞 숏과의 연결. 확신이 없으면 보내지 않는다.

**설계 카드·화면 묘사·키프레임 프롬프트·영상 프롬프트·길이·에셋 연결은 하나도 쓰지 않는다.**
그것들은 2단계에 속하며, 2단계는 이 숏이 실제로 더빙되어 실측 초수가 나온 뒤에야 시작된다.
지금 쓸 수 있는 어떤 초수도 추정값이며, **이 워크플로는 추정값을 받지 않는다**.

## 1.4 숏당 정보점 하나

숏 경계는 길이가 아니라 **정보점**이 정한다: 한 숏에서 한 가지를 분명히 말하고, 말이 끝나면 끊는다.
`title`의 그 한 문장은 2단계에서 `design_card.info_points[0].text`가 된다.

정보점과 화면이 맞지 않으면 2단계에서 **화면을 고친다**. 내레이션으로 돌아가 고치지 않는다.

# 2단계: 실측 내레이션 길이에 맞춘 설계 카드

## 2.1 전제(서버가 강제, 우회 불가)

- 본 화의 **내레이션 골격이 사람에 의해 확인됨**;
- 이 숏에 **현재 유효한 음성이 있음**: 본문, 발음 마크업, 현재 유효한 음성 파라미터가 음성과 일치하고,
  음성 파일이 존재하며, 그 파일에서 유한한 양수 길이가 실측됨.

지시문에 이 숏의 **실측 음성 초수**가 제시된다. 그것은 파일에서 측정한 사실이지 글자 수 추정이 아니다:
**예산은 반드시 그 값을 따른다**. “초당 4.5자” 추정 기준은 이 단계에서 쓰지 않는다.

## 2.2 설계 카드 `design_card`(모든 숏 필수)

화면을 쓰기 전에 아래 사슬을 끝까지 밟고, 결론을 `design_card`에 적는다:

```
이 숏에서 관객이 받아야 할 정보(info_points[], 12개 이하)
  → 그중 무엇을 레이어 구간이 그리는가(layer_plan: 베이스 이미지 base + 필수 표기 must_mark[] + 계획 레이어 planned_layers[])
  → 그중 무엇을 생성 구간이 연기하는가(gen_plan: 참조 에셋 reference_assets[] + 첫/중간/끝 프레임 묘사)
  → 각 구간의 초수(budget: layer_s / gen_s). 둘의 합은 실측 음성 길이 이상이어야 한다
  → 왜 이렇게 배분했는가(rationale, 600자 이하)
```

### 2.2.1 `info_points[]`: 전달할 정보와 담당

각 항목 `{ id, text, via }`, 최대 12개:

- `id`: 숏 안에서 유일한 짧은 식별자(`p1`, `p2`…). `planned_layers`와 `rationale`에서 참조할 수 있다.
- `text`: 그 정보를 한 문장으로(“준가르의 지배 범위는 발하슈호까지다”).
- `via ∈ layer | generated | narration_only`:
  - `layer` —— 레이어 구간이 베이스 이미지 위에 표기(범위, 경로, 지점, 이름 바, 연대).
  - `generated` —— 생성 구간이 연기(출발, 행군, 교전, 알현처럼 과정이 있는 사건).
  - `narration_only` —— 내레이션만 담당하고 화면은 맡지 않음. 신중히 쓸 것. 한 숏에 너무 많으면 화면이 일하지 않는다는 뜻이다.

모든 정보점에는 담당이 있어야 한다. 담당이 없는 항목은 `info_point_unassigned`(경고)로 표시된다.

### 2.2.2 `layer_plan`: 레이어 구간 계획

- `base`: 레이어 구간의 베이스 이미지. 기존 소재의 특정 버전을 가리키는 `{kind:'asset', asset_kind, asset_id, version_task_id}`,
  또는 앞 숏의 베이스를 이어받는 `{kind:'inherit_prev'}`(같은 서술 단락의 연속된 숏들은 **같은 증거 소재를 공유**하고
  레이어 상태만 바꾼다: S01은 삼자 범위, S04는 강, S07은 경로. 매 숏 지도를 바꾸지 않는다).
- `must_mark[]`: 이 숏에서 베이스 이미지 위에 반드시 표기할 의미 항목. 각 항목 `{ asset_id, semantic_id, name }`을
  `read_storyboard_context`가 돌려주는 `semantics` 목록에서 **원문 그대로 복사**한다(`asset_id` + `id` + `name` 세 가지 모두 일치).
  이름을 지어내면 `unresolved`로 표시되어 설계 카드 화면에서 빨갛게 뜬다. 쓰지 않은 것과 같다.
  내레이션에 나오는 지명·수계·호수·성채·정권 범위·경로는 여기에 대응 항목이 있어야 한다.
  의미 항목이 없으면 표기 레이어 계획을 유지하고 앵커의 semantic_id와 name을 비운 채 `rationale`에 주석 대기라고 적는다. 항목을 지어내거나 레이어를 낮추지 않는다.
- `planned_layers[]`: 어떤 레이어를 어떤 순서로 띄울지. 각 항목
  `{ type, text?, anchor?: {asset_id, semantic_id, name}, at_s }`:
  - `type ∈ polygon | polyline | marker | label | card | image`
    (범위 강조 / 하천·경로·화살표 / 지점 / 지명·연대 문자 / 이름 바·연도 카드 / 삽입 소도면).
  - `anchor`는 `must_mark`와 같은 의미 항목을 가리킨다. 문자 레이어는 `text`에 표시할 글자를 쓴다.
  - `at_s`: 레이어 구간의 몇 초째에 나타나는가. **실측 음성 타임라인에 맞춰 배치한다**: 내레이션이 먼저 말하는 것이 먼저 나온다.
    “동시에”, “두 갈래로”는 **같은 `at_s`의 두 레이어**로, “먼저… 그다음…”은 서로 다른 `at_s`로 표현한다.
    `at_s`는 해당 구간의 `layer_s`를 넘을 수 없다.
- 모든 `must_mark` 항목은 최소 한 개의 `planned_layers`로 그려져야 하며, 빠지면 `must_mark_not_planned`(경고)가 된다.
- 레이어 구간이 있는 숏(조합 A / C / D)은 `base`가 필수이며, 없으면 `missing_base`로 차단된다.

### 2.2.3 `gen_plan`: 생성 구간 계획

- `reference_assets[]`: 생성 구간이 반드시 쓰는 참조 에셋(`{kind, id, name}`, 에셋 단위).
  프롬프트 작성 단계에서 하나씩 대조하며, `@에셋이름`으로 참조되지 않은 참조 에셋은 생성을 차단한다.
  내레이션이 언급하지만 이 숏에 등장하지 않는 조직·원격지 인물·원격지 사건에는
  `read_storyboard_context`의 `exposition_assets`에 있는 시각적 매개 에셋을 쓴다.
  예: “그는 세묘놉스키 근위연대 출신이고, 그 연대는 표트르 1세가 손수 창설했다”라면
  화면에 근위연대의 시각적 매개와 표트르 1세의 초상이 함께 있어야 하며, 빈 연병장에 선 한 사람이어서는 안 된다.
- `first` / `mid` / `last`: 세 슬롯의 화면 묘사(한 문장이면 된다. 정식 프롬프트는 이후 단계가 쓴다).
  연결 프레임은 레이어 구간이 상속해 잠그므로 **쓰지 않는다**: 조합 C는 `first`를, 조합 D는 `last`를 생략한다.
- 지리 관계를 생성 구간으로 연기시키지 않는다: 빈 땅을 걷는 사람으로는 “이르티시강을 거슬러 북상한다”를 표현할 수 없다. 그건 레이어 구간의 일이다.

### 2.2.4 구간 조합 `combo`

- `combo ∈ A | B | C | D`를 작성하고 필요하면 `suggested_combo`도 작성한다. 기존 선택은 유지하며 사람이 검토하거나 변경한다.
  `rationale`에 선택 이유를 한 문장으로 적는다.
- 네 조합의 판단 기준:
  - **A** “지도/원자료 위의 표기와 팬: ‘어디·누구·몇 년’을 말한다”
  - **B** “AI 생성 숏: ‘무슨 일이 일어났는가’를 말한다”
  - **C** “먼저 위치를 잡고 장면으로”
  - **D** “먼저 장면, 그다음 지도/문서로 착지”
- A는 레이어 구간 ▣만, B는 생성 구간 ▶만, C = 레이어 ▣ → 생성 ▶, D = 생성 ▶ → 레이어 ▣.
  C의 생성 구간 첫 프레임과 D의 마지막 프레임은 **연결 프레임 ◆**이며, 인접한 레이어 프레임을 상속해 잠긴다.

### 2.2.5 `budget`: 구간별 초수(실측 음성이 기준)

- `layer_s ≤ 30`, `gen_s ≤ 15`는 하드 상한이며, 초과한 설계 카드는 서버가 **저장을 거부**한다.
- 제안한 조합에 맞춰 적는다: A는 `layer_s`만(`gen_s`는 null), B는 `gen_s`만, C / D는 둘 다.
- **두 구간의 합은 지시문에 제시된 실측 음성 초수 이상이어야 한다.** 담기지 않을 때는:
  - 구간별 상한을 넘지 않는 선에서 화면을 늘려도 된다;
  - 예산에 맞추려고 내레이션을 잘라내거나 압축하거나 고쳐 쓰는 것은 **절대 불가**다. 이미 음성이 생성되었으므로
    글자를 바꾸면 음성이 무효가 된다;
  - 정말 담기지 않으면(예: 실측 40초인데 조합 상한이 모자람) `rationale`에 충돌을 명시해, 사람이 골격 단계로 돌아가 다시 끊게 한다.

### 2.2.6 `rationale`

600자 이하로, 정보점을 이렇게 나눈 이유, 이 조합을 제안하는 이유, 앞 숏에서 무엇을 이어받았는지
(“앞 숏에 나온 선단을 받아 이 숏은 목적지만 표기한다”), 그리고 소재 부족·표기 부족·예산 충돌을 적는다.

## 2.3 화면 규율

- 화면 묘사에 **내레이션 문장을 쓰지 않는다**. “내레이션: …”도 쓰지 않는다. 내레이션은 전용 필드가 있어 두 번 쓰면 두 번 읽힌다.
- 다큐멘터리에는 **대사가 없다**: `인물명: 「대사」` 금지. 화면 속 인물이 해설을 말하게 해서는 안 된다.
- 화면에는 관객이 실제로 보는 것을 쓴다: 주체, 동작, 숏 안의 변화(펼쳐지는 지도, 행진하는 대열, 넘겨지는 문서).

## 2.4 길이와 비트

- 이 숏의 길이 = `budget.layer_s` + `budget.gen_s`(없는 구간은 0) 이며, 실측 음성 길이 이상이어야 한다.
- 구간 상한은 하드하다: 레이어 구간 30초 이하, 생성 구간 15초 이하.
- 대본의 `【비트 이름】` 표기는 하드컷 경계이며, 한 숏이 비트를 가로질러서는 안 된다(1단계 분할 시점에 이미 지킨다).
- 길이를 채우려고 주 정보점 두 개를 한 숏에 밀어 넣지 않고, 한 문장을 두 숏으로 나눠 읽게 하지 않는다.
