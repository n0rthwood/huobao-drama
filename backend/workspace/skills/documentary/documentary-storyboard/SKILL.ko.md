# 다큐멘터리 프로젝트: 스토리보드 분해 추가 규범(두 단 스크립트 + 설계 카드)

`storyboard-breaker` 기본 규범 위에 덧씌워지며, 충돌 시 **본 파일이 우선한다**.

다큐멘터리 스토리보드는 **두 단 스크립트**이다: 왼쪽 단은 내레이션(무엇을 말하는가), 오른쪽 단은 화면(무엇이 보이는가). 두 단은 일대일로 대응하며, 같은 숏 안에서는 같은 사항을 다뤄야 한다.

## 1. 내레이션 단 = 대본 본문 원문 그대로 복사(하드 룰)

본 프로젝트의 대본 본문**이 곧 내레이션 원고**이다. 분해 시 본문을 순서대로 단락으로 잘라 각 단락을 **원문 그대로** `narration_text` 에 기록한다:

- **한 글자 그대로 복사**: 문장 부호, 연도, 인명, 지명, 숫자는 모두 원문과 일치한다. 재작성하지 않고, 다듬지 않고, 줄이지 않고, 단어를 보태지 않는다.
- **문장 경계에서 자른다**: 마침표 / 물음표 / 느낌표 / 세미콜론 뒤에서만 자를 수 있고, 문장 중간에서 잘라서는 안 된다.
- **추가하지 않고, 빠뜨리지 않는다**: 본문의 모든 단락은 어느 한 숏에 담겨야 하며, 전체 숏의 `narration_text` 를 순서대로 이어 붙이면 대본 본문과 같아야 한다.
  `save_storyboards` 는 호출마다 `script_coverage.gaps` 와 `must_fix` 를 반환한다: **빈틈이 남아 있는 한 숏을 계속 보충한다**.
  문장 경계에 새 `shot_number` 를 삽입하고 빠진 문장을 한 글자 그대로 잘라 넣는다. 빈틈을 남긴 채 끝내면 스토리보드 분해 작업 전체가 실패로 판정된다.
- 숏당 **≤80 자**(음성 합성의 단락당 하드 상한). 원문 단락이 80 자를 넘으면 문장 경계에서 인접한 두 숏으로 나눈다.
- 도구가 검증한다: `narration_text` 는 대본 본문에서 한 글자 그대로 찾아야 하고 순서도 본문과 일치해야 한다. 재작성된 텍스트는 **저장이 거부**된다.

### 1.1 서버가 강제하는 세 가지 저장 거부 규칙

위반한 숏은 조용히 수정되지 않고 **저장이 거부**되며, 반환값의 `rejected[]` 에 사유와 함께 나열된다. `rejected[]` 를 보면 사유에 따라 고쳐 다시 저장한다.

1. **본 에피소드 숏 총수 하드 상한**: `cap = min(ceil(내레이션 단락 수 × 1.5), 내레이션 단락 수 + 3)`.
   여기서 "내레이션 단락 수" = 대본 본문을 빈 줄로 나눈 비어 있지 않은 단락의 수. `cap` 을 넘는 숏은 모두 거부된다.
   더 잘게 자르고 싶으면 숏 수를 늘리지 말고 인접한 짧은 문장을 합친다.
2. **모든 숏은 반드시 내레이션 한 단락을 담당한다**: `narration_text` 가 비면 거부된다. 다큐멘터리에 무음의 화면 전용 숏은 없다.
   빈 장면, 전환, 지도 정샷도 내레이션 한 단락을 받는다.
3. **같은 내레이션 단락을 두 숏이 중복해서 가져갈 수 없다**: 두 숏이 같은 문장을 가져가면(또는 겹치면) 거부된다.

## 2. 화면 단 = `description` 은 화면만 기술(하드 룰)

- `description` 에 내레이션 문장을 쓰지 않고, "내레이션: …"도 쓰지 않는다. 내레이션에는 독립 필드가 있고, 두 번 쓰면 두 번 읽힌다.
- 다큐멘터리에는 **대사가 없다**: `캐릭터명:「대사」` 는 금지이며, 화면 속 인물이 해설을 입으로 말하게 하는 것도 금지이다.
- `description` 은 관객이 실제로 보는 것을 쓴다: 피사체, 동작, 프레임 안의 변화(펼쳐지는 지도, 행진하는 대열, 넘겨지는 문서).

## 3. 숏당 정보점 하나

분해의 경계는 **정보점**이 정하고, 길이가 정하는 것이 아니다: 한 숏이 한 가지를 명확히 말하고, 말이 끝나면 자른다.

모든 숏은 `title` 에 한 문장으로 그 숏의 주요 정보점을 명시한다("额尔齐斯河(이르티쉬 강)가 유일한 수로다", "근위 연대 출신이 지휘권을 결정했다").
같은 문장이 `design_card.info_points[0].text` 가 된다. 화면은 그 정보점을 **보여줄 수 있어야 한다**.

정보점과 화면이 맞지 않으면 **화면을 고치고**, 내레이션을 고치지 않는다.

## 4. 숏 설계 카드 `design_card`(모든 숏에 필수)

여기가 다큐멘터리 스토리보드와 드라마 스토리보드의 가장 큰 차이다: **먼저 이 숏을 어떻게 만들지 정하고, 그다음 화면을 쓴다**.
`description` 을 쓰기 전에 다음 연쇄를 밟고, 결론을 `design_card` 에 기록한다:

```
이 숏이 전달할 정보는 무엇인가(info_points[], ≤12 개)
  → 그중 무엇을 레이어 세그먼트가 그리는가(layer_plan: 베이스 base + 필수 표시 must_mark[] + 계획 레이어 planned_layers[])
  → 그중 무엇을 생성 세그먼트가 연기하는가(gen_plan: 참조 자산 reference_assets[] + 첫/중간/마지막 프레임)
  → 각 세그먼트가 몇 초를 갖는가(budget: layer_s / gen_s)
  → 왜 그렇게 배분했는가(rationale, ≤600 자)
```

### 4.1 `info_points[]`: 이 숏이 전달할 정보, 담당자를 함께 적는다

각 항목은 `{ id, text, via }`, 최대 12 개:

- `id`: 숏 안에서 유일한 짧은 식별자(`p1`, `p2`…). `planned_layers` 와 `rationale` 에서 참조할 수 있다.
- `text`: 그 정보를 한 문장으로 쓴다("준가르의 지배 범위는 발하슈 호까지").
- `via ∈ layer | generated | narration_only`:
  - `layer` —— 레이어 세그먼트가 베이스 이미지 위에 표시한다(범위, 경로, 지점, 네임바, 연도).
  - `generated` —— 생성 세그먼트가 연기한다(출발, 행진, 교전, 알현처럼 과정이 있는 사건).
  - `narration_only` —— 내레이션만 담당하고 화면은 담당하지 않는다. 남용하지 말 것. 많으면 화면이 일하지 않는다는 뜻이다.

모든 정보점에는 담당자가 있어야 한다. 담당자가 없는 항목은 `info_point_unassigned`(경고)로 표시된다.

### 4.2 `layer_plan`: 레이어 세그먼트 계획

- `base`: 레이어 세그먼트의 베이스 이미지. 기존 소재의 구체적 버전을 가리키는 `{kind:'asset', asset_kind, asset_id, version_task_id}`,
  또는 앞 숏의 베이스 이미지를 이어받는 `{kind:'inherit_prev'}`(같은 서사 세그먼트의 연속 숏은 **같은 증거 소재를 공유**하고
  레이어 상태만 바꾼다: S01 에서 삼국 범위, S04 에서 하천, S07 에서 경로. 숏마다 지도를 갈아끼우지 않는다).
- `must_mark[]`: 베이스 이미지 위에 반드시 표시해야 하는 시맨틱 항목. 각 항목은 `{ asset_id, semantic_id, name }` 이며,
  `read_storyboard_context` 가 반환하는 `semantics` 목록의 항목을 **한 글자 그대로 복사**한다(`asset_id` + `id` + `name` 세 가지 모두 일치).
  스스로 이름을 지어내면 `unresolved` 로 표시되고 설계 카드 페이지에 빨갛게 드러나며, 쓰지 않은 것과 같다.
  내레이션에 나오는 지명 / 수계 / 호수 / 성채 / 정권 범위 / 경로는 여기에 대응 항목이 있어야 한다.
  지도에 정말 그 항목이 없으면 억지로 맞추지 말고 `rationale` 에 "내레이션은 X 를 언급하지만 소재 N 의 주석에는 X 가 없다"고 명시하고 소재를 바꾸거나 생성 세그먼트에 맡긴다.
  필요하면 `read_image` 로 원본을 열어 실제로 있는지 확인한다.
- `planned_layers[]`: 어떤 레이어를 어떤 순서로 나타낼지. 각 항목은
  `{ type, text?, anchor?: {asset_id, semantic_id, name}, at_s }`:
  - `type ∈ polygon | polyline | marker | label | card | image`
    (범위 하이라이트 / 하천·경로·화살표 / 지점 / 지명·연도 텍스트 / 네임바·연도 카드 / 삽입 소도).
  - `anchor` 는 `must_mark` 와 같은 시맨틱 항목을 가리킨다. 텍스트 레이어는 표시할 글자를 `text` 에 쓴다.
  - `at_s`: 레이어 세그먼트 안에서 몇 초에 나타나는가. 내레이션이 먼저 말하는 것이 먼저 나타난다.
    "동시에" "두 길로 나뉘어"는 **같은 `at_s` 의 두 레이어**로 표현하고, "먼저 … 나중에 …"는 다른 `at_s` 로 벌린다.
- 모든 `must_mark` 는 적어도 하나의 `planned_layers` 가 그려야 한다. 빠지면 `must_mark_not_planned`(경고)로 표시된다.
- 레이어 세그먼트가 있는 숏(조합 A / C / D)은 반드시 `base` 를 지정해야 하며, 없으면 `missing_base` 로 차단된다.

### 4.3 `gen_plan`: 생성 세그먼트 계획

- `reference_assets[]`: 생성 세그먼트가 반드시 쓰는 참조 자산(`{kind, id, name}`, 자산 단위).
  프롬프트 작성 단계가 한 항목씩 대조한다: `@자산명` 으로 참조되지 않은 참조 자산은 생성을 차단한다.
  내레이션에 언급되지만 이 숏에 등장하지 않는 조직 / 타지의 인물 / 타지의 사건은
  `read_storyboard_context` 의 `exposition_assets` 에 있는 시각적 담체 자산을 쓴다.
  예: 내레이션이 "그는 谢苗诺夫近卫团(세묘놉스키 근위 연대) 출신이며, 그 근위 연대는 彼得一世(표트르 1세)가 직접 창설한 것이다"라고 말하면,
  화면에는 근위 연대의 시각적 담체와 표트르 1세의 초상이 동시에 있어야 한다. 빈 훈련장에 홀로 선 한 사람이어서는 안 된다.
- `first` / `mid` / `last`: 세 슬롯의 화면 기술(한 문장이면 된다. 정식 프롬프트는 이후 단계가 쓴다).
  연결 프레임은 레이어 세그먼트에서 상속되어 잠기므로 **쓰지 않는다**: 조합 C 는 `first` 를, 조합 D 는 `last` 를 쓰지 않는다.
- 지리적 관계를 생성 세그먼트로 연기하지 않는다: 빈 마당을 걷는 한 사람으로는 "额尔齐斯河(이르티쉬 강)를 거슬러 북상"을 표현할 수 없다 —— 그것은 레이어 세그먼트의 일이다.

### 4.4 조합 제안 `suggested_combo`: 제안만 하고 결정하지 않는다

- 쓰는 것은 `suggested_combo ∈ A | B | C | D` 뿐이다. **`combo` 를 쓰지 않는다**: 서버는 모델이 보낸 `combo` 를 무시하며,
  세그먼트 조합은 사람이 골라야 한다. 왜 그 제안인지 `rationale` 에 한 문장으로 쓴다.
- 네 조합의 판단 기준(이 기준 그대로 판단한다):
  - **A** 「地图/原件上标注与推拉：讲『在哪里·是谁·哪一年』」(지도/원본 위의 표시와 푸시: "어디·누구·몇 년"을 말한다)
  - **B** 「AI 生成镜头：讲『发生了什么』」(AI 생성 숏: "무슨 일이 일어났는가"를 말한다)
  - **C** 「先定位再入戏」(먼저 위치를 잡고 그다음 극에 들어간다)
  - **D** 「先入戏再落到地图/档案」(먼저 극에 들어가고 그다음 지도/문서로 내려앉는다)
- A 는 레이어 세그먼트 ▣ 만; B 는 생성 세그먼트 ▶ 만; C = 레이어 세그먼트 ▣ → 생성 세그먼트 ▶; D = 생성 세그먼트 ▶ → 레이어 세그먼트 ▣.
  C 의 생성 세그먼트 첫 프레임, D 의 생성 세그먼트 마지막 프레임은 **연결 프레임 ◆** 이며, 인접한 레이어 세그먼트 프레임을 상속하여 잠긴다.

### 4.5 `budget`: 각 세그먼트의 초수

- `layer_s ≤ 30`, `gen_s ≤ 15` 는 모두 하드 상한이다. 이를 넘는 설계 카드는 서버가 **쓰기를 거부**한다.
- 제안한 조합에 맞춰 쓴다: A 는 `layer_s` 만(`gen_s` 는 null); B 는 `gen_s` 만; C / D 는 둘 다.
- 둘의 합은 내레이션 추정 길이 **이상**이어야 한다: 내레이션 글자 수 ÷ **4.5 자/초** + **0.8 초**의 꼬리 여백.
  담기지 않으면 문장 경계에서 인접한 두 숏으로 나눈다. 예산을 압축하지 않는다.

### 4.6 `rationale`

≤600 자. 정보점을 왜 그렇게 배분했는지, 왜 그 조합을 제안하는지, 앞 숏에서 무엇을 이어받았는지
("앞 숏에서 이미 나온 선단을 이어받아, 이 숏은 목적지만 표시한다"), 소재나 주석이 부족한 상황이 있으면 그것도 쓴다.

## 5. 길이와 비트

- `duration` = `budget.layer_s` + `budget.gen_s`(없는 세그먼트는 0). 그리고 내레이션 추정 길이
  (내레이션 글자 수 ÷ 4.5 자/초 + 0.8 초의 꼬리 여백) 이상이어야 한다.
- 세그먼트별 상한은 하드하다: 레이어 세그먼트 ≤30 초, 생성 세그먼트 ≤15 초. 한 숏에 담기지 않으면 문장 경계에서 나눈다(§1.1 의 숏 수 상한도 유의).
- 대본의 `【비트명】` 표시는 하드 절단 경계이다: 한 숏이 비트를 넘어서는 안 된다.
- 길이를 맞추려고 두 주요 정보점을 한 숏에 채워 넣지 말고, 한 문장을 두 숏에 나눠 읽히게 하지도 말라.
