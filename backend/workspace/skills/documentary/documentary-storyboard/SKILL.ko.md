# 다큐멘터리 프로젝트: 스토리보드 분해 추가 규범(두 단 스크립트 + 표현 설계)

`storyboard-breaker` 기본 규범 위에 덧씌워지며, 충돌 시 **본 파일이 우선한다**.

다큐멘터리 스토리보드는 **두 단 스크립트**이다: 왼쪽 단은 내레이션(무엇을 말하는가), 오른쪽 단은 화면(무엇이 보이는가). 두 단은 일대일로 대응하며, 같은 숏 안에서는 같은 사항을 다뤄야 한다.

## 1. 내레이션 단 = 대본 본문 원문 그대로 복사(하드 룰)

본 프로젝트의 대본 본문**이 곧 내레이션 원고**이다. 분해 시 본문을 순서대로 단락으로 잘라 각 단락을 **원문 그대로** `narration_text` 에 기록한다:

- **한 글자 그대로 복사**: 문장 부호, 연도, 인명, 지명, 숫자는 모두 원문과 일치한다. 재작성하지 않고, 다듬지 않고, 줄이지 않고, 단어를 보태지 않는다.
- **문장 경계에서 자른다**: 마침표 / 물음표 / 느낌표 / 세미콜론 뒤에서만 자를 수 있고, 문장 중간에서 잘라서는 안 된다.
- **추가하지 않고, 빠뜨리지 않는다**: 본문의 모든 단락은 어느 한 숏에 담겨야 하며, 전체 숏의 `narration_text` 를 순서대로 이어 붙이면 대본 본문과 같아야 한다.
  `save_storyboards` 는 호출마다 `script_coverage.gaps` 와 `must_fix` 를 반환한다: **빈틈이 남아 있는 한 숏을 계속 보충한다**.
  문장 경계에 새 `shot_number` 를 삽입하고 빠진 문장을 한 글자 그대로 잘라 넣는다. 빈틈을 남긴 채 끝내면 스토리보드 분해 작업 전체가 실패로 판정된다.
- 숏당 **≤80 자**(음성 합성의 단락당 하드 상한). 원문 단락이 80 자를 넘으면 문장 경계에서 인접한 두 숏으로 나눈다.
- 화면 전용 숏(빈 장면, 전환, 지도 정샷)은 내레이션이 없어도 된다: `narration_text` 를 비워 두면 되며, 해설을 지어내지 않는다.
- 도구가 검증한다: `narration_text` 는 대본 본문에서 한 글자 그대로 찾아야 하고 순서도 본문과 일치해야 한다. 재작성된 텍스트는 **저장이 거부**된다.

## 2. 화면 단 = `description` 은 화면만 기술(하드 룰)

- `description` 에 내레이션 문장을 쓰지 않고, "내레이션: …"도 쓰지 않는다. 내레이션에는 독립 필드가 있고, 두 번 쓰면 두 번 읽힌다.
- 다큐멘터리에는 **대사가 없다**: `캐릭터명:「대사」` 는 금지이며, 화면 속 인물이 해설을 입으로 말하게 하는 것도 금지이다.
- `description` 은 관객이 실제로 보는 것을 쓴다: 피사체, 동작, 프레임 안의 변화(펼쳐지는 지도, 행진하는 대열, 넘겨지는 문서).

## 3. 숏당 정보점 하나

분해의 경계는 **정보점**이 정하고, 길이가 정하는 것이 아니다: 한 숏이 한 가지를 명확히 말하고, 말이 끝나면 자른다.

모든 숏은 `title` 에 한 문장으로 그 숏의 정보점을 명시한다("额尔齐斯河(이르티쉬 강)가 유일한 수로다", "근위 연대 출신이 지휘권을 결정했다").
같은 문장을 `intent.info_point` 에도 쓴다. 화면은 그 정보점을 **보여줄 수 있어야 한다**.

정보점과 화면이 맞지 않으면 **화면을 고치고**, 내레이션을 고치지 않는다.

## 4. 표현 설계 `intent`(모든 숏에 필수)

여기가 다큐멘터리 스토리보드와 드라마 스토리보드의 가장 큰 차이다: **먼저 표현 방법을 정하고, 그다음 화면을 쓴다**.
`description` 을 쓰기 전에 다음 연쇄를 밟고, 결론을 `intent` 에 기록한다:

```
이 숏에서 관객이 무엇을 이해하게 만들 것인가(info_point, 하나만)
  → 어떤 수단으로 표현할 것인가(device)
  → 그러기 위해 화면에 구체적으로 무엇이 보여야 하는가(must_show)
  → 그것들을 어떤 레이어로 그리고, 어떤 순서로 나타나게 할 것인가(overlay_plan)
  → 왜 그렇게 선택했는가(rationale)
```

### 4.1 `device`: 다섯 가지 표현 수단, 내레이션의 성격에 따라 선택

| device | 어떤 내레이션에 쓰는가 | 화면은 무엇인가 |
|---|---|---|
| `map_anim` | 지리, 경로, 범위, 동시에 진행되는 두 계열 | 증거 지도 + 하이라이트/화살표/라벨의 층별 출현 |
| `archival` | 조약, 문서, 판화, 기물 원본 | 아카이브 원본 그 자체 + 느린 푸시인 + 라벨 |
| `card` | 인물의 첫 등장, 연도, 챕터 전환 | 초상/정지 화면 + 네임바(이름/직책/연도) |
| `reenact_still` | 정적인 상태, 초상, 물건, 동작이 없는 상황 | 생성한 재연 정지 화면 + 느린 푸시인 |
| `reenact_video` | **과정과 움직임이 있는 사건**(출발, 행진, 역류 항해, 교전, 포위, 승선, 축조, 알현, 호송) | 생성 모델 영상 |

판단 기준은 **우선순위**로 진행하며, 앞 항목에 해당하면 뒤는 판단하지 않는다:
1. **인물이 이 에피소드에 처음 등장한다** → `card`(초상/정지 화면 + 네임바). 그 내레이션에 동작이 함께 있어도 마찬가지다.
   인물이 제대로 소개되기 전에 먼저 인물을 세운다; 그 동작은 바로 뒤따르는 숏에 맡긴다.
2. "어디 / 어느 범위 / 어떤 길을"을 말한다 → `map_anim`.
3. 문장에 **진행 중인 동작이나 과정**을 서술하는 동사가 있다 → `reenact_video` 를 쓰고, `reenact_still` 로 격하하지 않는다.
4. 신분, 출신, 연도, 숫자만을 말한다 → `card` 나 `archival`.

`reenact_still` 은 **화면에 실제로 동작이 없는** 숏(초상, 물건, 빈 장소, 정지한 상황)에만 쓴다.
"선단이 물살을 거슬러 올라간다" "대군이 라사(拉萨)로 진군한다" "정찰대가 배로 출발한다" "양측이 교전한다" 같은 문장은 `reenact_video` 에 속한다.
이것들을 정지 화면으로 쓰면 다큐멘터리에서 유일하게 움직이는 부분까지 얼려 버리는 셈이다——한 에피소드에 `reenact_video` 가 하나도 없다면
거의 확실히 오판한 것이므로, 동작이 있는 내레이션을 문장별로 다시 검토한다.

`reenact_video` 의 `deterministic` 은 기본값 `none`(숏 전체가 모델 영상); 모델 영상 앞/뒤에 짧은
결정론적 레이어 클립을 이어 붙여야 할 때(예: 먼저 연도 카드를 내보내거나, 끝에 지도 소도를 얹을 때)만 `pre` / `post` 를 제안한다.

지리적 관계를 `reenact_*` 로 연기하지 않는다: 빈 마당을 걷는 한 사람으로는 "额尔齐斯河(이르티쉬 강)를 거슬러 북상"을 표현할 수 없다.

### 4.2 `must_show`: 내레이션 속 모든 구체적 명사는 화면에 닿아야 한다

- 내레이션에 나오는 **지명 / 수계 / 호수 / 성채 / 정권 범위 / 경로**는 반드시 어느 증거 소재의
  **시맨틱 주석**(`read_storyboard_context` 의 `props[].semantics`)에서 해당 항목을 찾을 수 있어야 하고, `must_show` 에 기록한다:
  - 구역 → `{kind:'region', asset_id, semantic:'准噶尔汗国'}`
  - 하천/경계/경로 선 → `{kind:'line', asset_id, semantic:'额尔齐斯河'}`
  - 도시/지점 → `{kind:'point'|'label', asset_id, semantic:'斋桑湖'}`
  - 행군 경로 → `{kind:'route', asset_id, from:'西宁', to:'拉萨'}`(양끝 모두 그 지도에 주석된 지명이어야 한다)
- `semantic` 은 `semantics` 목록의 `name`(또는 그 `id`)에서 **한 글자 그대로**取한다. 스스로 이름을 지어내면
  `unresolved` 로 표시되고, 표현 설계 페이지에 빨갛게 드러나며, 쓰지 않은 것과 같다.
- 지도에 **그 항목이 없으면** 억지로 맞추지 않는다: `rationale` 에 "내레이션은 X 에 언급하지만 소재 N 의 주석에는 X 가 없다"라고 명시하고,
  이 숏을 강등한다(device 를 바꾸거나 소재를 바꾼다). 필요하면 `read_image` 로 원본을 열어 실제로 있는지 확인한다.
- **인물의 첫 등장** → `device='card'`, `must_show` 는 `{kind:'portrait', asset_id:<캐릭터 id>}` 를 갖고,
  `overlay_plan` 에 `card` 레이어를 둔다(필드에 이름/직책/연도).
- **내레이션에 언급되지만 이 숏에 등장하지 않는 조직 / 타지의 인물 / 타지의 사건** →
  `read_storyboard_context` 의 `exposition_assets` 를 참조한다: `{kind:'exposition', asset_id:<그 담체 소재>}`.
  예: 내레이션이 "그는 谢苗诺夫近卫团(세머노프스키 근위 연대) 출신이며, 그 근위 연대는 彼得一世(표트르 1세)가 직접 창설한 것이다"라고 말하면,
  화면에는 근위 연대의 시각적 담체와 표트르 1세의 초상이 동시에 있어야 한다. 빈 훈련장에 홀로 선 한 사람이어서는 안 된다.

### 4.3 `overlay_plan`: 지도 숏의 오버레이 레이어를 비워 두지 않는다

- `device='map_anim'` 일 때 `overlay_plan` 은 **비어 있으면 안 된다**. 지도를 평면으로 푸시/팬하는 것은 지도 애니메이션이 아니며,
  바로 본 프로젝트가 없애려는 오류이다.
- 레이어 타입은 `polygon`(범위 하이라이트), `polyline`(하천/경로/화살표), `marker`(지점),
  `label`(지명/연도 텍스트), `card`(네임바/연도 카드), `image`(삽입 소도)만 취한다.
- 각 레이어는 가급적 `anchor:{asset_id, semantic_id}` 를 갖고(`must_show` 와 같은 시맨틱 항목을 가리킴),
  `reveal_at`(초)으로 출현 순서를 정한다: 내레이션이 먼저 말하는 것이 먼저 나타난다.
- "동시에" "두 길로 나뉘어" 같은 병렬 관계는 **같은 시점에 두 레이어를 출현시켜** 표현하고, "먼저 … 나중에 …"는 `reveal_at` 으로 벌린다.
- 전체 지도에서 국부로 푸시해야 할 때는 `viewport:[x,y,w,h]`(정규화 0–1)를 쓴다.

### 4.4 `deterministic`: 스스로 기본값을 정하지 않는다

클립 위치는 프로그램이 device 로 표를 찾아 정한다(`map_anim/archival/card/reenact_still` → `replace`,
`reenact_video` → `none`). `pre`/`post`(모델 영상 앞/뒤에 짧은 결정론적 클립을 이어 붙임)를 제안해도 되는 것은 `reenact_video` 뿐이다.
그 외의 경우에는 **이 필드를 쓰지 않는다**; 범위를 벗어난 값은 서버가 버리고 기본값으로 돌아간다.

### 4.5 서사 세그먼트 문맥

- `read_storyboard_context` 를 호출할 때 앞뒤 숏의 `intent` 도 읽는다. 같은 서사 세그먼트(같은 베이스 지도 위의 연속 숏)는
  **같은 증거 소재를 공유**하고 레이어 상태만 바꿔야 한다: S01 에서 삼국 범위, S04 에서 하천, S07 에서 경로를 표시한다.
  숏마다 지도를 갈아끼우지 않는다.
- 뒤 숏이 앞 숏을 이어받을 때는 `rationale` 에 무엇을 이어받았는지 명시한다("앞 숏에서 이미 나온 선단을 이어받아, 이 숏은 목적지만 표시한다").

## 5. 길이와 비트

- `duration` = 해당 숏 내레이션 글자 수 ÷ **4.5 자/초** + **0.8 초**의 여백, **4–15 초**로 클램프. 내레이션 없는 화면 전용 숏은 4–6 초.
- 대본의 `【비트명】` 표시는 하드 절단 경계이다: 한 숏이 비트를 넘어서는 안 된다.
- 길이를 맞추려고 두 정보점을 한 숏에 채워 넣지 말고, 한 문장을 두 숏에 나눠 읽히게 하지도 말라.
