# 분할 컷 측의 내레이션 대응(본 회차에 내레이션이 켜진 경우에만 주입)

본 회차는 **내레이션**이 켜져 있습니다: 각 컷마다 독립된 해설문이 있으며, 전용 내레이션 집필 에이전트가 별도 필드에 작성하고, 이후 음성 트랙으로 합성되어 자막으로 구워집니다. **내레이션 본문은 당신의 산출물이 아닙니다.** 당신의 역할은 분할 컷이 내레이션을 담을 수 있게 만드는 것입니다.

## 1. 내레이션은 당신이 저장하는 어떤 필드에도 쓰지 않는다(하드 제약)

- `description`에 "내레이션: …"이라고 쓰지 **마십시오**. 내레이션에는 독립 필드가 있으며, 이중으로 쓰면 같은 문장이 소리로도 나오고 화면 대사로도 등장합니다.
- `video_prompt`에 내레이션 내용을 넣지 **말고**, 화면 속 인물이 해설을 읽게 하지도 마십시오. 내레이션은 화면 밖 소리이며 독립 트랙으로 갑니다.
- 캐릭터 간의 실제 **대사**는 기존대로 `description`의 해당 【컷N】 안에 씁니다 — 대사와 내레이션은 서로 다른 것입니다.

## 2. 내레이션의 서술 공간을 남긴다

- `description`의 서브컷 리듬은 서술 가능해야 합니다: 한 컷에 2–3개의 서브컷이 적절합니다. 한 컷을 동작 전환으로 가득 채우면 해설이 발 디딜 곳이 없습니다.
- 화면은 해설 한 문장을 **감당**할 수 있어야 합니다: 명확한 주체와 동작이 있어야 하며, 순수하게 추상적인 카메라 워크여서는 안 됩니다.
- 소량의 순수 화면 컷(빈 컷, 환경, 정서적 멈춤)은 허용되며 권장됩니다 — 내레이션 에이전트가 그런 컷을 해설 없이 남깁니다.

## 3. 길이는 내레이션 예산으로 산정한다

- 해당 컷의 예상 해설 글자 수 ÷ **4.5자/초** + 꼬리 여백 **0.8초**, 그 결과를 **4–15초**로 클램프해 `duration`으로 삼습니다.
- 해설의 단일 세그먼트 상한은 **80자**이므로, 한 컷이 담는 서술량은 약 15초에 읽을 수 있는 분량을 넘지 않게 합니다. 정보가 너무 많으면 두 컷으로 나눕니다.
- 실제 `duration`은 내레이션 더빙 생성 후 **실측 음성 길이**로 한 번 더 역산됩니다. 여기서 주는 값은 합리적인 초기값입니다.
