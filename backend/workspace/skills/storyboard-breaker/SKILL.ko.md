# 스토리보드 분할 가이드

## 핵심 정의: 스토리보드 구간

하나의 스토리보드 = 하나의 **스토리보드 구간**(segment) = 하나의 영상 생성 작업.

- 각 구간의 길이는 **8~15초**이며 내부에 **2~4개의 서브 컷**을 담는다
- 서브 컷 사이에는 **컷 전환이 가능하다**: 화면 크기, 각도, 촬영 대상을 바꾸고 하드 컷으로 잇는다
- 서브 컷 사이에는 **장면을 넘지 않는다**: 한 구간은 한 장면 안에서만 일어난다(`scene_id` 는 구간 단위 바인딩)
- 각 서브 컷은 2~6초이며 하나의 화면 단위(**하나의 주요 동작**, 하나의 반응, 하나의 클로즈업)에 집중한다

## 분할 절차(5단계)

1. `read_storyboard_context` 를 호출해 대본, 캐릭터, 장면, 소품, 기존 스토리보드 요약을 읽는다
2. **비트 식별**: [오프닝] [촉발] [절정] [마무리] 등의 표시나 서사의 전환점을 식별한다. 비트 경계에서는 강제로 구간을 나누고, 같은 비트의 서브 컷은 같은 구간에 두는 것을 우선해 인과의 사슬을 흩뜨리지 않는다
3. **컷별 물건 스캔**: 각 구간이 다루는 대본을 한 문장씩 훑어 화면에 보이는 물건을 나열 → 소품 목록에 매핑해 `prop_ids` 를 바인딩 → 세 개의 키프레임과 video_prompt 에서 @소품명 으로 언급한다. 승계 체인상의 손에 든 물건·착용 물건은 연속해서 인용한다(`prop-continuity` 스킬 참조). 대본에는 있으나 소품 목록에 없는 물건은 마무리 멘트의 목록에 기록한다
4. **총량 기준 설정**: 목표 총 길이 = 대본 글자 수 ÷ 분당 500자. 구간 수 ≈ 목표 총 길이 ÷ 12초, ±20%
5. **구간 내 서브 컷 분할**: 동작, 시점, 대상 전환점을 기준으로 나누고 필드를 채운 뒤 `save_storyboards` 를 호출해 나누어 저장한다

## 리듬 계층별 길이

| 구간 유형 | 길이 | 설명 |
|---|---|---|
| 전환 구간 | 8~10초 | 이동, 빈 화면, 환경 제시, 장면 전환 |
| 서사 구간 | 10~15초 | 일반적인 줄거리 진행, 대화 |
| 폭발 구간 | 12~15초 | 클로즈업, 규칙 공개, 감정 폭발, 반전. 단일 서브 컷을 4~6초 머물게 해도 된다 |

하드 규칙: 15초 구간에는 최소 3개의 서브 컷. 어떤 서브 컷도 5초를 넘지 않는다. 순수 클로즈업 서브 컷은 구간당 최대 1개이며 마무리로 쓰면 안 된다 — 클로즈업으로 끝내면 영상 후반이 계속 밀려 들어오는 큰 얼굴로 무너진다.

## 대사 길이 하한(하드 규칙)

**구간 길이 ≥ 구간 내 대사와 내레이션 총 글자 수 ÷ 초당 4.5자 + 연기 여유 2초**. 담기지 않는 대사는 다음 구간으로 넘긴다.

## 동작과 사지(하드 규칙)

- **서브 컷 하나에 주요 동작 하나**: "다리를 내리고—몸을 틀고—다시 접는" 같은 동작 사슬을 한 서브 컷에 밀어 넣는 것은 금지. 나누거나 취사선택한다
- **고위험 동작은 사지의 행방을 쓴다**: 양반다리/웅크리기/한 다리 서기/다리 꼬기/돌아서기/두 캐릭터의 신체 접촉/거울 보기 — description 에 양손과 양다리를 어떻게 거두었는지와 보이는지를 명시한다("두 다리를 몸 앞으로 당겨 접고, 두 발은 몸 아래에 넣고, 두 손으로 무릎을 안는다")
- **가려지는 동작은 고쳐 쓴다**: 손을 등 뒤로 뻗는 등 몸통에 가려지는 동작은 측면에서 보이는 동등한 동작으로 바꾼다("카메라를 향해 옆으로 서서 오른손을 등 뒤 허리 쪽으로 돌리고 팔꿈치가 보인다") — 모델은 보이지 않는 사지를 그리지 못하고 엉뚱하게 이어 붙일 뿐이다
- **접촉 상호작용은 양쪽 모두 선언**: A 가 B 를 건드릴 때 두 캐릭터의 사지 최종 상태를 모두 쓰고 접촉점은 하나로 한다
- **비인간 체형의 실행 가능성에 맞춘 재작성**: 짧은 사지에 둥근 몸, 발굽, 손발이 같은 형태인 캐릭터는 인간의 동작을 그 체형이 해낼 수 있는 버전으로 먼저 고쳐 쓴다(기니피그가 덤벨을 든다 → 두 앞발로 봉을 가슴 앞에 끌어안는다. 나무 자세 → 한쪽 뒷발을 땅에서 살짝 뗀다)
- **여러 캐릭터가 한 화면에**: 캐릭터가 3명 이상이거나 두 캐릭터의 거리가 반 몸 너비 미만이면 캐릭터마다 한 문장씩 위치와 자세를 서술하고, 합쳐서 묘사하지 않는다

## 컷 구성 요소

1. **컷 제목**: 3~5자 요약
2. **시간**: 구체적인 시각 + 빛 묘사
3. **장소**: 장면의 완전한 설명 + 공간 배치
4. **화면 크기**: 주된 화면 크기. 여러 크기면 조합을 쓴다
5. **각도**: 수평/로우 앵글/하이 앵글/측면/후면
6. **카메라 워크**: 고정/푸시인/풀아웃/팬/팔로우/이동
7. **화면 묘사** `description`: [컷N] 별로 서브 컷 단위 묘사. 화면이 먼저, 대사는 그 안에(규칙은 위 참조)
8. **화면 결과** `result`: 구간 끝의 즉각적인 결과 + 시각적 디테일 + 이 시점에 각 캐릭터가 **무엇을 들고 무엇을 착용하고 있는지**
9. **분위기** `atmosphere`: 빛 + 색조 + 소리 + 전체 분위기
10. **길이** `duration`: 8~15초이며 대사 하한을 충족
11. **장면 연결** `scene_id`, 12. **캐릭터 연결** `character_ids`, 13. **소품 연결** `prop_ids`
14. **연결 표기** `continuity`
15. **키프레임 프롬프트**: `first_frame_prompt` / `mid_frame_prompt` + `mid_frame_time` / `last_frame_prompt`

## 장면 연결 규칙

- `read_storyboard_context` 가 반환하는 `scenes` 를 우선 사용한다. `location + time` 이 명확히 일치하면 올바른 `scene_id` 를 반드시 채워 넣는다
- 존재하지 않는 장면 ID 를 임의로 만들지 않는다. 같은 물리 공간을 여러 장면으로 쓰지 않는다

## 캐릭터 바인딩 규칙

- `character_ids` 는 반환된 캐릭터 목록에서 가져와야 한다. 분명히 등장하거나, 보이거나, 동작하거나, 말하는 캐릭터는 모두 바인딩한다. 빈 화면은 빈 배열을 전달한다

## 소품 바인딩과 참조 이미지 예산

- `prop_ids` 는 반환된 소품 목록(`props`)에서 가져와야 한다
- 소품이 사용되거나, 전달되거나, 클로즈업되거나, 착용되거나, 화면에서 뚜렷이 보이면서 서사에 의미가 있으면 반드시 바인딩하고 프롬프트에서 @ 한다
- 예산: 컷당 참조 이미지 상한 9장, 영상 측 첫 프레임이 1장을 차지 → 장면 1 + 캐릭터 N + 소품 M ≤ 8
- 예산 초과 시 취사 우선순위: 장면 > 등장 캐릭터 > 사용·전달·클로즈업·착용되는 소품 > 보이기만 하는 소품. 밀려난 소품은 바인딩과 @ 를 동시에 제거하고, "@ 했는데 바인딩하지 않은" 이름을 남기지 않는다(ref_issues 가 발생한다)
- 줄거리와 무관한 배경 물건은 바인딩하지 않는다. 소품이 없는 구간은 빈 배열을 전달한다

## 연결 표기와 키프레임

**표기 규칙**(모든 구간에 `continuity` 를 부여):

| 상황 | 값 |
|---|---|
| 첫 번째 구간 | `cut` |
| 장면 변경(`scene_id`/장소 변화), 시간 점프, 회상, 의도적인 하드 컷 | `cut`(**장면을 넘는 continue 는 엄금** — 승계된 첫 프레임이 잘못된 장면의 이미지에 고정된다) |
| 같은 장면, 앞 구간 바로 다음 순간, 인물 연속 | `continue` |

**키프레임 필드**(규칙 상세는 `keyframe-prompt` 스킬, 반드시 엄수):

- `first_frame_prompt`: [컷1] 의 시작 순간. `continue` 구간에서는 반드시 비워 둔다
- `mid_frame_prompt` + `mid_frame_time`: 첫 서브 컷을 제외한 가장 중요한 서브 컷의 시작 순간. `mid_frame_time` 은 해당 [컷N] 의 시작 시간과 정확히 같아야 하고 0.5 와 `duration - 0.5` 사이에 엄격히 들어와야 한다. 서브 컷이 하나뿐이면 쓰지 않는다
- `last_frame_prompt`: 구간 끝의 순간이며 `result` 와 일치시킨다

**작성 요구**:

- 각 키프레임 프롬프트는 자족적이어야 한다: @장면명, 화면 크기·카메라 위치·구도, 각 @캐릭터명 의 위치/자세/**양손 양다리 상태**/표정, 핵심 @소품명 과 **착용·파지 상태**, 빛과 분위기. 상대적 서술은 금지
- **절대적 이미지 우선**: 캐릭터의 종족, 의상, 색상, 헤어스타일, 체형, 이목구비, 나이를 묘사하면 안 된다. 캐릭터는 `@캐릭터명` 으로만 지칭한다. 상대적 체격 비율과 착용형 소품의 착용 상태는 써도 된다(이는 외모 묘사가 아니다). 의상은 스타일링 버전 참조 이미지가 결정한다
- 뒤에 `continue` 가 이어지는 구간의 `last_frame_prompt` 는 안정적이고 정보가 명확하며 인물이 화면에 온전히 들어오고, 다음 구간에 필요한 인물과 그들이 들고/착용한 소품을 포함해야 한다
- 거울과 화면: 같은 프레임에서는 "거울 속 상" 또는 "실체" 중 하나만 주체로 삼는다. 화면 속 TV 는 프로그램만 방영하며 본 작품의 캐릭터가 나와서는 안 된다

## 품질 요구

- `description` 은 사람이 읽기에 적합해야 하며, 관객이 실제로 보고 듣는 내용을 서브 컷 단위로 묘사한다
- 세 개의 키프레임 프롬프트는 단일 프레임 구도, 인물의 위치와 자세, 사지 상태, 환경 조명을 부각한다
- `bgm_prompt` 와 `sound_effect` 는 간결한 구절로 쓰되 "긴장", "슬픔" 뿐일 정도로 막연해서는 안 되며 비워 두어서도 안 된다
- 조정이 필요하면 `update_storyboard` 를 호출해 해당 구간을 수정한다
